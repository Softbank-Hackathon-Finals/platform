# T28 보안 대응 장면: 터미널 접근 시도 → 격리 → Green 대체

시연에 넣는 별도 장면이다. [T28 런북](t28-demo-runbook.md)의 해피패스 계획과 나뉜다. 계획 상태, 270초 버짓,
기존 운영 앱(`target-dev` demo-chat) · DB · Edge를 바꾸지 않는다. 구현과 신뢰 경계는
[터미널 워크로드 시험](../../services/console/docs/terminal-workload-response.md)을 따른다.

## 보여 주는 것

목적지(온프렘)에 새로 만든 시험 namespace 세 개 안에서, 한 번의 실제 요청으로 시작하는 대응 여덟 단계를 콘솔 한 화면에 보인다.

1. 소유자 터미널의 고정 `attempt` 명령 → 시험 Blue Pod가 보호된 이웃 서비스에 인증 없는 HTTP 요청
2. 이웃의 실제 **HTTP 403**
3. 요청 주체 Pod UID · IP · 소유 Deployment와 독립 이웃 감사를 대조
4. 사건 뒤에 만든 대응 계획(처음 표시한 계획의 승인은 이 계획을 승인하지 않는다)
5. 사람 승인
6. 원본으로 가는 **새 연결 격리**와 이웃 정상 응답
7. Green 기동 · HTTP 확인
8. 시험 진입점 전환 · readback, 끝나면 소유 namespace UID를 대조해 정리

## 언제 넣나

- 해피패스 계획 밖의 장면이라 계획의 270초 안에 세지 않는다. S2가 끝나기를 기다리는 동안이나 S3 뒤에 따로 보인다.
- 실행 상한은 8분이다(개인 자격 10분보다 짧다).
- 해피패스와 따로 돌려도 된다. 운영자 Mac에서 돌고, 목적지에는 전용 namespace만 만든다. 출발지는 지도용으로 읽기만 한다.
- 목적지 노드 몫은 작다. Pod 하나가 CPU 25m · 메모리 32Mi를 요청하고 최대 4개라, 합쳐도 100m · 128Mi다. namespace마다 할당량도 건다. 11-08 노드는 CPU 요청 85% · 메모리 71%였고, 시험을 더해도 약 88% · 73%다.
- 화면이 섞이지 않게 S4 장애 주입 장면과만 겹치지 않게 한다. 시작 전에 시험 namespace가 남아 있지 않은지 본다.

## 실행 (운영자 Mac)

전제는 다음과 같다.

- tailnet 운영자 그룹으로 목적지 API에 닿을 것(`bravo:operators`, `kube-system` UID `7ca7d762-`)
- 출발지 조회용 개인 AWS SSO 세션
- 콘솔 소스는 develop의 `services/console`이다. 시험 호스트는 `services/console/testing/terminal_trial_host.py`다.
- 생산자는 `sova-test` [#3](https://github.com/Softbank-Hackathon-Finals/sova-test/pull/3)(`demo/onprem_response/terminal_*`, 아직 main 밖)이다. 커밋을 고정한다.

경로 · 등록 프로필 · 접속 래퍼는 운영자 비공개 자료다. 런처는 시작할 때 다음을 확인하고, 다르면 뜨지 않는다.

- 콘솔 · 시험 호스트 파일이 고정 리비전과 바이트로 같은지
- 생산자 checkout이 고정 SHA인지
- 래퍼 sha256이 맞는지

| 단계 | 하는 일 | 확인 |
|---|---|---|
| 1 | 비공개 운영 폴더의 런처로 로컬 콘솔을 띄운다(`127.0.0.1`, 2시간 상한) | 출발지 · 목적지 조회 지도가 보임 |
| 2 | 콘솔 시험 패널에서 소유자 인증 뒤 시험 자원 생성에 동의(prepare) | 시험 namespace 3개 · Blue Pod 준비 |
| 3 | 터미널에서 고정 `attempt` 명령 | 화면에 403 · 주체 · 독립 감사 |
| 4 | 대응 계획을 확인하고 승인 | 격리 · Green 기동 · 응답 · 진입점 전환 네 효과 |
| 5 | stop | 화면 근거 만료, 소유 namespace 정리 확인 |

브라우저는 고정 prepare · respond · stop만 보낸다. 대상 · URL · 명령은 지정할 수 없다. 효과 응답이 불명확하면 다시 실행하지 않고 원장과 실제 자원을 읽어 인수한다.

## 말하는 범위

- 403은 고정 접근 통제가 실제 요청을 거부했다는 뜻이다. 공격 탐지나 침해 판정이 아니다.
- 격리는 독립 확인 Pod에서 원본으로 향하는 새 HTTP 연결 거부에 한정한다. 기존 연결 · egress 전체 봉쇄로 넓히지 않는다.
- 승인은 개인 시험 승인이다. 제품 T10 승인 · 운영 인수를 대신하지 않는다. AWS → 온프렘 이전 장면이 아니다.
