# Slack 메시지 작성 기준

에이전트가 팀 Slack 메시지를 작성하거나 전송할 때 적용한다. 수신자가 현재 상태와 자신이 해야 할 일을 바로 이해할 수 있도록 쓴다.

## 작성 기준

1. **결론과 요청을 먼저 쓴다.** 무엇이 달라졌고 누구에게 어떤 판단이나 행동이 필요한지 앞부분에 적는다. 단순 공유라면 응답이 필요하지 않음을 밝힌다.
2. **한 질문에는 하나의 결정만 담는다.** 담당자가 같아도 별도로 결정할 사안은 구분한다. 지금 진행을 막는 질문부터 요청하고, 필요한 기한은 이유와 함께 적는다. 정해지지 않은 기한은 만들지 않는다.
3. **상태를 정확히 표현한다.** 제안·합의·구현·검증을 구분한다. 검증은 모의 환경인지 실제 대상 환경인지 밝힌다. 적용 가능성을 확인하기 전에는 확정적으로 약속하지 않고, 무응답이나 확인 이모지를 합의로 간주하지 않는다.
4. **비유 없이 아주 쉽게 작성하고, 판단에 필요한 설명만 남긴다.** 익숙한 단어와 짧은 문장으로 실제 동작과 영향을 직접 설명한다. 꼭 필요한 기술 용어는 처음 나올 때 뜻을 쉽게 풀어 쓴다. 코드·리소스 식별자·시험 목록·작업 경과는 PR이나 이슈에 두고 해당 위치를 연결한다. 요청을 이해하는 데 꼭 필요한 조건은 본문에 남긴다.
5. **답변과 새 요청을 구분한다.** 기존 질문에 대한 결론을 먼저 내고, 추가로 발견한 작업은 별도 요청으로 정리한다. 같은 주제의 후속 논의는 기존 스레드에서 이어가며 이미 공유한 내용은 반복하지 않는다.
6. **변경된 결정과 다음 행동을 정리한다.** 정정할 때는 이전 답에서 무엇이 바뀌었고 상대가 무엇을 수정해야 하는지 밝힌다. 여러 사람이 논의한 사안은 요청자가 확정 사항·남은 일·담당자를 짧게 정리한다.

## 전송 전 확인

- 첫 부분만 읽어도 무엇이 달라졌고 누가 무엇을 해야 하는지 알 수 있는가?
- 확정된 내용과 아직 확인하거나 검증해야 할 내용을 구분할 수 있는가?
- 상대의 판단에 필요하지 않은 작업 기록이나 새로운 요청이 섞여 있지 않은가?

분량은 짧게 유지하되, 이해에 필요한 이유와 조건은 생략하지 않는다. 한 문장에 여러 정보를 밀어 넣어 길이만 줄이지 않는다. 다른 사람의 판단이나 행동에 영향을 주지 않는 단순 작업 경과는 이슈에 모은다.

이 기준은 메시지 작성 방식에 관한 것이며, 메시지 전송 권한이나 팀의 승인 절차를 변경하지 않는다.
