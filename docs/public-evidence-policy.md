# 공개 증빙과 비공개 원본

공개 저장소에는 검증 방법·결과·측정 대상 소스의 해시를 남긴다. 개인 이메일, 사용자 홈 절대경로, 실제 클라우드 계정 번호, 운영 리소스 ID·이름·호스트 주소는 공개본에서 가린다. 인증 키와 토큰은 증빙으로 수집하지 않으며 플랫폼의 비밀 저장소에 둔다. 실제 운영 입력은 Git에서 제외한 변수 파일 또는 플랫폼 설정으로 전달한다.

## 원본과 공개본의 관계

원본 readback·로그는 저장소 밖의 접근 제한 경로에 보존한다. 공개본을 만들기 전에 원본 바이트와 SHA-256을 대조하고, 원본 파일은 권한 `0600`, 보관 디렉터리는 `0700`으로 제한한다. 중앙 보관이 필요하면 접근 제어·암호화·보존 정책이 있는 비공개 저장소로 옮긴다. 이 도구는 중앙 업로드나 보존 기간을 관리하지 않는다.

`scripts/public_evidence.py sanitize`는 명시한 파일만 가린다. 한 실행 안에서 식별자로 판정한 위치의 같은 원문은 같은 가상값으로 치환한다. 예를 들어 계정은 `AWS_ACCOUNT_001`, 리소스 ID는 `AWS_RESOURCE_001`, 리소스 이름은 `RESOURCE_NAME_001`, 이메일은 `person-001@example.invalid`, 사용자 홈은 `$HOME`, 호스트 IP는 문서용 `192.0.2.0/24` 값으로 바꾼다. 이 값은 실제 배포 입력으로 사용하지 않는다. JSON의 `account`·`AccountId` 같은 명시적 계정 필드가 숫자라면 가상값 문자열로 바뀔 수 있다. 측정값·판정·시간·소스 해시는 그대로 둔다.

리소스 이름은 증거 JSON의 지정 이름 필드·`log_groups` 배열·`Name` 태그의 값 전체에서만 치환한다. 이름이 `db` 또는 `PASS`라고 해도 JSON 키, 같은 내용의 판정·측정 필드, 해시의 일부, 다른 설명 문자열을 바꾸지 않는다. 이메일·AWS ID 등 일반 패턴도 검출된 토큰 경계 안에서만 치환한다. JSON 키는 자동 변경하지 않는다.

공개 파일과 manifest를 쓰기 전에 원본 JSON을 다시 읽어 별도의 보존 검사를 수행한다. 키·배열 구조·타입, 계정 번호 이외의 숫자·불리언·null, 해시·판정·측정·시간 필드와 식별자가 아닌 문자열의 변경은 실패로 처리한다. 이 비교는 치환 횟수나 개인정보 검사 통과 여부를 증거 보존의 근거로 쓰지 않는다. JSON 키에 실제 식별자가 있거나 계정 번호와 측정값을 구분할 수 없어 잔여 개인정보 검사를 통과하지 못하면 파일을 쓰지 않고 중단한다. 이런 경우는 의미를 보존하는 공개 형식을 사람이 검토해야 하며, 숫자나 해시를 임의로 바꾸어 통과시키지 않는다.

공개 [`redaction-manifest.json`](evidence/privacy/redaction-manifest.json)은 다음을 구분한다.

| 필드 | 의미 |
|---|---|
| `checkout_commit` | 가림을 수행한 작업 트리의 HEAD. 파일 바이트가 그 커밋에 들어 있었다는 보증은 아님 |
| `original_sha256` | 비공개로 보존한 원본 파일 바이트의 해시 |
| `public_sha256` | 가린 공개 파일 바이트의 해시 |
| `redactions` | 가린 종류별 발생 횟수. 실제 값이나 원문 매핑은 포함하지 않음 |
| `public_is_raw: false` | 공개 파일은 원본의 일부 식별자가 가려진 사본임 |

증빙 안의 `source_sha256`, 기존 `source-manifest.json` 등은 **실측 당시 입력**을 식별한다. 가린 현재 파일의 해시로 바꾸거나 새로운 실행의 증거라고 주장하지 않는다. 공개본에 나타난 ID와 과거 해시를 대조해야 할 때는 권한이 있는 검토자가 비공개 원본을 사용한다. 원본을 조회할 권한이 없는 독자는 공개본만으로 리소스 실체나 해시와 원본의 일치를 독립 확인할 수 없다.

가림 뒤 문서의 링크·표기 등을 교정하면 `public_sha256`을 새 공개본에 맞추고, 해당 artifact의 `post_redaction_edits`에 `prior_public_sha256`과 편집 사유를 기록한다. `original_sha256`과 원본은 그대로 보존한다. 후속 편집이 있는 공개본은 가림만 적용한 사본과 구분해 검토하며, 실측 당시 소스 해시와 측정값을 새 실행의 값으로 바꾸지 않는다.

## 작성·공개 순서

1. 운영 결과를 저장소 밖 비공개 경로에 저장하고, 판정·측정값·실행 소스를 확인한다. 원본에 인증 정보가 들어갔다면 공개 절차를 멈추고 해당 정보의 관리 담당자에게 알린다.
2. 공개할 사본을 준비한다. 아래 명령은 사본의 바이트도 먼저 비공개로 보존한 뒤 파일을 바꾸며, 원문 매핑은 비공개 디렉터리에만 기록한다.

   ```sh
   python3 scripts/public_evidence.py sanitize \
     docs/evidence/RUN/readback.json \
     --private-root "$HOME/.bravo/private-evidence"
   ```

3. 공개 파일과 manifest를 읽어 가림이 측정 의미를 바꾸지 않았는지 확인한다. README·PR 본문·댓글·스크린샷에도 같은 공개 기준을 적용한다. 링크된 원본을 공개 업로드하지 않는다.
4. `python3 scripts/public_evidence.py check`와 CI의 gitleaks 검사를 통과시킨다. 새 파일도 검사하려면 Git에 추가하거나 `check <파일>`에 명시한다. PR은 리뷰 승인을 받은 뒤 병합한다.

이미 가린 파일을 다시 실행해도 새로운 원문은 생기지 않는다. 가상값의 번호는 실행 단위이며, 서로 다른 실행의 같은 번호가 같은 실제 리소스를 뜻하지 않는다. 원문 매핑과 비공개 보관 위치는 커밋하지 않는다.

## 자동 검사 범위

`check`는 Git이 추적하는 UTF-8 텍스트 중 4 MiB 이하 파일을 읽는다. 개인 이메일·홈 경로·계정 번호·일부 AWS ID/ARN/DNS 패턴은 전체 텍스트에서 검사한다. `docs/evidence/`에서는 개별 호스트 IPv4와 JSON의 `GroupName`, `KeyName`, `log_groups`, `Name` 태그 같은 운영 이름 필드도 검사한다. CIDR은 네트워크 설계 설명에 쓰이므로 자동으로 가리지 않는다. 공식 예시 계정, 문서용 주소, 이미 가린 ARN은 허용한다. 심볼릭 링크는 링크 대상 문자열만 검사하고 파일을 따라 읽지 않는다.

GitHub SSH 원격 주소의 고정 `git` 전송 사용자 표기는 저장소 경로가 붙은 scp/SSH URL 문맥에서만 이메일과 구분한다. 같은 주소가 이메일로 단독 등장하거나 다른 사용자 주소·주변 실제 이메일이 있으면 계속 탐지한다. 파일 제외나 개인 이메일 허용 목록은 사용하지 않는다.

이 검사는 모든 개인정보가 없다는 보증이 아니다. 바이너리·이미지·4 MiB 초과 파일, 사람 이름·자유 서술 리소스 별칭·사설 토폴로지, 일반 URL과 알려지지 않은 공급자 식별자, PR 본문·댓글은 별도 검토한다. 다른 증빙 폴더를 추가하면 필드 검사 범위도 함께 확장한다. 일괄 파일 제외나 개인값을 담은 공개 허용 목록을 추가하지 않는다. 검사 결과에는 원문 대신 상대 파일명·종류·개수만 출력한다.

누락된 파일, 잘못된 JSON, 파일 읽기·Git 명령 실패는 성공으로 처리하지 않는다. CLI는 오류 코드 `2`와 일반 오류 문구만 남기며 원문 예외·traceback·Git stderr의 사용자 경로를 노출하지 않는다. 추적 파일을 이름 변경한 직후에는 변경을 Git에 추가한 뒤 다시 검사한다.

CI의 `secrets` job에서 이 표준 라이브러리 검사를 실행한다. 클라우드 로그인·네트워크 요청·추가 서비스는 필요 없다. 인증 정보 탐지는 별도 gitleaks가 맡고, 이 도구는 비용 정산이나 클라우드 실행 권한을 바꾸지 않는다. 테스트는 상쇄되지 않는 식별자 검사, 가상 예시 허용, JSON 형식, 원본 바이트·권한·해시 보존과 안전한 오류 출력을 확인한다.

## 기존 공개 이력

이메일의 예외는 도메인으로 판별한다. 이름이 `example`·`AWS_`로 시작해도 실제 이메일 도메인이면 검사하며, 같은 접두사의 실제 AWS endpoint도 가리지 않은 값으로 탐지한다. GitHub SSH 전송 표기는 위 자동 검사 범위의 저장소 경로 문맥으로만 구분한다.

가림 커밋은 현재 공개 파일을 교정한다. 이미 공개된 Git 커밋·PR diff·포크·캐시의 내용을 지우지는 않는다. 이번 절차는 이력 재작성·인증 정보 회전·자동 삭제를 수행하지 않는다. 실제 인증 정보 노출이 확인되면 값의 재게시 없이 종류와 위치를 기록하고, 별도의 회수·회전 및 이력 처리 결정을 받는다. 운영 ID가 공개됐다는 사실만으로 인증 키가 공개됐다고 판단하지 않는다.
