# [ADR-0015] 초기 설계의 범위와 기반 구성

* **상태 (Status):** 제안됨(Proposed). 기존 설계의 결정을 뒤늦게 기록한 문서다. 선택의 재검토나 구현 완료를 뜻하지 않는다.
* **날짜 (Date):** 2026-11-04
* **관련 (Related):** T29 #10, 설계 1~8장 · 10~12장

## 1. 배경 및 문제 상황 (Context and Problem Statement)

초기 설계에는 서비스 범위와 기반 구성이 있지만, 이후에 추가한 세부 ADR처럼 선택 근거를 한곳에서 찾기 어렵다.
[설계 v0.4의 기준 커밋](https://github.com/Softbank-Hackathon-Finals/platform/blob/d5cc834021993af96321e4add8b7403968d3b8b6/docs/design.html)에 있는 결정을 이 문서에 묶어 연결한다.
구현 중 새로 정한 세부 계약은 [ADR 목차](README.md)의 원문을 따른다.

이 기록은 현재 설계와 회의 기록에 적힌 이유만 사용한다.
문서에 없는 성능 비교나 당시 검토하지 않은 대안을 소급해 만들지 않는다.
실증 수치와 아직 정하지 않은 선택은 그대로 제안 또는 미정으로 둔다.

## 2. 고려한 옵션들 (Considered Options)

| 선택 지점 | 원문에 있는 대안과 이유 | 근거 |
|---|---|---|
| 데모 앱 | 실시간 채팅과 영상통화. 영상통화는 행사장 Wi-Fi, 미디어 서버 경험, 데이터 무결성·되돌리기 표현이 부담이다. 채팅은 QR 참여와 이전 후 기록 확인이 쉽다. | [10/31 회의 5절](https://app.notion.com/p/4098bee9ada480e98c83dec9c15d8b2a), 설계 1·3·8.10장 |
| 구현 범위 | 여러 클라우드·AI 추론·ETL까지 한 번에 이전하는 범위와 AWS → 온프렘의 채팅을 먼저 끝내는 범위. 설계는 데이터 무결성·보안 유지·에이전트 격리를 중점으로 둔다. | 10/31 회의 6·8·11절, 설계 2.1·4장 |
| 출발지 DB | 현재 구성은 EKS 안의 CNPG이고, RDS 출발지 가져오기는 P2다. 원문에는 두 제품의 선택 이유를 별도 비교한 기록이 없으므로 이유를 추가하지 않는다. DB 엔진 변환·호환되지 않는 스키마 변경은 이번 범위 밖이다. | 설계 4·7.3·8.6장 |
| 플랫폼 배치 | EKS와 EC2 + RKE2. 데모 플랫폼은 비용 때문에 EC2 단일 노드를 쓴다. 운영 권장은 별도 계정 또는 다른 클라우드다. | 설계 7.2장 |
| Edge 독립성 | Cloudflare LB + Tunnel을 사용하는 범위와 독립 대체 진입점까지 만드는 범위. 현재는 전자를 쓰고 Cloudflare를 잔존 의존성으로 표시한다. | 설계 4·7.2·8.7장 |
| 에이전트 런타임 | 목적지의 리허설 네임스페이스와 Harbor 평가. 런타임은 리허설 네임스페이스이며 Harbor는 같은 이미지·검증 스크립트를 쓰는 P1 평가로 구분한다. | 설계 8.4·11장 T26·12장 |

위 표는 당시 모든 후보 제품을 조사했다는 뜻이 아니다.
RKE2·Cloudflare 등 표에 적힌 구성의 제품 간 우열을 새로 판정하지 않는다.

## 3. 결정 사항 (Decision Outcome)

아래는 기준 설계에 있는 결정과 세부 기록의 위치다.
절의 숫자·절차·스키마를 여기서 다시 정의하지 않는다.

| 설계의 결정 | 선택 이유와 경계 | 세부 원문 |
|---|---|---|
| 금융 서비스 운영팀의 출구전략 시험을 실시간 채팅으로 보인다. | 보안 유지와 데이터 무결성 요구를 하나의 데모로 확인한다. 일반적인 여러 앱 이전은 범위 밖이다. | 설계 1~4·6·10장 |
| 결정적 코드가 흐름·판정·실행을 맡고 AI는 정해진 형식의 제안만 낸다. | AI 결과를 독립 검증하고 사람 승인 뒤 반영한다. | 설계 1·8.1~8.5장, [모델 제공자](0007-model-provider-and-s2-ci.md), [상태·이벤트](0008-plan-state-event-transaction.md) |
| 출발지, 플랫폼, 목적지, Edge의 역할을 나눈다. | 출발지는 AWS 관리 기능을 사용하고, 플랫폼은 비용을 낮춘 제어부다. 목적지는 바깥 방향 연결을 사용한다. | 설계 7.1~7.5·8.8장 |
| 출발지 DB는 CNPG이고, 논리 복제와 짧은 쓰기 정지로 전환한다. | DDL·시퀀스는 논리 복제만으로 해결되지 않으므로 사전 조건과 최종 비교를 둔다. 실패 시 DB가 동시에 쓰기를 받지 않게 한다. | 설계 7.3·8.6장, [Executor 언어](0006-cutover-executor-language.md), [실행·실패](0011-cutover-executor-execution-and-failure.md), [지문 생산자](0013-integrity-fingerprint-producer.md) |
| AWS 기능을 목적지 구성에 대응시키고, 제품 이름 대신 같은 통제를 시험한다. | OpenBao·ESO·SeaweedFS·RBAC 등의 존재만으로 동등성을 주장하지 않는다. | 설계 7.3·8.5장, [통제 계약](../controls/README.md), [T33 형식](0001-security-finding-format.md), [T33 보안 경계](0005-t33-security-boundary.md) |
| 리허설은 컷오버 전 목적지의 격리 네임스페이스에서 실행한다. | 운영 자격을 주지 않고, 별도 검증 Job이 판정한다. Harbor 평가는 P1이다. | 설계 8.4장, [송신 범위](0002-rehearsal-egress-allowlist.md), [격리 구현](0003-rehearsal-namespace-isolation.md) |
| Cloudflare LB와 클러스터별 Tunnel로 환경 간 트래픽을 전환한다. | 온프렘은 외부 인바운드 개방 없이 연결한다. Edge 전환과 DB 쓰기 주체 전환을 구별한다. | 설계 7.2·7.5·8.7장 |
| Tailscale로 클러스터 간 DB 경로를 연결한다. | 복제와 컷오버 전 목적지 앱의 출발지 DB 접근에 사용한다. 경로 허용과 실제 지연 검증은 별개다. | 설계 7.5·8.6장 |
| 환경과 앱을 등록하고, 환경별 차이는 어댑터로 나눈다. | P0 AWS → 온프렘에서 시작하되 다른 환경을 붙일 수 있게 한다. 비용 비교는 P2다. | 설계 8.9·8.11장, [상태 저장](0009-postgres-state-adapter.md), [데이터 접근](0012-platform-data-access-boundary.md) |
| 승인한 diff와 이미지 digest에 배포를 묶는다. | 승인과 다른 산출물의 반영을 막고, 반영 뒤 게이트를 다시 대조한다. | 설계 8.4·11장 T31, [이미지 전달](0011-private-image-delivery.md), [계약 목차](../contracts/README.md) |
| 관측·감사 기록을 판정과 설명의 근거로 쓴다. | 판정용 외부 관측과 환경 내부의 진단·감사를 구분한다. | 설계 5.2·7.3·8.2·8.7장, [관측 경계](0010-observability-boundary.md) |

## 4. 결과

- 구성과 시나리오의 원본은 [설계 문서](../design.html)다. 세부 계약은 표의 링크를 따른다.
- 설계 5.3의 수치는 제안값이다. [기존 측정 근거](README.md#실측-근거)를 연결하되 로컬·모의 환경 값을 실환경 확정값으로 바꾸지 않는다.
- 설계 12장의 미결정 선택은 이 ADR로 채택하지 않는다. SeaweedFS 대안·배포 방식 등 새 선택은 해당 담당의 근거와 검토로 갱신한다.
- 이 ADR은 기존 설계의 출처 기록이다. 실제 통합·배포·완료 여부는 각 태스크 이슈와 실행 근거에서 확인한다.
