# [ADR-0018] 의존성 3등급은 규칙이 정하고, 에이전트는 빈칸만 채운다

* **상태 (Status):** 제안됨(Proposed)
* **날짜 (Date):** 2026-11-04
* **관련 (Related):** T16 #25, T11 #20, T32 #34. 설계 8.11, FR-2, 7.3

## 1. 배경 및 문제 상황 (Context and Problem Statement)

* **상황:** 설계 FR-2는 의존성을 설정 교체 / 어댑터 추가 / 코드 수정 3등급으로 나누고, 8.11은 "애매한 항목만 에이전트가 분류"한다고 적었다. 어디까지가 규칙이고 어디부터가 에이전트인지 경계가 코드로 고정되어 있지 않았다.
* **문제:** 경계가 없으면 같은 레포에 다른 등급이 나오고(비결정), 에이전트가 "대체 없음"을 "설정 교체"로 낙관하는 사고가 생긴다. 반대로 전부 규칙으로 하면 카탈로그 밖 의존성이 조용히 사라진다.
* **목표:** 같은 입력이면 같은 등급. 규칙이 못 정하는 항목은 지우지 않고 표시한다.

## 2. 고려한 옵션들 (Considered Options)

### 1. 전부 에이전트 분류

코드와 정책을 모델에 주고 등급을 받는다.

**Pros**
* 구현이 가장 빠르다. 카탈로그 밖 의존성도 설명이 붙는다.

**Cons**
* 같은 입력에 다른 등급. 게이트와 추천의 입력이 흔들린다.
* "대체 없음"을 낙관적으로 뒤집을 수 있다(설계 8.3 가드레일 위반).

### 2. 전부 규칙

카탈로그에 없는 것은 `unknown`으로 끝낸다.

**Pros**
* 완전 결정적.

**Cons**
* 와일드카드 정책, 배포에만 있는 권한, 타 클라우드 SDK처럼 맥락이 필요한 항목이 설명 없이 남는다.

### 3. 규칙 우선 + 빈칸만 에이전트 (선택)

규칙이 `config_swap` · `adapter` · `code_change` · `none`을 정한다. 같은 역할의 SDK 호출이 여럿이면 호출마다 따로 보고 가장 무거운 등급을 택한다(S3 클라이언트 하나라도 endpoint 설정이 없으면 `code_change`, 일부만 설정 가능하면 `agent_needed`). 규칙이 못 정하면 `unknown` + `agent_needed`로 표시한다. 배포에만 있는 항목은 카탈로그 기본 등급을 적용하되 `agent_needed`를 켠다. 에이전트 결과는 `grade_by: agent`와 이유를 붙여 같은 스키마로 재검증하고, 규칙의 `none`은 바꾸지 못한다.

**Pros**
* 결정적인 부분과 비결정적인 부분이 문서에서 구분된다(8.1 원칙).
* 에이전트 실패가 인벤토리 자체를 망가뜨리지 않는다.

**Cons**
* 카탈로그를 유지해야 한다. 새 역할이 생기면 데이터 파일을 고친다.

## 3. 결정 사항 (Decision Outcome)

* **옵션 3을 선택한다.**
* **옵션 1은 채택하지 않는다.** 판정의 비결정성은 게이트 · 추천의 입력으로 허용되지 않는다.
* **옵션 2는 기본 동작으로 남기되** `agent_needed` 표시로 보완한다.

**이유**
* 설계 8.1 · 8.3: 반복해도 같아야 하는 것은 코드, 바뀌어도 되는 것은 에이전트.
* T32는 규칙 판정이 `blocked`인 후보를 AI가 뒤집지 못해야 한다. 같은 원칙을 항목 등급에도 적용한다.

## 4. 결과

* `services/inventory`에 규칙(`grading.py`)과 카탈로그(`catalog.py`)를 분리해 두었다. 카탈로그는 데이터이며 7.3 표와 1:1이다.
* demo-chat 기준 결과: object_store `config_swap`, secrets `code_change`, iam `adapter`, db `config_swap`, 배포에만 있는 kms는 기본 등급 `code_change` + `agent_needed`.
* 출력 경계: 환경변수 값 · 접속 문자열의 사용자 정보 · 비밀로 보이는 설정 값은 인벤토리에 넣지 않는다(이름 · 출처 · `scheme://host[:port]`만). 콘솔과 모델이 같은 문서를 읽기 때문이다.
* 후속: 에이전트 분류 결과 병합 경로(T11), 리허설 송신 차단 기록을 동적 증거로 합치는 안(T15), GCP 어댑터(P2).
