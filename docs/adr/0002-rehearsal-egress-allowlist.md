# [ADR-0002] 리허설 네임스페이스의 송신 허용 범위: 같은 네임스페이스 · DNS · 시험용 SeaweedFS · OpenBao만

* **상태 (Status):** 채택됨(Accepted)
* **날짜 (Date):** 2026-11-03
* **관련 (Related):** T3 #7, T9 #13, T15 #24, 설계 문서 8.4 · NFR-4

## 1. 배경 및 문제 상황 (Context and Problem Statement)

* **상황:** 리허설 네임스페이스는 AI가 만든 변경을 목적지 클러스터 안에서 시험하는 곳이다. 설계 문서 8.4 격리 규칙은 "NetworkPolicy 기본 거부(수신 · 송신), 네임스페이스 안 통신만 허용"이다.
* **문제:** 같은 8.4 흐름은 리허설에 "목적지 프로필(시험용 OpenBao 경로 · SeaweedFS 버킷)"을 넣고 "실제 목적지와 같은 OpenBao · SeaweedFS에서 돌려 본다"고 한다. 리허설 앱은 첨부파일을 SeaweedFS에, DB 비밀번호를 OpenBao에서 받으므로 네임스페이스 밖에 닿아야 한다. 격리 규칙 문장대로 막으면 앱이 돌지 않아 시험이 되지 않는다.
* **목표:** 앱이 실제 목적지와 같은 SeaweedFS · OpenBao로 시험되면서, 그 밖의 모든 곳(다른 네임스페이스, 메타데이터 주소, 인터넷)으로는 나가지 못하게 한다.

## 2. 고려한 옵션들 (Considered Options)

### 1. 전부 거부 (DNS 포함)

**Pros**
* 가장 엄격하고 규칙이 단순하다

**Cons**
* 같은 네임스페이스 서비스도 이름으로 찾지 못해 앱 복사본이 돌지 않는다

### 2. 같은 네임스페이스 + DNS

**Pros**
* 격리 규칙 문장과 같다
* 허용 대상이 클러스터 내부 DNS뿐이라 시험이 단순하다

**Cons**
* 앱이 SeaweedFS · OpenBao에 닿지 못해 S2의 두 작업(버킷 정책 번역, OpenBao 코드 수정)을 시험할 수 없다
* 결국 3번으로 바꿔야 하므로 템플릿과 시험을 두 번 만들고 검증한다
* 가장 실수하기 쉬운 부분(허용 규칙이 너무 넓게 열리는 것)이 T3 완료 시점에 시험되지 않는다

### 3. 같은 네임스페이스 + DNS + 시험용 SeaweedFS · OpenBao의 Pod · 포트만

허용 대상은 네임스페이스 · Pod 라벨 · 포트로 지정하고, 값은 템플릿 밖 설정으로 둔다.

**Pros**
* 8.4 흐름(실제 목적지와 같은 SeaweedFS · OpenBao에서 시험)을 지킨다
* 허용 규칙의 범위가 맞는지 T3에서 바로 시험한다
* T9가 끝나면 설정값만 바꾸면 된다

**Cons**
* 리허설 앱과 운영 앱이 같은 SeaweedFS · OpenBao 인스턴스를 쓴다. NetworkPolicy는 "어느 서버에 닿는가"만 정하므로, 서버 안에서 어떤 버킷 · 경로를 쓸 수 있는지(T9의 권한 설정)가 격리의 일부가 된다
* T9 구축 전에는 실제 라벨 · 포트를 모르므로 가정한 값으로 시작한다

### 4. 리허설마다 SeaweedFS · OpenBao를 따로 띄움

**Pros**
* 운영 인스턴스와 완전히 분리된다

**Cons**
* 8.4가 피하려는 "흉내 낸 환경"이 된다. 실제 목적지 설정에서만 생기는 차이를 놓친다
* 리허설마다 두 서비스를 띄우고 지우는 시간과 자원이 든다

## 3. 결정 사항 (Decision Outcome)

* **3번(같은 네임스페이스 + DNS + 시험용 SeaweedFS · OpenBao의 Pod · 포트만)을 선택한다.**
* **4번은 운영 인스턴스와 공유하는 위험이 커지면 다시 검토한다.**
* **1번 · 2번은 채택하지 않는다.**

**이유**
* 리허설 앱이 SeaweedFS · OpenBao 없이는 돌지 않으므로 2번은 중간 단계일 뿐이다
* 허용 규칙이 너무 넓게 열리는 실수를 T3 격리 시험으로 바로 잡을 수 있다
* 8.4의 "실제 목적지와 같은 환경에서 시험"과 맞는다

## 4. 결과

* T3 템플릿의 NetworkPolicy는 ① 수신 · 송신 기본 거부 ② 같은 네임스페이스 허용 ③ kube-dns 53번 허용 ④ 시험용 SeaweedFS · OpenBao Pod · 포트 허용, 네 개로 구성한다. ④의 네임스페이스 · 라벨 · 포트는 설정값이다.
* T3 격리 시험에 다음을 더한다. 허용한 서버 · 포트로는 접속된다(양성 대조). 같은 서버의 다른 포트, 허용한 네임스페이스 안의 다른 Pod로는 막힌다.
* T9 구축 전에는 k3d에 같은 포트(SeaweedFS S3 8333, OpenBao 8200)를 쓰는 대역 서버를 두고 시험한다. 실제 라벨 · 포트는 T9 결과로 바꾸고 RKE2에서 다시 시험한다.
* 리허설 앱의 SeaweedFS · OpenBao 자격증명은 시험용 버킷 · 시험용 경로에만 권한이 있어야 한다. 이 권한 설정과 "운영 버킷 · 경로 접근은 거부된다" 시험은 T9 담당과 정한다. 정하기 전까지 T3 결과는 네트워크 단계의 격리만 보증한다.
* 설계 문서 v0.2에서 8.4 격리 규칙과 7.5 네트워크 경로 규칙 표를 이 결정에 맞게 고쳤다.
