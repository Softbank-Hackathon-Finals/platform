# ADR-0014: PR 조상 이력과 저장소 전체 보안 감사 분리

- 상태: 제안 (PR 리뷰와 병합 후 적용)
- 날짜: 2026-11-04
- 범위: T7 저장소 CI, T29 공개 증빙 형식

## 배경

[PR #135의 알림](https://github.com/Softbank-Hackathon-Finals/platform/pull/135#issuecomment-6606173356)은 미병합 증빙의 소스 해시 세 건 때문에 무관한 #116·#117의 secrets가 실패한 사건이다. 같은 커밋 소스의 SHA-256과 일치하는 값이 파일명 `api`와 결합해 Gitleaks 8.24.3 generic 규칙에 걸렸다. 전체 fetch와 기본 `--all`이 다른 브랜치를 각 PR의 필수 입력으로 만들었다. 소유자의 미병합 커밋 교체 후 두 run은 attempt 2에서 복구됐으며 검사 예외는 추가되지 않았다.

## 결정

필수 PR 검사는 checkout한 병합 커밋에서 도달 가능한 전체 이력을 검사한다. 다른 브랜치의 refs는 이 판정에 영향을 주지 않는다. PR 조상에서 지운 비밀과 병합 해결 중 추가한 비밀은 계속 탐지한다.

모든 fetched refs를 검사하는 별도 감사는 실패를 그대로 보고하며, 보호 브랜치 push·주간 예약·수동 실행과 감사 자체의 PR에서 실행한다. 기존 필수 세 context와 연결하지 않는다. 설정·버전·입력 refs와 run attempt를 기록해 전체 감사의 가변 입력을 확인할 수 있게 한다.

새 공개 소스 manifest는 `source_revision`과 `source_files`의 `path`/`sha256` 행을 사용한다. 공통 생성기는 고정 커밋의 파일 바이트를 읽는다. 형식 검사는 새 경로→해시 객체를 거부하며, 동일 위치의 변경 없는 과거 구조는 보존한다. 해시처럼 보인다는 이유로 비밀 검사에서 면제하지 않는다.

## 결과와 검증

무관한 브랜치 또는 태그의 탐지는 해당 PR의 필수 검사를 막지 않지만 전체 감사에서는 실패한다. 실제 scanner와 임시 Git 저장소로 이 구분, 자체 과거 비밀 삭제, merge-only 비밀, 기존 오탐 형식과 새 행 형식을 검증한다. scanner의 오류와 실패 종료 코드는 기록 저장 후에도 전파한다.

전체 감사가 실패하면 해당 run의 정확한 refs·fingerprint·원문 위치를 조사한다. 일반 PR을 막는 필수 context로 승격하거나 전체 경로를 제외하는 방식으로 해결하지 않는다. 정기 실행은 이 workflow가 기본 브랜치에 병합된 뒤 활성화되며, PR에서의 검증 실행과 구분한다.
