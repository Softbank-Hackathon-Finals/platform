# [ADR-0039] SHIFT 전에도 사람 승인으로 Edge 실측을 한다(승인된 Edge 시험)

* **상태 (Status):** 채택됨(Accepted)
* **날짜 (Date):** 2026-11-07
* **관련 (Related):** T17 #26, T10 infra 승인(#603), ADR-0033

## 1. 배경 및 문제 상황 (Context and Problem Statement)

* **상황:** T17 실행기(edge-control)는 코드와 연결이 끝났다. 하지만 완료 기준 3개가 모두 비어 있다. 세 기준은 가중치 반영 시간, 실제 분배, 기준 초과 시 자동 0%다.
* **문제:** 가중치를 바꾸려면 이전 계획이 SHIFT에 있고 그 SHIFT 승인이 유효해야 한다. SHIFT에 가려면 GATE 통과가 먼저다. GATE는 다른 담당의 결함 수정(T31)과 원본 대조(T14·T19)에 묶여 있다. 그래서 Edge 자체의 성질은 GATE가 끝날 때까지 실측할 수 없다.
* **목표:**
  * 실제 LB, 실제 T18 부하, 정본 T36 판정으로 T17 기준을 GATE와 독립해 확인한다.
  * 사람 승인 없이 가중치를 바꾸는 경로는 여전히 만들지 않는다.

## 2. 고려한 옵션들 (Considered Options)

### 1. 해피패스가 SHIFT에 들어갈 때까지 기다린다

**Pros**
* 규칙이 바뀌지 않는다.

**Cons**
* Edge 실측 시점이 GATE와 다른 담당의 일정에 묶인다.
* SHIFT에서 처음 실측하면, Edge 결함이 이전 당일에 처음 드러난다.

### 2. 운영자 권한만으로 가중치를 바꾸는 시험 명령

**Pros**
* 가장 빠르다.

**Cons**
* 사람 승인 없이 트래픽을 옮기는 경로가 생긴다. 설계 원칙("불명확하면 쓰기를 열지 않는다", 사람 승인)에 어긋난다.

### 3. 기존 T10 infra 승인으로 시험 명세를 승인한다 (선택)

* 사람은 시험 명세의 digest 하나를 T10 `approval_kind=infra`로 승인한다. 명세는 계획·run·T36 프로필·LB다.
* 실행은 그 승인을 run 하나에 한 번 소비한다.
* 나머지는 SHIFT와 같은 경로를 탄다: 같은 승인 호스트, 같은 journal, Controller, T18 창, T36 판정, 자동 0%.

**Pros**
* 사람 승인과 단일 writer가 그대로다. 새 승인 종류도, T10 변경도 필요 없다.
* 요청자는 자기 요청을 승인할 수 없다. 승인은 24시간 이내이고, 소비는 한 번이다(기존 infra 승인 규칙).

**Cons**
* "가중치는 SHIFT 승인으로만"이 "SHIFT 승인 또는 승인된 Edge 시험"으로 넓어진다. 이 범위는 아래 결정으로 좁힌다.

## 3. 결정 사항 (Decision Outcome)

옵션 3을 택한다(2026-11-07 류지환 결정). `bravo_edge_control.drill`이 구현한다.

* **승인:** 시험 명세(`drill_spec`: 계획·run·T36 프로필·LB)의 digest를 T10 infra 승인으로 받는다.
  * 승인 가능 상태는 SHIFT 전(COLLECT ~ AWAIT_APPROVAL)뿐이다.
  * 요청자는 승인자가 될 수 없고, 유효기간은 24시간 이내다.
* **소비:** `register`가 그 승인을 run 하나에 한 번 소비한다(`apply_infra`). 이때 승인자는 지금도 `approve_infra`를 가져야 한다.
* **매 단계 재확인:** 계획 잠금 안에서 매 단계마다 다시 읽는다.
  * 승인, 소비 기록, 철회, 만료
  * 계획 version(승인 시점과 같아야 한다), 계획 상태(SHIFT 전이어야 한다)
  * 두 사람의 권한
  * 하나라도 다르면 PATCH를 보내지 않는다.
* **SHIFT와의 분리:** 계획이 SHIFT 이후로 넘어가면 시험은 거부된다. 이전 자체의 전환 옆에서 시험이 돌지 않는다.
* **같은 실행 경로:** 승인 호스트의 단일 journal(`/records/edge/journal.db`)과 ShiftHost 경로를 쓴다.
  * 10→50→100은 `ADVANCE_ALLOWED`일 때만 진행하고, `SET_WEIGHT_0`이면 자동 복귀한다.
  * 시험은 계획 상태나 DB writer를 바꾸지 않는다.
* **운영자 현존:** 실행 중 운영자의 AWS SSO 증명(60초 수명)을 표준 입력으로 계속 받는다. 끊기면 다음 PATCH를 보내지 않는다.
  * 이때 가중치가 0이 아니면 `restore`로 되돌린다. 0% 명령의 작업 ID는 `sequence`와 같아서 중복 PATCH가 생기지 않는다.

## 4. 결과

### 좋아지는 점
* T17의 반영 시간·분배·자동 0%를 GATE와 독립해 실측할 수 있다.
* SHIFT 이전에 같은 실행 경로를 실제로 한 번 통과시킨다.

### 감수하는 점
* 시험은 공개 LB와 실제 사용자 경로를 옮긴다.
  * 실행 전에 목적지 쓰기 경로(목적지 pooler → 출발지 DB, write switch)와 두 앱의 준비를 확인한다.
  * 끝나면 0%를 재조회해 남긴다.
* 시험의 판정·명령 기록은 그 계획의 `plan_commands`에 남는다. 다른 run이므로 이후 SHIFT 실행과 충돌하지 않는다.
  * Controller는 이전 run의 확인된 0% 뒤에만 새 run을 받는다.
