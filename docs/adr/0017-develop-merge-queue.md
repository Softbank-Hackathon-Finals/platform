# ADR-0017: develop 승인 필수 해제와 GitHub Merge Queue

- 상태: 채택됨 (회의 결정). 실제 적용·검증은 T40에서 추적한다.
- 날짜: 2026-11-05
- 관련: T40, [운영 절차](../merge-queue.md)

## 배경

리뷰 대기로 기준선이 오래 분리되고 통합 충돌 비용이 늘었다. 회의는 develop의 필수 리뷰를 해제하고 CI와 핵심 업무 시험을 기준으로 통합하며, 이상무가 병합 자동화를 맡기로 했다. 이 결정은 ‘위험 경로만 필수 승인’이라는 앞선 제안보다 상위 기준이다.

## 대안

1. 모든 PR의 승인 1건 유지: 병목이 남는다.
2. 일부 경로만 승인 필수: 가능한 정책이지만 현재 회의 결정과 다르다.
3. 승인 없이 각 PR의 CI만 보고 즉시 병합: 앞선 PR과 합친 결과를 검사하지 못한다.
4. 승인 없이 GitHub 기본 Merge Queue에서 조합 검사: 회의의 속도 개선과 통합 검사 요구를 함께 충족한다.

## 결정

4번을 선택한다. develop의 숫자 승인과 코드 오너 승인 요구를 모두 해제하고, 필수 secrets·infra·platform을 실제 merge_group SHA에서 실행한다. main 규칙, 담당 범위 합의, 제품 실행 승인, 에이전트 권한 경계는 유지한다. 기존 미해결 지적을 강제로 dismiss하거나 결함이 확인된 PR을 일괄 등록하지 않는다.

## 결과와 한계

리뷰는 필수 승인 대기 대신 파트별 검토·후속 수정으로 지속한다. 큐는 최신 기준선과 앞선 PR의 조합을 검사하지만 모든 변경 조합·운영 부하·데이터 무결성을 증명하지 않는다. 실제 통합 시험과 안전 경로의 실패 시험을 대체할 수 없다. CI가 약하면 큐도 약하므로 검사 예외·필수 context·권한을 함께 유지한다. 초기 병렬도는 2개로 제한하고 실제 실행 시간으로 조정한다.
