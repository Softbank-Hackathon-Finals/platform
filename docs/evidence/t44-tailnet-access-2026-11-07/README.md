# T44 사람의 tailnet API 접속 인수 기록 — 2026-11-07

## 구현과 변경 이유

기준은 #627의 `07cbf343`이다. 플랫폼은 기존 `operator-access`에 비공개 정책의 운영자 그룹을 연결한다.
출발지는 `api-transport-access`로 HTTPS 도달 권한만 선언한다. 기존 Kubernetes/IAM 인증은 유지하고,
새 RBAC·토큰·impersonation은 만들지 않는다. 두 방식을 네트워크 조회 응답에서도 구분한다.

에이전트의 경로 확대는 거부한다. 출발지처럼 통신만 허용한 프록시에 선언되지 않은 impersonation이
추가되어도 `tailnet-check`가 거부한다. #627의 바인딩 차트 제외·역할별 새 바인딩 이름·추가 capability 검사는 보존한다.

## 정책 준비와 실제 관측의 구분

사용자가 제공한 전체 정책에는 플랫폼 admin/owner grant가 이미 있었다. 준비한 수정안은 이를
중복 추가하지 않고 기존 운영자 그룹에 본인 한 명과 grant 두 개를 추가했다. 기존 grants·그룹의 다른 멤버·
SSH·tagOwners·tests는 보존했고, 재실행 시 동일 결과와 잘못된 입력 7건 거부를 확인했다.
사용자는 저장 완료를 알렸으나, 저장 뒤 원격 정책 원문을 다시 받은 것은 아니므로 현재 정책 전체의 동일성은 미확인이다.
사람의 이메일과 정책 원문은 공개 저장소에 넣지 않는다.

18:03 KST까지의 읽기 전용 확인에서 플랫폼 장치 표시·온라인·태그와 DNS의 등록 IP 일치를 확인했다.
직접 HTTPS 조회는 실패하여 `whoami`, `bravo:operators` 그룹, 직접 경로의 권한은 인수하지 못했다.
기존 SSM 경로에서는 등록 클러스터 신원·RBAC 존재·operator 로그를 조회했고 만든 세션은 종료했다.
operator Pod를 선택하는 NetworkPolicy는 0개였고 최근 로그에서 오류는 발견하지 못했다.
이 사실만으로 TLS·권한·네트워크의 실제 거부 시험을 PASS 처리하지 않는다.

18:05 KST에는 기존 온프렘 개인 직접 접속 도구도 시간 초과였다. Mac 네트워크 진단의 UDP·IPv4·중계
측정은 가능했으나, 실제 목적지까지의 HTTPS 연결을 증명하지 못한다. 원인은 미확정이다.
정책 선언, 장치 표시, 클러스터 내부 상태와 개인 직접 접속 결과를 각각 기록한다.
