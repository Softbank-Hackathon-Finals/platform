# T14: 등록된 앱·환경 ID를 사용하는 출발지 읽기 전용 수집

2026-11-06 KST에 실제 팀 AWS 출발지에서 새로 수집한 결과다. T14 실행 결과의
`app`에 앱 이름 대신 T10 등록 영수증의 `workload_id`를 사용하고,
`environment.id`에는 등록된 출발지 ID를 사용했다. 과거 원문의 ID를 수정한 결과가 아니다.

## 결과

| 시험 | 실제 확인 | 결과 |
|---|---|---|
| IAM-01.1 | 동일 객체에 앱의 임시 역할로 읽기 성공 → 익명 GET 거부 → 앱 재읽기 성공 | PASS |
| ENC-02.1 | 기존 Secret의 현재 버전과 그 버전의 실제 KMS 키가 사용 가능한지 확인 | PASS |

**서로 다른 실행 두 건이다.** 각 실행은 full 프로필의 20개 행 중 해당 시험 1개만
PASS이고, 나머지 19개는 `UNKNOWN/NOT_RUN`이다. 두 실행이나 과거 TLS 결과를 합쳐
하나의 전체 PASS를 만들지 않았다.

## 수집 경계

- 수집 전 실제 앱이 등록 영수증의 ReplicaSet 식별 지문·이미지·서비스 계정과
  일치하고 Ready인지 확인했다. 각 수집의 전후에도 앱 등록을 다시 읽어 대조했다.
- S3 시험은 기존 앱 안의 임시 역할을 STS 신원·RoleId와 대조해 사용했다.
  객체의 현재 버전·ETag를 전후 확인했고 객체 본문은 저장하지 않았다.
- 암호화 시험은 운영자 본인의 단기 SSO 자격으로 Secret 메타데이터와 실제 키를
  조회했다. Secret 값은 읽지 않았으며, KMS 기본 키를 새로 만드는 호출도 하지 않았다.
  이 결과는 앱 역할의 최소 권한이나 다른 역할의 접근 거부를 증명하지 않는다.
- DB 연결·업무 쓰기·앱 배포·IAM 및 네트워크 설정 변경은 없었다.
  이번 수집에 사용한 별도 SSM 세션은 종료했다.

## 원문과 형식 검증

[summary.json](summary.json)은 공개 요약이며, 실제 운영 식별자는 싣지 않았다.
각 실행 원문·수집 증거·등록 결속 기록은 접근 제한된 비공개 경로에 보존했다.
요약의 해시는 그 원문 바이트를 식별하며 서명이나 운영 승인 권한이 아니다.

원문 두 건에 대해 다음을 확인했다.

- T14 `Catalog`와 T19의 고정 `T5Contract`가 각각 결과 형식을 수용한다.
- 원문의 앱·출발지 ID가 등록 영수증과 일치한다.
- PASS 행의 증거 해시가 보존한 수집 증거와 일치한다.
- 수집 증거의 실행 ID·앱·시험 ID가 결과 원문과 일치한다.
- 미실행 19행을 누락하지 않고 `UNKNOWN/NOT_RUN`으로 유지한다.

형식·해시 검증은 T19의 출처 인가·유효기간·계획 결속·전체 판정을 대신하지 않는다.
[source-manifest.json](source-manifest.json)은 사용한 저장소 소스를 고정한다.
비공개 실행 스크립트의 바이트 지문은 [collector-manifest.json](collector-manifest.json)에
구분해 기록했다. 공개 요약만으로 비공개 원문이나 실제 리소스의 실체를 독립 검증할 수는 없다.

## 남은 인수

T10의 평가 프로필이 고정된 새 계획, 신뢰된 수집 주체의 `GateRecords.record_run`
저장, 실제 목적지 결과와 T19 최종 판정은 이번 작업에 포함하지 않았다.
기존 계획의 digest나 과거 증거는 덮어쓰지 않았다.

T14·T19는 계속 In progress이며 완료 체크를 추가하지 않는다. 실제 DB 시험에 필요한
앱 내부 읽기·Pooler 통계 접점과 시험 시간 조율은 기존 T14 인계에서 이어간다.
