# T37 조회 신선도 검증 (2026-11-04)

실제 로컬 Collector·Prometheus·조회 API와 별도 k3s/CNPG로 검증했다. 팀 EKS/RKE2 배포 완료와 구분한다. [결과·소스 해시](results.json).

- Collector 성공 신호의 **원 표본 시각**을 사용한다. 비교 연산 뒤 `timestamp(up == 1)`을 적용하면 평가 시각으로 바뀌므로 잘못 신선하다고 판정할 수 있다. promtool의 중단 시험에서 이를 발견하고 `timestamp(up) and (up == 1)`로 수정했다.
- 실제 CNPG 지표와 비활성 논리 슬롯을 조회한 뒤 Collector를 중지했다. 정상 상태가 확인 불가로 바뀌고 기존 DB 수치를 숨겼다. HTTP 과거 창도 동일하게 확인 불가로 바뀐다.
- 미래 시각·NaN/Inf·중복 단일 표본·손상 응답·과대 응답을 정상/0으로 표시하지 않는다. 조회 결과는 캐시하지 않는다.
- Compose와 k3s를 실행별 이름으로 분리하고, 생성한 컨테이너 ID만 정리한다. port-forward 종료의 143 코드 때문에 정리가 중단되는 결함도 수정했다.

## 실패와 범위

첫 Compose 실행은 스크립트 편집과 겹쳐 실패했으며 결과에서 제외했다. 소스를 고정해 다시 실행해 19항목 통과했다.

첫 k3s 실행은 새 시험 Pod의 서비스 첫 접속이 한 번 거부되어 전체 성공으로 세지 않았다. 당시 API 내부의 동일 요청은 확인 불가를 반환했고 다음 독립 헬스 요청은 200이었다. 최초 접속 실패의 근본 원인이나 서비스 무중단은 이 시험으로 입증하지 않았다. 최종 시험은 미리 정상 응답을 확인한 같은 클라이언트로 중단 전후를 비교해 15항목을 통과했다.

관측 화면의 상태는 실행 허가가 아니다. T36은 별도 창 요약, T19는 등록된 통제·데이터 근거를 사용한다. 실제 배포·팀 인증·장애 시 가용성·보존/PVC·환경별 egress 제한은 별도 운영 검증 사항이다.
