# T36 창 수신과 T37 DB 출처 검증 통합

#168에 #160의 출처 검증 수정과 develop을 합친 결과다. README와 k3s 시험의 충돌은 양쪽 검사를 보존해 해결했다.

| 검증 | 결과 |
|---|---|
| 관측 라이브러리·조회·창 수신 Python 시험 | 144 통과 |
| 실제 로컬 Compose 수집·조회·사칭·중단 | 20/20 |
| Docker 내부 k3s + CNPG + 창 수신 | 20/20 |
| 고정 Prometheus promtool 알림·HTTP 조회식 | 두 묶음 통과 |
| loadgen 잠금 설치·회귀시험 | uv 0.13.7, 172 통과·8 제외 |
| Ruff·공개 정보·diff 검사 | 통과 |

창 수신에서는 생산자 토큰·네임스페이스 제한, 플랫폼 수신 시각, 중복 거부, 콘솔 토큰 거부와 외부 통신 차단을 확인했다. DB 경로에서는 실제 CNPG scrape의 출처와 식별자, 앱 경로의 같은 이름 지표 제외, Collector 중단 후 확인 불가를 함께 확인했다.

수집·조회·배포 시험 중 관측 트리는 `results.json`의 runtime_test_revision에 고정했다. 이후 develop 병합에서도 관측 트리가 같은지 확인했다. loadgen 잠금 파일은 통합된 API extra 메타데이터를 반영하되 패키지 이름·버전·출처는 바꾸지 않았다.

원문 로그와 인증서는 공개하지 않는다. 소스 해시는 변경 확인용이며 서명이나 제3자 인증이 아니다. 자체 생성한 시험 컨테이너·클러스터는 시험 종료 처리로 정리했다. 다른 세션 자원은 변경하지 않았다.

실제 팀 AWS/EKS/RKE2, 운영 인증서·영속 스토리지·ACL, 실제 T18 생산자 및 T17 실행 연결은 이번 검증에 포함하지 않는다. T36/T37 전체 완료나 무중단 운영을 뜻하지 않는다.
