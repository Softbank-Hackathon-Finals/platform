네 증거 JSON은 운영 식별자가 해시로 결속된 **제품 출력의 동일 바이트**다.
`ControlRun.results[].evidence.output_sha256`과 해당 증거 파일 해시를 대조했다.
네트워크 주소, 계정·역할·Pod 식별자 및 자격증명은 공개 파일에 넣지 않았다.

## 실제 실행과 보존 경계

- 운영자 개인 SSO로 앱 Deployment·Pod·서비스계정·고유 IAM RoleId·Secret 버전·CA·Pooler와
  첨부 객체의 현재 버전을 등록했다. 시작·시험 사이·종료 시 총 12회 등록을 대조했다.
- SDK는 **앱의 실제 임시 역할 세션**을 사용했다. STS에서 고유 RoleId와 세션 만료를
  확인하고 그 자격 스냅샷으로 S3 접근을 수행했다. 운영자 AWS 자격을 앱에 넣지 않았다.
- 정상 DB 접속에는 앱 자격만 사용했다. CA·hostname·평문 음성 시험에는 비밀번호를
  보내지 않았다. S3 응답 본문은 읽거나 저장하지 않고 스트림을 닫았다.
- 새 Pod·객체·역할·정책을 만들지 않았고 앱·DB·네트워크 설정을 바꾸지 않았다.
  패키지는 임시 디렉터리에서만 풀고 프로세스 종료 시 정리했다.
- 각 증거를 운영자 장치의 비공개 디렉터리에 저장하고 파일·디렉터리를 fsync한 뒤
  같은 run ID와 해시의 ACK를 보냈다. 보존 ACK 없는 PASS를 발행하지 않는다.
- `source-manifest.json`의 제품 파일은 명시한 revision과 일치한다. 운영자 transport는
  실행 당시 미커밋 파일이며 기록된 파일 해시로 구분한다. 나중 증빙 커밋을 과거 실행
  소스로 표시하지 않는다.

첫 복합 수집 준비는 수집기 생성자의 인자 이름 오류로 DB/객체 시험 전에 중단됐다.
이를 교정한 새 실행이 위 결과다. 실패한 실행 자료는 비공개로 보존했으며 성공 결과로 덮지 않았다.

## 별도 ENC-01.5 시험은 UNKNOWN

Pooler→DB 구간은 [별도 결과](backend-control-run.json)와
[증거](backend-evidence.json)에 남겼다. 등록된 관리 주체의 `SHOW CONFIG` 접속이
인증 단계에서 실패해 `UNKNOWN / TOOL_ERROR`다. 관리 접속 오류 원문·자격증명은 공개하지 않는다.
이 별도 시험은 신뢰된 운영자 프로세스 메모리에서 등록된 자격을 읽었다. 자격 값을 파일에
보존하거나 앱 프로세스에 관리 자격을 주입하지 않았다. 네 시험의 앱 내부 자격 경계와 구분한다.

설정 파일의 `server_tls_sslmode=verify-full`만으로 실제 적용 정책과 새 backend 연결을
증명하지 않았다. 이 조회를 위해 Pooler를 재시작하거나 기존 연결을 종료하지 않았다.
현재 관리 읽기 주체 인수와 실제 backend 관측이 추가로 필요하다.

## T19/T10 인수 범위

- `operator-qualified/source`는 운영자 자격 시험의 환경 참조이며 T10 정본에 등록된
  환경 참조로 고쳐 제출하지 않는다. 현재 계획의 서버 등록에 맞춘 생산자 실행과
  저장소·권한·발급자 인증 연결은 별도로 인수해야 한다.
- 이 원문은 출발지 한쪽의 관찰이다. 목적지 결과를 만들거나 출발지를 목적지로 복사하지 않았다.
  전체 게이트 PASS, 무중단 이전, 컷오버 승인 또는 T14 전체 완료를 뜻하지 않는다.
- 각 실행의 UNKNOWN은 그대로 유지한다. ENC-01.5 별도 실패를 네 시험 실행의 PASS로
  포함시키지 않으며, 네 시험 실행의 `NOT_RUN`을 ENC-01.5 성공으로 해석하지 않는다.
- 증거 기본 유효기간은 T5 계약을 따르며 T19 소비 시 현재 기한·계획·등록을 다시 검사한다.
  로컬 fsync ACK는 중앙 저장소의 장기 보존·접근 통제·복구 자격을 대신하지 않는다.
