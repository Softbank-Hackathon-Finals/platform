# T34 OTLP 감사 기록 연결 — 2026-11-03

두 가지 시험을 구분해 수행했다.

| 입력 | 실제 수행 경로 | 결과 |
|---|---|---|
| 합성 접속·DDL·RBAC 5건 | 실제 Collector mTLS → 정제 → file exporter → 디코더 → AUD-01.1/2/3 | 모두 present |
| 전용 로컬 kind의 실제 접속·테이블 생성/삭제·RoleBinding 생성/삭제 5건 | kubectl 인증 조회로 캡처 → 등록 UID 경로에 재생 → 같은 Collector·디코더·의미 검사 | 모두 present |

실제 canary는 기존 시험 DB의 임의 이름 테이블과 무토큰 시험 주체의 임의 이름 RoleBinding을
만들고 자기 자원만 정리했다. PostgreSQL 로그인/DDL과 Kubernetes API의 이벤트를 원문 그대로
비공개 보존했다. 저장소 원문에는 SQL·요청 본문이 남지 않도록 전달 단계에서 정제했다.

**두 번째 시험도 노드에 DaemonSet을 설치해 상시 수집한 결과는 아니다.** 인증된 API로 읽은
기록을 파일 스트림에 재생한 통합 시험이다. Collector는 실제 프로세스이며 인증서 검증 mTLS를
사용했다. 수신 저장소는 시험용 file exporter이고 운영 보존·권한·검색·고가용성을 제공하지 않는다.

최초 합성 시험은 실제 Collector의 `doubleValue` 상태 코드를 지원하지 못해 실패했다.
정확히 표현 가능한 정수만 수용하도록 고치고 동일 의미 검사를 다시 실행했다. 소수 상태 코드,
부정확한 큰 수, 출처 불일치, 중복 키, 부분 export, 기한 뒤 수신 거부 시험을 추가했다.
실패 기록과 원문·인증서·실제 자원 식별자는 로컬 비공개 기록에 보존했다.
