# T37 실제 양쪽 지표와 조회 API 대조

2026-11-06 13:07–13:15 KST에 플랫폼의 실제 Prometheus를 읽기 전용으로 조회했다.
AWS·온프렘의 Collector와 CNPG 표본 4개가 모두 `up=1`이었고, 1분 간격
대조에서 각 **표본 생성 시각**이 60초 전진했다. 기존 T8 담당의
[수집 경로 복구](../t8-runtime-policy-2026-11-06/README.md)를 독립 확인한 결과다.
이번 실행에서는 Collector·네트워크·CA·DB 설정을 바꾸지 않았다.

## 확인 범위

| 대상 | 결과 | 해석 |
|---|---|---|
| 실제 양쪽 Collector / CNPG | 4개 모두 수집 중, 표본 시각 전진 | 저장소의 실시간 수신 확인 |
| 실제 저장소 → 로컬 T37 API | 양쪽 DB 조회 200 / `OK`, 각 인스턴스 1개 | 호스팅 API 배포를 대신하지 않음 |
| 앱 HTTP 지표 | 양쪽 `UNOBSERVABLE`, 요청률·오류율·p95는 `null` | 누락을 0이나 정상으로 채우지 않음 |
| PgBouncer 지표 | 양쪽 `UNOBSERVABLE`, 목록 비어 있음 | DB 수집 성공과 별개 |
| API 접근 | 토큰 없는 로컬 조회 401 | 시험용 인증이며 T10 운영 권한 인수 아님 |
| 저장소 TLS | 허용 인증서 TLS 1.3 정상, 아래 3개 거부 | 사설 터널을 통한 실제 저장소 접속 |

DB 조회의 `OK`는 관측 가능 상태다. 당시 정방향 슬롯의 WAL 차이는
16,777,000바이트였으며 역방향 슬롯은 비활성이었다. 이 값은 업무 데이터
유실량도, RPO 0도 아니다. T36 판정 입력·컷오버 허가·데이터 일치로 사용하지 않는다.

## TLS 거부와 정상 대조

각 시험의 직전·직후 허용 인증서 요청이 모두 HTTP 200인지 확인했다.
모든 접속에서 CA·서버 이름 검증을 켰고, 서버 인증서를 건너뛰지 않았다.

| 시험 | 실제 거부 근거 |
|---|---|
| 클라이언트 인증서 없음 | `TLSV13_ALERT_CERTIFICATE_REQUIRED` |
| 신뢰하지 않는 CA의 클라이언트 인증서 | `SSLV3_ALERT_BAD_CERTIFICATE` |
| 등록되지 않은 서버 이름 | 인증서 검증 코드 62(호스트명 불일치) |

첫 API 조회는 종료된 로컬 포트포워드 때문에 연결에 실패했다. 이를 인증 거부
성공으로 세지 않았다. 본인 터널 안에서 포트포워드를 다시 열어 정상 조회를
확인하고, SSL 사유와 전후 정상 대조를 수집했다. 네트워크 단절이나 일반적인
`ConnectError`만으로 인증서 통제 PASS를 만들지 않았다.

## 재현과 증거

등록된 플랫폼 클러스터와 저장소 Pod UID를 확인한 뒤 개인 인증서 기반 Kubernetes
접속과 본인 SSM 터널로 Pod의 9090을 로컬에 전달했다. HTTP 클라이언트의
프록시 상속과 리다이렉트를 끄고, 서버 인증서 이름을 검증하며 mTLS로 조회했다.
고정 쿼리는 다음과 같다.

```promql
up{bravo_env=~"aws|onprem"}
timestamp(up{bravo_env=~"aws|onprem"})
```

이어 동일 저장소에 현행 `bravo_observability.api.Prometheus`와 `create_app`을
연결하고 로컬 FastAPI 시험 클라이언트로 양쪽 환경의 http/database/pgbouncer
경로를 호출했다. 토큰은 메모리에서 새로 만든 시험용 값이다. 운영 API 토큰을
발급하거나 공개 API를 열지 않았다. 저장소 Pod UID·컨테이너 ID·재시작 수는
읽기 시험 전후 같았다. 원문은 비공개로 보존하고 [result.json](result.json)에
해시와 운영 식별자를 제외한 결과를 남겼다.

## 남은 인수

- 실제 앱의 전용 OTel 설정·클라이언트 인증서 연결과 HTTP 표본 수신
- 양쪽 PgBouncer exporter의 실제 등록·수집·출처 대조
- 승인된 조회 API 이미지의 배포·운영 인증·콘솔 연결
- T18의 실제 외부 측정 창과 T36 계획별 입력 결속

이번 결과만으로 T37 전체나 T21 운영 콘솔을 완료 처리하지 않는다. 기존 저장소의
emptyDir를 지우거나 재시작하지 않았으며, 네트워크 정책·인증서 신뢰·DB 쓰기도
바꾸지 않았다. 사용한 본인 SSM 세션과 포트포워드는 종료했다. 종료 전 조회에 본인 고아 세션은 없었다.
