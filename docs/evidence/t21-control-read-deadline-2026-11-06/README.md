# T21 보고서 조회 기한의 서버·화면 전달

보고서 출처가 곧 만료되는 경우 현재 조회 시각만 전달하면 화면이 일반 15초 동안
이전 표시를 유지할 수 있었다. 기존 T19 `VerifiedAuthority.valid_until`을
조회 모델과 화면에 보존해 표시 수명이 그 기한을 넘지 않게 했다.

[계약·운영 경계](../../../services/console/README.md#통제-보고서의-표시-기한)

## 검증

- 수정 전 실제 SQLite/PostgreSQL·초기/반영 후 네 조합의 기한 보존 시험 실패 재현.
- Python 전체 266개(새22), Node 전체185개(새10) 통과. 실제 DB·HTTP·Ed25519 코드를
  사용했으나 보고서·신원·키·권한은 명시적 fixture다.
- Chromium24·WebKit24를 **각각 새 시험 서버**로 실행해 통과. 알려진 7초 표시 창이
  끝나면 기존 15초 freshness나 5초 네트워크 poll을 기다리지 않고 다음 렌더에서
  표를 비우는지 검사했다. 동일 응답 재전송은 기한을 늘리지 않았다.
- 서버 기한 전달·짧은 창 유지·응답 직전 만료 검사 제거 사본에서4/1/2개 회귀 실패.
  실제 변이 import 경로/해시를 확인했다.
- 브라우저 render 만료 검사만 제거한 사본에서도1개 회귀가 시간 경계 안에 실패했다.
  브라우저에서 해당 변이 스크립트의 실행과 hash를 확인했다(총4/4 변이 검출).
- Linux arm64/Python3.12.14·비root·network none·read-only root에서 실제 wheel의
  정적자산7개/보안헤더/기본거부와 합성 보고서의 짧은 표시 기한·정확한 만료 거부 확인.
- 잠긴 의존성 sync, Ruff·Node 문법·자산 검사는 통과했다. 표시 기한만 바뀌며 승인·
  Executor 접수·업무 데이터·트래픽은 변경하지 않는다.

## 실패 시도와 해석

처음 Chromium과 WebKit을 한 Playwright 실행에 넣었을 때 상태 있는 단일 시험 서버를
공유해, Chromium에서 승인한 S2 계획을 WebKit이 미승인 상태로 기대하면서 실패했다.
오류 문맥에서 이미 기록된 승인과 disabled 확인란을 확인했고 그 실행을 정상 중단·보존했다.
제품 조건을 바꾸거나 retry를 추가하지 않고 각 엔진을 새 서버로 분리해 전체 시험을 마쳤다.
앞선 실패 실행을 최종 통과 집계에 넣지 않았다.

현재 기본 브랜치의 초기 계획 버전 정합성 후속은 별도 #500이다. 이 변경은 해당 PR의
브랜치·리뷰·정합성 코드를 수정하지 않았고, 운영 원문 저장·T19 인증된 평가·팀 콘솔
배포 완료를 뜻하지 않는다. 신뢰 호스트/DB 관리자 침해 또는 규제 인증을 이 표시 변경으로
해결했다고 주장하지 않는다. `authorizes_cutover=false`는 그대로 유지한다.
