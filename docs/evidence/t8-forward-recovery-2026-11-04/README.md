## 행 도착과 삭제를 어떻게 확인했나

| 단계 | 출발지 기준 | 목적지에서 확인한 결과 |
|---|---|---|
| 재개 전 | WAL flush `0/1C000000`, 기존 슬롯 confirmed flush `0/16000000` | 구독 OFF, 워커 0개, origin 적용 위치 `0/140125E8`, 시험 행 없음 |
| 삽입 후 | `cutover.barrier`에 새 UUID·epoch 0 한 행 삽입. 커밋 전 WAL 기준 `0/1C0001B0` | UUID·epoch·생성 시각 일치. origin 적용 위치 `0/1C0001E0` |
| 삭제 후 | 출발지에서 동일 UUID·epoch 한 행 삭제. 커밋 전 WAL 기준 `0/1C000268` | 양쪽 모두 시험 행 없음. origin 적용 위치 `0/1C000298`, 출발지 슬롯 confirmed flush `0/1C0002D0` |

출발지와 목적지에서 각 단계마다 메시지 2행과 첨부 메타데이터 1행의 건수·SHA-256이 일치했고, 재개 전과 비교한 해시도 같았다. 구독 OID와 origin을 대조했으며 슬롯 재생성·초기 복사 없이 기존 구독에 ENABLE을 한 번 제출했다. 출발지 앱의 쓰기 차단은 실행 전후 모두 켜져 있었다. 목적지의 누적 적용 오류는 1건, 동기화 오류는 0건으로 실행 중 증가분은 각각 0건이었다.
