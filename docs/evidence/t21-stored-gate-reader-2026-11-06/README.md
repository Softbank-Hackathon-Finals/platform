# T21: T10 저장 보고서 → 콘솔 조회 연결

기존 콘솔은 `PlanControlReport`의 화면 투영을 제공했지만, 실제 T10 저장소를
읽는 공급자는 호스트가 따로 구현해야 했다. 선택적 `T10ControlReports`를 추가해
기존 `GateRecords`의 현재 계획·보고서 조회를 연결했다.

## 구현한 경계

- T10의 같은 정본 DB·계획 잠금 안에서 현재 `gate:read` 권한과 snapshot을 확인한다.
- 현재 컨텍스트의 보고서만 읽고 gate/context digest, 최초 또는 반영 후 단계와
  Application ID를 보존한다. 클라이언트가 보고서나 단계를 등록하는 API는 없다.
- T19의 출처·해시·용도·기한 검사를 재사용한다. 저장 행이나 단순 hash만으로 인증하지 않는다.
- 조회 뒤에도 현재 권한·보고서를 대조한다. 계획/컨텍스트 변경, 만료·폐기·변조나
  다른 tenant이면 반환하지 않는다. 오류 원문은 공개 응답으로 전달하지 않는다.
- 어댑터는 SELECT만 수행한다. 새 보고서·승인·이벤트를 쓰거나 Executor를 호출하지 않는다.
  `PlanControlReport`의 `authorizes_cutover: false`를 유지한다.

호스트 연결 예시는 [콘솔 README](../../../services/console/README.md#기존-t10-저장소에서-읽기)에 있다.
호스트가 검증된 신원, 현재 계획별 권한, 실제 T19 보고서 출처를 공급해야 한다.

## 확인한 결과

| 확인 | 범위·결과 |
|---|---|
| 전체 콘솔 Python | 212 passed, Ruff 통과 |
| 저장소 연결 | SQLite 및 별도 로컬 PostgreSQL 17.11의 실제 T10 저장·잠금 사용 |
| 보고서 출처 | 실제 Ed25519 서명 검증 코드, 합성 issuer/키/신원/보고서 |
| 현재 상태 | 최초/반영 후 단계, 권한 회수, 현재 컨텍스트 변경, 새 snapshot 필요 여부 |
| 거부 | 다른 tenant, 서명 폐기·만료·변조, 정확한 서명이 있는 다른 gate/context, 출처 없는 보고서 |
| 오류 보호 | 호스트 resolver 오류와 잘못된 오류 코드에 포함된 진단 문자열 비노출 |
| 방어 퇴행 | 임시 사본에서 출처 검사·현재 결속 검사를 각각 제거하면 회귀가 실패: 2/2 탐지 |
| 패키징 | 개발 그룹 없이 잠긴 `t10` extra 설치·모듈 임포트 통과 |

초기 시험에서는 개발용 PostgreSQL 드라이버 누락으로 collection이 실패했다.
드라이버를 개발 의존성에 명시했다. 변조 시험의 첫 구성은 실제 PostgreSQL의
append-only 권한이 UPDATE를 막았으므로, 권한을 넓히지 않고 전달 경로가 원문을
바꾸는 사례로 수정했다. 이후 전체 212개가 통과했다. 기존 Starlette/httpx
deprecation 경고 1건은 남아 있으며 검사 조건을 바꾸지 않았다.

## 새 목적지 접속 도구 적용

사용자가 전달한 직접 API 도구를 커밋된 팀 소스와 바이트 단위로 대조했다.
실제 개인 신원에서 10분 ServiceAccount 자격을 받고, 포트포워드 없는 직접
API에서 20개 읽기 전용 점검을 통과했다. exec 뒤 조회, 로그 요청 뒤 조회,
가장(`--as`) 신원 보존·권한 거부를 확인했다. kubectl 1.36.1에서 WebSocket/SPDY를
요청하는 설정별로 exec 3회씩을 사용했으며 실제 협상된 wire protocol을 별도
관측한 것은 아니다. DB 호출·자원 생성·RBAC 변경은 없다.

도구·운영 설정은 비공개 고정 경로에 설치했다. 토큰은 저장하지 않았으며,
다운로드 원본이나 과거 실측 스크립트·원문은 바꾸지 않았다. 이 접속 점검은
T14 통제 PASS나 T19 운영 판정을 생성하지 않는다.

## 남은 운영 인수

이 변경은 운영 호스트 배포나 실제 팀 계획의 보고서 저장을 대신하지 않는다.
T10 담당이 맡은 원문 인수, T19 실제 출처·컨텍스트·판정 저장, 그 호스트의 신원과
보고서를 사용하는 콘솔 배포를 같은 계획으로 확인해야 한다. 합성 키로 한
로컬 시험을 운영 보고서 인증이나 금융 서비스 운영 자격으로 보고하지 않는다.

[summary.json](summary.json)은 공개 요약이다. 저장소 소스와 직접 API 도구 소스는
[source-manifest.json](source-manifest.json),
[transport-source-manifest.json](transport-source-manifest.json)에 구분했다.
비공개 원문·운영 설정은 공개하지 않았으며 공개본만으로 운영 환경의 실체를
독립 확인할 수는 없다.
