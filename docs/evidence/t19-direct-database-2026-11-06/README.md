# T19: DB 신원 결속 정정과 목적지 직접 수집

## 앞선 증빙의 범위 정정

[PR #489](https://github.com/Softbank-Hackathon-Finals/platform/pull/489)의
수집기는 양쪽 **앱의 `DB_HOST`**를 사용했다. 목적지 CNPG의 UID를 읽어
결과에 참조를 붙였지만, 그 연결이 해당 CNPG에 도달하는지는 확인하지 않았다.
따라서 당시의 결과는 **양쪽 앱 경로에서 도달한 DB의 스키마·PK 조회**이다.
독립된 두 DB의 스키마 일치를 증명했다는 설명은 철회한다.

후속 실환경 조사에서 목적지 PgBouncer의 선언 설정과 실행 중 설정이 모두
출발지 DB를 가리키는 것을 확인했다. 이는 컷오버 전 구성이다. 후속 조사를
과거 시점의 DB 신원 증명으로 소급하지 않는다. 앱 두 곳의 쓰기 허용 여부와
업무 쓰기를 받는 DB가 하나인지 여부 역시 구분해야 한다.

기존 원문·관측 시각·해시와 공개 기록은 보존한다. 이를 새 직접 수집의 결과로
바꾸거나, 아래 목적지 관측과 합쳐 같은 승인 창의 양쪽 대조로 사용하지 않는다.
T14 앱→PgBouncer TLS 시험도 해당 구간의 결과이며 풀러→DB 신원 증명은 아니다.
운영 context·판정 저장이나 전환 허가에 이 자료를 사용한 사실은 없다.

## 새 목적지 직접 수집

2026-11-06 **21:31:43 KST**, 목적지 CNPG에 직접 연결해 기존
`bravo_gate.t13.collect_schema`와 T13 `schema_fingerprint`를 실행했다.
앱이나 PgBouncer의 연결 설정을 사용하지 않았다.

| 확인 | 결과 |
| --- | --- |
| 직접 대상 | CNPG UID·Service UID/selector·Ready endpoint·primary Pod 소유권 결속 |
| 접속 | 등록 Service 주소로 직접 연결, 등록 DNS 이름과 CA를 verify-full로 검증 |
| 실제 DB | cluster_name·서버 주소·DB·session/current role 확인 |
| 역할 | 기존 로그인 역할, superuser/BYPASSRLS 없음. 복제 권한은 보유 |
| 스키마·PK | `public.messages`, `public.attachments` 두 테이블 수집·재조회, 오류 없음 |
| 전후 확인 | 동일 DB/Service/Pod/CA/자격 참조 메타데이터와 backend identity 유지 |
| 데이터 변경 | 업무 행 조회 0, 업무 쓰기 0, 시퀀스·로그인·역할 변경 0 |
| 정리 | 생성한 임시 세 자원을 각각 정확한 UID 조건으로 삭제·소멸 확인 |

기존 복제 역할을 사용했으므로 전용 최소 권한 수집 역할의 운영 인수와는 다르다.
암호는 Pod에 읽기 전용으로 마운트한 기존 Secret에서만 사용하고 외부로 내보내지
않았다. 공개 CA만 사전 대조했으며 CA 개인키는 읽지 않았다.

검사 Job은 기존 네이티브 arm64 CNPG 이미지에 고정했고, 잠긴 의존성의 wheel
해시와 번들을 확인했다. 비root·읽기 전용 root·권한 상승 금지·SAToken 미마운트,
목적지 DB TCP 5432만 허용하는 전용 네트워크 정책을 사용했다. SQL은 읽기 전용이며
문장·잠금 시간 제한을 적용했다. 공유 앱·네트워크 정책·DB 역할은 수정하지 않았다.

## 실패와 정정 기록

- 첫 server dry-run은 Kubernetes가 빈 `ingress` 배열을 응답에서 생략해 검사기에
  거부됐다. 자원 생성은 없었다. 명시적 Ingress policyTypes 아래 빈 배열 생략만
  정규화했으며 허용 규칙을 추가하지 않았다.
- 이후 네 실행은 UNKNOWN이었다. 초기에는 원인을 확정하지 못했고, 추가 진단에서
  `inet_server_addr()::text`가 `/32`를 포함해 등록된 순수 IP와 다르게 비교되는 것을
  확인했다. 고정 테스트 주소를 실제 PostgreSQL에서 검사한 뒤 `host(inet)`로
  주소 표현만 수정했다. 주소·클러스터·역할 검사를 생략하지 않았다.
- 각 실패 실행의 세 임시 자원도 UID 조건으로 삭제·소멸 확인했다. 실패를 최종
  PASS 횟수에 포함하거나 최초 시도도 성공한 것처럼 표시하지 않는다.

## 운영 판정에 남은 조건

이는 **목적지 직접 수집기의 자격 확인**이며 운영 T19 PASS가 아니다.
관측 유효기간은 시작 후 30초였고 이미 만료됐다. 새 운영 평가에는 같은 현재 계획과
등록된 출처·권한 아래 양쪽 DB의 새로운 관측이 필요하다. 데이터 행 무결성,
복제 지연, 시퀀스 보정·복구, T10 실제 원문 저장·조회와 T21 운영 표시는 별도다.

[summary.json](summary.json)은 관측·실패·정리의 공개 요약,
[source-manifest.json](source-manifest.json)은 실제 실행 번들의 소스 결속이다.
원문·실행 코드·자원 메타데이터는 비공개로 보존했다. 공개본만으로 운영 자원의
실체나 원문과 해시의 일치를 독립 검증할 수 있다고 주장하지 않는다.

후속 [같은 문맥의 양쪽 직접 수집](paired/README.md)은 새 관측으로 별도 기록했다.
위 목적지 단독 수집이나 과거 앱 경로 관측의 시각·결과를 갱신하지 않는다.
