# 같은 문맥의 양쪽 직접 DB 스키마 수집

앞선 [목적지 단독 수집과 증빙 범위 정정](../README.md) 이후, 같은 검증용
context·정책으로 출발지와 목적지 CNPG를 각각 직접 수집했다.
앱·PgBouncer의 DB 경로와 독립적으로 서로 다른 CNPG/Service/primary Pod,
공개 CA와 서버·DB·역할 신원을 확인했다. 운영 T10의 신뢰 등록은 아니다.

| 항목 | 출발지 | 목적지 |
| --- | --- | --- |
| 관측 시작(KST) | 21:40:43 | 21:40:31 |
| 런타임 | 네이티브 amd64 | 네이티브 arm64 |
| 두 테이블 스키마·PK 수집 | 오류 없음 | 오류 없음 |
| 실제 DB와 전후 backend 신원 | 일치 | 일치 |
| 자신의 임시 자원 정리 | 3개 소멸 확인 | 3개 소멸 확인 |

`public.messages`와 `public.attachments`의 스키마 해시·PK가 일치했다.
서로 다른 DB에서의 **이번 새 관측**만 비교한 결과다. 같은 검증 문맥과 규칙을
사용했고 30초 관측 시간창이 겹침을 확인했다. 앞선 앱 경로 관측을 재사용하거나
시각·hash·DB 참조를 교체한 결과가 아니다.

기존 T13 SQL 규칙과 T19 수집기를 동일한 소스 바이트로 실행했고, 네이티브별로
잠긴 의존성을 패키징했다. 기존 비관리자·비BYPASSRLS 역할은 복제 권한도 보유한다.
전용 최소 권한 수집 역할의 운영 인수를 대신하지 않는다. 업무 행·데이터 쓰기·시퀀스
변경·로그인·역할 변경은 없었다. 자격 값은 각 Pod 밖으로 내보내지 않았다.

**이는 운영 판정·T19 전체 PASS가 아니다.** 실제 운영 게이트는 호출하지 않았다.
30초 증거는 이미 만료됐고 운영 평가에 재사용할 수 없다. 테이블 데이터의 일치,
복제 지연, 시퀀스 리허설, 같은 현재 계획의 출처·권한 등록 및 T10 저장·조회는
별도 인수 대상이다. 스키마 두 개의 일치만으로 전체 이전 범위나 무중단을 주장하지 않는다.

[summary.json](summary.json)에 실제 시각·원문 해시와 정리 결과를,
[source-manifest.json](source-manifest.json)에 두 번들의 동일 소스와 아키텍처별
의존성을 남겼다. 전체 원문과 실행 코드는 비공개로 보존한다.
