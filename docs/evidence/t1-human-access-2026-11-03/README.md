## 적용 과정과 복구

[initial-plan.json](initial-plan.json)의 최초 계획은 그룹·정책 1개와 사용자·그룹 가입·콘솔 프로필 각 4개였다. 첫 시도는 그룹/정책과 첫 신규 사용자/그룹 가입까지 수행한 뒤 CLI의 표준입력 처리 오류로 콘솔 프로필 생성을 중단했다. 암호는 Keychain에 이미 보관됐지만 AWS에는 콘솔 프로필이 생성되지 않았다.

현재 상태를 다시 조회한 [resume-plan.json](resume-plan.json)에 따라 미완료 작업만 재개했다. 암호 전달을 Keychain→메모리 파이프→격리된 AWS SDK로 바꾸었고, 비밀 없는 전달 시험에서 클라우드 호출 0으로 경로를 검증했다. 보관된 첫 암호를 재사용하고 기존 로그인 프로필을 초기화하지 않았다. OS 확인 창은 자동 조작하지 않았다. 사용자의 수동 허용 후 원래 적용이 정상 완료됐다.

최종 코드에는 Keychain 상호작용을 끄는 검사를 추가했다. 이후 기존 항목에 새 도우미 인증이 필요하면 무인 세션이 계속 기다리지 않고 실패한다. 사용자 확인이나 ACL 변경을 우회하지 않는다. 실패 시 현황 재조회부터 시작하며 기존 암호를 삭제하거나 프로필을 다시 만들지 않는다.

## 검증과 남은 범위

기본 scripts 시험 38개와 SDK 프로필 시험 4개가 통과했다([검증 결과](validation.json)). 계정 불일치, 런타임 주체가 섞인 그룹, 중복 사람 매핑, 기존 사용자 충돌, Keychain/SDK 미준비, 기존 프로필 보존, 재실행 무변경, 키 생성·기존 암호 변경 금지 등을 검사했다. Swift 컴파일·Keychain 시험·메모리 전달 시험과 Ruff도 통과했다. macOS의 기존 Keychain API 사용에 대한 컴파일 deprecation 경고는 있으며, 실행 시험은 통과했다.

[validation.json](validation.json)의 해시는 최종 검토/검증 소스에 대한 것이다. 첫 실패 시도 코드의 해시나 원격 배포 아티팩트로 해석하지 않는다. CI와 PR 리뷰는 GitHub에서 별도로 확인한다.

아직 확인하지 않은 항목: 암호의 승인된 경로 전달, 팀원 실제 로그인/암호 변경/MFA, 조직 SCP 등을 포함한 유효 권한, Identity Center 전환, EKS access entry/RBAC, RKE2 개인 인증, DB/PgBouncer 접근 제어. T1 전체 완료나 이슈 체크 해제의 근거로 이 접근 준비 결과만 사용하지 않는다. 운영 절차는 [사람 개발자 접근 가이드](../../human-developer-access.md)를 따른다.
