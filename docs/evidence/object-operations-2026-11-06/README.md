# 저장소 열기·닫기 본인 계정 실행 — 2026-11-06

현재 개발 작업 상태는 **지속 open / PUBLIC_READ**다. 사용자 지시에 따라 HTTP API의 명시적 open을 실행해 17:00 KST에 한 차례 재시작(22.139초)으로 반영했다. 11개 확인 PASS, 실행 객체 CLEAN, 자동 닫힘 false다. 익명 GET/HEAD와 기존 첨부 읽기 200, 익명 PUT/LIST/DELETE/다른 버킷 403, 정상 앱 자격·바이트 보존을 확인했다. [지속 open 실제 결과](persistent-open.json). 아래 16:30 closed 결과는 이전 cycle의 완료 근거이며 현재 상태를 뜻하지 않는다.

실제 ARM RKE2에서 개인 팀 계정으로 고정 운영 작업을 요청했다. 클라이언트는 접수 직후 종료했고 클러스터 작업이 열기와 닫기·정리를 수행했다. 저장소 키를 운영자에게 배포하거나 로컬 Secret 파일로 만들지 않았다. [결과 JSON](result.json)은 개인·클러스터 식별자와 객체 이름·내용을 제외했다. 16:29 cycle 원본에는 실행 소스 해시가 없어 그 실행을 현재 HEAD 검증으로 사용하지 않는다. 16:34 후속 읽기 확인의 소스 해시는 `2036f12cfb7b039f5786f46ccd41d1942ed104ae14fd4c595e54686f12e70828`이며 cycle 소스로 소급하지 않는다. 17:00 지속 open의 실제 실행 소스 해시는 결과 JSON에 공개했다. 개인·클러스터·Pod 식별자만 비공개로 보존한다.

16:29:01–16:30:00 KST 실제 cycle: **13개 확인 PASS / CLEAN**. 열림 Ready 22.089초, 닫힘 Ready 22.091초. 열린 상태 익명 GET/HEAD 200, PUT/LIST/DELETE/다른 버킷 403. 닫힘 후 정책 부재, 익명 GET 403, 기존 첨부 정상 인증 GET 200과 바이트 불변, 실행 전용 객체 삭제·부재 확인. 기존 Deployment UID를 유지하고 Ready 1로 반환했다. DB·복제·PVC는 변경하지 않았다.

16:31 추가 읽기 전용 확인은 closed/정책 없음/정상 인증 GET 200/익명 403 PASS다. 실제 앱의 객체 Secret이 저장소 client와 일치하는지도 클러스터 내부에서 확인했다. 기존 계정 이름을 새 기본 이름으로 덮어쓰지 않았다.

운영 연결의 중단·만료·취소·원래 실패 보존·정책 제거/부재 재조회·UID 교체 거부·실행 소유권과 HTTP 인증/소유권/중복 요청 시험은 복구 경계·전용 audience·미완료 종료 코드 회귀를 포함해 44건, 기존 T3/T15 운영 연결 회귀 12건이 통과했다. 중단된 서버 작업을 다시 열지 않고 닫기만 수행하는 분기는 로컬 시험으로 확인했으며, 공유 실환경의 열린 저장소에 강제 종료 장애를 추가 주입하지 않았다.

이는 한 개인 계정의 실제 실행이다. 다른 팀원 기기·WSL에서 실행했다고 표시하지 않으며, 앱 UI·T14 게이트·실제 AI·승인·컷오버 완료 근거로 사용하지 않는다. 사용법과 설치·복구 한계는 [운영 안내](../../object-operations.md)를 따른다.

HTTP API를 같은 실제 클러스터에 배포한 뒤 기존 cycle 결과를 다시 조회하고 읽기 전용 check를 접수했다. 같은 키 반복은 같은 run, 입력이 다른 같은 키 409, 처리 중 새 요청 409, 오래된 키 410, 임의 owner/확인 없는 open 400, 유효한 앞쪽 인증과 잘못된 서비스 토큰 조합 401을 확인했다. 같은 run 취소 반복도 유지됐고 SeaweedFS Deployment generation은 변하지 않았다. API 실측 15건은 별도 비공개 원본에 보존했다. 이후 사용자 지시에 따른 지속 open은 같은 HTTP API로 실제 접수·실행했다. 상태 GET의 open/PUBLIC_READ, 지속 open 모드에서 cycle409, 배포된 OpenAPI와 저장소 명세 일치도 확인했다.

## 병합 전 복구 수정

첫 변경 전 거부는 재시작 없이 FINISHED/FAIL로 끝낸다. 실제 Worker에 메모리 Kubernetes/S3 경계를 연결해 빈 버킷 close, 추가 신원의 cycle, 앱 Secret 불일치, 실행 중 기존 첨부 삭제, 정상 open의 자기 객체 정리를 검증했다. 앱 검증 실패와 닫힘/자기 객체 삭제 결과를 분리하며 최초 오류를 보존한다. 복구 100주기 뒤 기록 크기도 제한 안에서 유지했다. 이 실패 주입은 로컬 합성 시험이며 공유 저장소의 실장애 주입으로 표시하지 않는다. 서비스 인증은 전용 audience `bravo-object-operations`로 분리했다.
