# T8 역방향 재개 측정 (2026-11-06)

해석과 절차는 [운영 문서](../../operations/t8-replication-health.md#컷오버-뒤-역방향-재개)에 있다. 전부 임시 컨테이너의 대역이고 실제 환경에서는 아무것도 돌리지 않았다.

| 파일 | 내용 |
| --- | --- |
| `lab.json` | `replication_resume_lab.py reverse`: 임시 PostgreSQL 18.4 두 대, 가정한 netem 100Mbps · RTT 30ms, 3회. 각 회의 `checks`와 명령 출력 전체 |
| `source-manifest.json` | 측정 코드가 들어간 커밋의 파일 해시 |

**컷오버는 lab이 흉내 냈다.** Executor를 돌리지 않고, Executor가 성공하면 남기는 상태를 같은 순서로 만들었다(`cut_over`). 시퀀스는 목적지 최대 id로 맞췄다.

**시간 초과는 5초다.** 링크를 끊으면 바로 꺼지도록 lab 기본값(11/6 이전 실제 값)을 썼다. 렌더 값 30초는 재지 않았다.

**DSN 역할.** 출발지(구독 쪽)는 소유자 권한으로, 목적지(발행 쪽)는 `chat_replicator`로 읽었다. 정방향 lab과 같은 배치다. 시험 행은 목적지의 `t8_probe`로만 썼다.

**측정한 코드와 커밋의 차이.** 측정은 커밋 전 작업 트리에서 돌렸고, 그 코드는 `source-manifest.json`의 커밋(`83cac24`)과 같다. 측정을 시작한 뒤에는 시험 파일과 문서만 바뀌었다.

머신 부하는 다른 세션과 함께 쓴 값으로, 각 회의 `machine`에 있다.
