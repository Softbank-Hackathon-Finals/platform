# T14 실제 AWS 앱 신원으로 실행한 IAM-01.1

2026-11-04 18:45–18:48 KST에 팀 출발지 앱에서 기존 `QualifiedAwsProbe`와
`Runner`를 실행했다. **IAM-01.1 한 항목의 실제 AWS 자격 시험**이다. 대상 환경,
전체 보안 게이트 또는 T10 등록 경로의 인수 완료를 뜻하지 않는다.

| 시험 | 결과 | 근거 |
|---|---|---|
| 등록 기대값과 실제 STS 신원 대조 → 앱 읽기 → 익명 GET → 앱 재읽기 | IAM-01.1 PASS, HTTP 200 → 403 → 200 | `control-run.json`, 연결된 `evidence-*.json` |
| 기대 IAM RoleId를 다른 값으로 주입 | UNKNOWN / TOOL_ERROR | `control-run-wrong-role-id.json` |
| 증거 바이트 수신 후 보존 확인 응답 거부 | UNKNOWN / TOOL_ERROR, PASS 미발행 | `control-run-retention-rejected.json` |
| 연결하지 않은 Secret·감사 시험 | UNKNOWN / NOT_RUN | 세 ControlRun 모두 |

기존 객체의 고정 버전을 읽었으며 버킷 정책, 역할, 객체, 앱 Deployment를 변경하지 않았다.
Deployment UID·spec·generation의 전후 동일성을 확인했다. 앱 설치 패키지를 바꾸지 않고
한 프로세스의 임시 디렉터리에 시험 패키지를 풀었다. 성공·실패 실행 종료 시 해당 디렉터리를
정리한다. 정상 실행 후 잔여 임시 디렉터리 0개를 직접 확인했다.

## 실행과 증거 보존

1. 운영자 읽기 권한으로 출발지 Deployment·ServiceAccount와 IAM GetRole을 대조했다.
   역할 ARN뿐 아니라 고유 RoleId를 기대값으로 고정했다. 버전 관리 객체의 현재 버전도 고정했다.
2. 앱 프로세스에서 기존 IRSA 자격의 단기 스냅샷과 실제 만료를 읽었다. 운영자 자격을
   Pod에 넣거나 자격 값을 로컬로 반출하지 않았다. STS와 S3 호출은 이 스냅샷을 사용했다.
3. `source-manifest.json`의 변경 없는 제품 소스와 T5 정본을 번들로 전달했다. 앱에 없던
   jsonschema 의존성 6개는 `uv.lock`의 정확한 wheel SHA-256을 확인한 뒤 포함했다.
   다운로드는 운영자 장치에서 수행했고, Pod 안에서 패키지를 내려받거나 설치하지 않았다.
4. 제품이 만든 envelope 바이트를 운영자 장치의 접근 제한 디렉터리에 저장하고 파일·디렉터리를
   fsync한 뒤에만 SHA-256에 결속된 보존 ACK를 돌려줬다. 전체 원격 시험에는 120초 한도를 뒀다.
5. 대조 시험에서는 잘못된 RoleId 또는 보존 거부 ACK만 주입했다. 실제 역할/정책을 바꾸지 않았다.

`control-run.json`의 `output_sha256`은 같은 이름의 envelope 파일 바이트와 일치한다.
역할·세션·객체 식별자는 제품이 만든 해시로만 기록된다. 이 공개 JSON은 민감값을 포함하지 않은
제품 출력의 동일 바이트이며, 실제 운영 리소스 등록 입력과 실행 harness 원문은 비공개로 보존한다.
`summary.json`은 그 원문의 해시와 확인 범위를 기록한다. 해시만으로 실행 사실이나 운영 리소스
실체를 독립 증명할 수 있다는 주장은 하지 않는다.

## 다음 인수와 한계

- `operator-qualified/source`는 이번 운영자 시험의 범위 표기다. T10 정본에 등록된 환경 참조로
  바꾸어 제출하지 않는다. 서버 등록·현재 계획 결속과 승인된 증거 저장소 연결은 남아 있다.
- SEC-01.1, AUD-01.1 및 목적지 시험을 수행하지 않았다. T19 전체 게이트는 이 결과만으로 통과할 수 없다.
- 잘못된 역할 기대값과 보존 거부는 시험했지만 실제 자격 만료·회수는 시험하지 않았다.
- 로컬 fsync ACK는 중앙 증거 저장소의 접근 통제·장기 보존·복구 능력을 검증한 결과가 아니다.
- 과거 PASS의 유효성은 소비 시점의 증거 만료·프로필·현재 계획·대상 결속으로 다시 판정해야 한다.
- 이 자격 시험을 위해 정책을 약화하거나 새 앱/DB를 배포하지 않았다. 별도 Secret·감사·목적지 인수는
  각 담당자가 제공한 승인 범위와 읽기 참조가 준비된 뒤 수행한다.
