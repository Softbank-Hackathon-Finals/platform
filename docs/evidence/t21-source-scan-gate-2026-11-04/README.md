# 실제 출발지 소스 검사 → 게이트 → 콘솔 연결

2026-11-04 20:47~20:51 KST에 출발지의 보존된 SEC-01.2 결과를 로컬 T19·T10·T21로 연결했다. [원 출발지 검사](../t14-source-scan-2026-11-04/README.md)의 ControlRun 바이트와 관측 시각을 변경하지 않았다. source-run SHA-256은 원 증빙과 같으며 이 시험에서 소스 검사를 다시 했다고 표시하지 않는다.

목적지는 실제 접속하지 않았다. 제품 Runner에 검사기를 하나도 등록하지 않아 full 프로필 20개가 모두 `UNKNOWN/NOT_RUN`인 별도 결과를 생성했다. 원래 환경을 실제 목적지로 위장하지 않도록 `unverified-target` 등록을 사용했다.

## 확인 결과

- T19: 출발지 SEC-01.2는 PASS, 목적지는 UNKNOWN이어서 해당 행은 `TARGET_UNKNOWN/BLOCK`. 나머지 19개는 `SOURCE_UNKNOWN/BLOCK`, 전체는 BLOCK.
- 불완전한 보고서는 보안 전제조건을 발급하지 않음. 전체 결과만 PASS로 바꾼 입력, 만료·회수된 시험 서명 권한은 거부.
- 실제 HTTP/SQLite를 사용하는 로컬 T10·T21에서 같은 보고서 digest와 20개 행 표시. 승인·실행·확인 버튼 잠금, 브라우저 변경 요청 0건.
- Chromium·WebKit에서 각각 3회(합계 6회) 반복 통과. 로그인 쿠키를 없앤 뒤 권한 오류·보호 데이터 제거·실행 잠금 확인.

## 실패와 수정

첫 실행은 Chromium 통과·WebKit 실패였다. 시험이 `권한`이라는 부분 문자열을 기다려 기존 일반 안내문을 권한 회수로 오인했다. 실제 권한 오류 문장 전체를 기다리고 브라우저 JavaScript 예외도 검사하도록 수정했다. 이후 WebKit 단독 1회와 두 브라우저 반복 6회를 통과했다. 제품의 인증/권한 판정이나 대기 시간을 완화하지 않았다.

## 범위

서명 키·사용자·계획·보고서 신뢰 등록은 **로컬 시험 권한**이다. 실제 IdP 로그인, 운영 T10 발급자 등록, 양쪽 환경 전체 게이트, 사람 승인, Executor 호출 또는 컷오버 완료가 아니다. 실환경에서 수집한 출발지의 일부 사실을 UI가 근거 이상으로 확대하지 않는 경로를 확인했다.

원 보고서·시험 실행 로그·두 브라우저 화면은 운영자 비공개 검증 디렉터리에 보관했다. 공개 문서에는 접속 주소·개인 정보·자격증명이 없다.

## 재현

`verify_live_audit_gate.py --mode source-scan-partial`에 원 source-run과 명시적 NOT_RUN target-run, 새 비공개 출력 폴더를 전달한다. 콘솔의 기존 `testing/live_report.config.js`에 생성 보고서 경로·정확한 해시·시험 계획 digest를 전달하고 `BRAVO_TEST_REPORT_KIND=source-scan-partial`로 실행한다. 생성된 시험 서명은 운영 권한으로 재사용하지 않는다.

## 리뷰 후 출처 결속 보강 (21:40 KST)

초기 재현 스크립트는 입력 형식과 판정만 확인하므로 다른 source-run도 보존된 AWS 원본으로 표시할 수 있었다. 전체 게이트는 BLOCK이었으나 출처 주장은 잘못될 수 있었다. 이제 #216에서 별도로 보존한 원본 바이트 SHA-256을 코드에 고정하고, 다른 입력은 서명·게이트 생성·AWS 원본 표시 전에 거부한다. 호출자가 예상 해시를 바꾸는 옵션은 없다. 이 모드는 해당 과거 실행에 한정되며 일반 운영 업로드 API가 아니다.

실제 보존 원본은 통과했고 실행 ID·환경 참조·증거 해시 변조는 각각 비정상 종료, INCOMPLETE, AWS 출처 표시 없음, 게이트 산출물 없음으로 확인했다. 단위 5개와 수정된 경로의 Chromium·WebKit 각 3회가 통과했다. 이전 결과와 소스 매니페스트는 당시 실행 기록으로 보존하고 [추가 회귀 근거](source-binding-regression.json)를 별도로 남긴다.

### 최적화 실행과 목적지 입력 검증

후속 검토에서 `python -O`가 자격 시험의 assert를 제거하면 목적지 TIMEOUT/PASS 입력도 미실행으로 요약하는 문제가 확인됐다. 모든 실행 중 자격 검사를 명시적인 오류 처리로 바꾸고 목적지 20개 전부 UNKNOWN/NOT_RUN일 때만 이 모드의 미실행 출처 설명을 기록한다. 일반/최적화 각각 정상은 통과, TIMEOUT/PASS 변조는 INCOMPLETE·비교 보고서 미생성으로 확인했다. 관련 회귀 15개 통과. [추가 결과](optimized-target-regression.json).

출처 회귀 매니페스트의 source_revision 누락으로 필수 secrets의 증빙 형식 검사가 실패한 기록도 있다. 당시 파일 바이트와 일치하는 커밋을 연결했으며 검사 예외나 CI 규칙을 완화하지 않았다.
