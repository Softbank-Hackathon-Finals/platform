# T8 첨부 복사 로컬 실측 (2026-11-04)

첨부 복사는 이제 저장소 코드만으로 실행된다. 다만 **로컬 컨테이너에서만** 쟀다. 실제 S3, 실제 SeaweedFS 배포, Tailscale 경로는 재지 않았으므로 T8의 다섯 번째 할 일은 아직 끝나지 않았다.

클라우드 자원은 호출하지 않았다. 숫자는 모두 스크립트가 실행 결과에서 만든 [result.json](result.json)과 [mutations.json](mutations.json)에서 왔다. 실행 방법은 [대상 워크로드 안내](../../../infra/envs/target-workloads/README.md)에 있다.

### 일부러 검사를 뺀 결과

첫 실행에서는 26개 중 1개(`raw_exception_suppression`)가 살아남았다. 코드가 아니라 시험이 약했다. `__suppress_context__`는 `from error`에서도 참이라서 아무것도 재지 못했다. T12가 남기는 traceback에 원본 메시지가 없는지 직접 보는 시험으로 바꿨다. 시간 제한을 뺀 복사본에서는 잠금 시험이 끝나지 않아, 잠금이 3초 뒤 풀리게 바꿔 멈추지 않고 실패하게 했다. 지금은 시험 함수가 실제로 실패해야만 잡힌 것으로 센다. 최종 46개가 모두 잡혔고, 건별 실패 시험은 [mutations.json](mutations.json)에 있다.

### PR 리뷰 지적: 비밀번호가 TLS 판단보다 먼저 나감

`b7101f0`의 `connect_read_only`는 연결을 끝낸 뒤에 `sslmode`를 확인했다. 리뷰에서 cleartext 인증을 요구하는 가짜 서버로 비밀번호가 먼저 전송되는 것이 보고됐다. 같은 가짜 서버를 시험으로 만들어 실제 libpq로 돌렸다. 시험 비밀번호는 실제 자격이 아닌 고정 문자열이다.

고치기 전 코드에서 13개 중 9개가 비밀번호 전송으로 실패해 지적이 재현됐다. 나머지는 재현이 아니다. 1개(TLS를 거절하는 서버)는 그때도 통과했고, 3개는 새 인수가 없어 실패했다.

| 설정 | 고치기 전 | 고친 뒤 |
| --- | --- | --- |
| 원격 이름 + 로컬 주소, `sslmode=disable` (DSN, 빈 DSN의 `PG*`) | 비밀번호 전송 | 연결 전 거부, 서버 접촉 0회 |
| `PG*`에 `sslmode` 없음 | 비밀번호 전송 | 연결 전 거부, 서버 접촉 0회 |
| DSN `sslmode=disable` + `PGSSLMODE=verify-full` | 비밀번호 전송 | 연결 전 거부, 서버 접촉 0회 (DSN이 우선) |
| 루프백 주소, 시험 예외 없음 | 비밀번호 전송 | 연결 전 거부, 서버 접촉 0회 |
| 서비스 파일 (`PGSERVICE`, DSN `service`) | 비밀번호 전송 | 연결 전 거부, 서버 접촉 0회 |
| Unix 소켓 + `verify-full`, 소켓이 섞인 호스트 목록 | 비밀번호 전송 | 연결 전 거부, 서버 접촉 0회 |
| 시험 예외 + 원격 이름, 시험 예외 + 루프백 `PG*`를 덮는 서비스 파일 | 새 인수라 돌리지 못함 | 연결 전 거부, 서버 접촉 0회 |
| 정상 설정(`verify-full`)인데 서버가 TLS를 거절 | 전송 안 됨 | 전송 안 됨 |
| 대조군: 시험 예외 + 루프백 + `sslmode=disable` | 새 인수라 돌리지 못함 | 비밀번호 도착. 가짜 서버가 실제로 받는다는 확인 |

Unix 소켓은 지적에 없던 경우다. libpq가 `sslmode`와 상관없이 TLS를 쓰지 않아 `verify-full`이어도 평문으로 나갔고, 연결 후 확인도 통과했다. 루프백 예외도 조건 없이 열려 있어서, 원격 DB로 가는 로컬 터널이 평문을 쓸 수 있었다.

이제 `connect_read_only`는 `psycopg.connect` 전에 libpq 우선순위(DSN, 서비스 파일, `PG*`)대로 판단한다. 서비스 파일은 해석하지 않고 거부한다. 통과하면 `sslmode=verify-full`과 `gssencmode=disable`을 연결 인수로 고정한다. 연결 후 확인은 추가 확인으로 남겼다. 루프백 예외는 시험 전용 변수를 켜고 이름 · 주소가 모두 `127.0.0.1` 또는 `::1`일 때만 적용되며, `localhost` 이름은 더 이상 예외가 아니다.

### PR 전 코드 리뷰

`/code-review`의 지적 10건 중 9건을 재현 시험과 함께 고쳤다. 응답이 끊긴 PUT의 SDK 재시도가 거짓 충돌을 내던 문제, `AWS_ENDPOINT_URL`이 출발지를 다른 저장소로 돌리던 문제, `localhost` 이름에 원격 `hostaddr`를 주면 TLS 검사를 건너뛰던 문제, DB 잠금에 시간 제한이 없던 문제 등이다. 같은 버킷 검사가 주소 문자열만 비교하는 1건은 고치지 않았다. 실제 출발지는 주소가 비어 있어 이 경로에 닿지 않는다. DB 연결이 조회 중 끊김 없이 멈추는 네트워크 정지는 시간 제한으로 막히지 않으며 재지 않았다.

## 재지 않은 것

- **실제 S3:** IAM, KMS 복호화, 페이지 처리, 서명을 재지 않았다. `ExpectedBucketOwner`는 요청에 실리는 것만 확인했다. moto와 SeaweedFS 모두 틀린 소유자를 그대로 받아서 거부 동작은 재지 못했다.
- **실제 SeaweedFS 배포:** RKE2, PV, NetworkPolicy, 재시작 뒤 보존, `kubectl port-forward` 경로를 재지 않았다. 에뮬레이션 위의 같은 이미지로만 재었다.
- **Tailscale 경로:** 처리량, 지연, MTU 1280, DERP 경유를 재지 않았다. 시간 값을 이 경로의 예상치로 쓰면 안 된다.
- **GSSAPI:** `gssencmode=disable`이 연결 인수로 넘어가는 것만 확인했다. 실제 Kerberos 환경에서는 재지 않았다.
- **T12 통합:** Executor에서 호출하지 않았다. 이미지에 boto3와 이 파일들이 없고, S3 읽기 권한과 SeaweedFS까지의 네트워크 경로도 없다.
- **복사와 쓰기 차단 사이의 업로드:** 이 명령은 알 수 없다. 그 행은 복제되지만 객체는 목적지에 없게 된다. 안내에 T12가 쓰기 차단 뒤 건수를 비교하는 방법을 적었다.
- **T9 이후 HTTPS 목적지:** 지금 개발 경로는 HTTP다. 사설 CA를 `AWS_CA_BUNDLE`로 주면 출발지 S3 연결에도 함께 적용되므로, HTTPS로 바뀌면 목적지 전용 CA 설정이 필요하다.

## 알아둘 점

- `source_write_calls`는 #131 함수가 0으로 고정해 돌려주는 값이다. 잰 값이 아니어서 영수증에서 뺐다. 대신 출발지 어댑터에 쓰기 메서드가 없는지와, 복사 전후 출발지 ETag · 수정 시각이 같은지를 시험으로 확인한다.
- 전송 중 출발지가 바뀌면 옛 내용이 목적지에 남을 수 있고, 재실행은 충돌로 멈춘다. 덮어쓰지 않는 설계의 결과이므로 사람이 정리한다.
- 개발 출발지에는 11/3 증거의 준비 확인용 객체가 DB 밖에 남아 있다. 그 환경에서 돌리려면 `ATTACHMENT_APPROVED_EXTRA_KEYS_FILE`로 개별 승인해야 한다.
- 이 머신의 Docker Hub 토큰이 만료돼 있었다. SeaweedFS와 moto 이미지는 레지스트리 API에서 익명으로 받아 각 층의 해시를 확인한 뒤 `docker load`로 올렸다. Docker 로그인 설정은 건드리지 않았다.
- `t8-attach-` 컨테이너는 모두 지웠다. 시험용 키는 실행마다 무작위로 만들어 컨테이너에만 넘겼고 파일에 남기지 않았다.
