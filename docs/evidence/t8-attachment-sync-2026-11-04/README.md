# T8 첨부 복사 로컬 실측 (2026-11-04)

첨부 복사는 이제 저장소 코드만으로 실행된다. 다만 **로컬 컨테이너에서만** 쟀다. 실제 S3, 실제 SeaweedFS 배포, Tailscale 경로는 재지 않았으므로 T8의 다섯 번째 할 일은 아직 끝나지 않았다.

클라우드 자원은 호출하지 않았다. 숫자는 모두 스크립트가 실행 결과에서 만든 [result.json](result.json)과 [mutations.json](mutations.json)에서 왔다. 실행 방법은 [대상 워크로드 안내](../../../infra/envs/target-workloads/README.md)에 있다.

### 일부러 검사를 뺀 결과

첫 실행에서는 26개 중 1개(`raw_exception_suppression`)가 살아남았다. 코드가 아니라 시험이 약했다. `__suppress_context__`는 `from error`에서도 참이라서 아무것도 재지 못했다. T12가 남기는 traceback에 원본 메시지가 없는지 직접 보는 시험으로 바꿨고, 빠져 있던 검사 2개를 추가해 최종 28개가 모두 잡혔다. 건별 실패 시험은 [mutations.json](mutations.json)에 있다.

## 한도: 객체 100개, 합계 16MiB

**지금 확인되는 데이터에는 맞지만, 데모 중 업로드를 막는다는 전제가 코드로 지켜지지 않아 그대로 믿을 수는 없다.** 넘어도 데이터는 안전하다. 아무것도 쓰지 않고 멈추므로 컷오버가 시작되지 않을 뿐이다.

| 근거 | 내용 |
| --- | --- |
| 개발 고정 데이터 | 객체 2개, 119바이트 ([11/3 증거](../2026-11-03-t8-development/README.md)). 여유 충분 |
| 앱의 파일당 상한 | 10MiB (`demo-chat` `app/config.py`, 고정 커밋과 현재 main 모두). **상한에 가까운 파일 2개면 16MiB를 넘는다** |
| 업로드 경로 | 설계는 "데모 중 새 첨부 업로드 없음"이지만 `demo-chat` main 화면에 `+ 첨부` 버튼이 있고, 서버는 쓰기 차단 전까지 받는다 |
| 데모 시드 | 저장소에 없다. T28 reset도 아직 없어 최종 첨부 수와 크기를 알 수 없다 |
| 메모리 | 최고 메모리가 작은 객체 3개일 때 86MB, 10MiB + 6MiB일 때 121MB. 16MiB는 메모리 때문에 필요한 값이 아니다 |
| 시간 | 100개 · 16MiB에 1.85초, 10MiB + 6MiB에 0.95초. 로컬 루프백이라 실제 경로의 시간이 아니다 |

한도를 올리려면 Tailscale 경로에서 시간을 먼저 재야 한다. `MAX_BYTES`는 #131 함수의 상수이고 파일당 한도와 합계 한도를 함께 정하므로 이번에는 바꾸지 않았다.

## 재지 않은 것

- **실제 S3:** IAM, KMS 복호화, 페이지 처리, 서명을 재지 않았다. `ExpectedBucketOwner`는 요청에 실리는 것만 확인했다. moto와 SeaweedFS 모두 틀린 소유자를 그대로 받아서 거부 동작은 재지 못했다.
- **실제 SeaweedFS 배포:** RKE2, PV, NetworkPolicy, 재시작 뒤 보존, `kubectl port-forward` 경로를 재지 않았다. 에뮬레이션 위의 같은 이미지로만 재었다.
- **Tailscale 경로:** 처리량, 지연, MTU 1280, DERP 경유를 재지 않았다. 시간 값을 이 경로의 예상치로 쓰면 안 된다.
- **T12 통합:** Executor에서 호출하지 않았다. 이미지에 boto3와 이 파일들이 없고, S3 읽기 권한과 SeaweedFS까지의 네트워크 경로도 없다.
- **복사와 쓰기 차단 사이의 업로드:** 이 명령은 알 수 없다. 그 행은 복제되지만 객체는 목적지에 없게 된다. 안내에 T12가 쓰기 차단 뒤 건수를 비교하는 방법을 적었다.
- **T9 이후 HTTPS 목적지:** 지금 개발 경로는 HTTP다. 사설 CA를 `AWS_CA_BUNDLE`로 주면 출발지 S3 연결에도 함께 적용되므로, HTTPS로 바뀌면 목적지 전용 CA 설정이 필요하다.

## 알아둘 점

- `source_write_calls`는 #131 함수가 0으로 고정해 돌려주는 값이다. 잰 값이 아니어서 영수증에서 뺐다. 대신 출발지 어댑터에 쓰기 메서드가 없는지와, 복사 전후 출발지 ETag · 수정 시각이 같은지를 시험으로 확인한다.
- 전송 중 출발지가 바뀌면 옛 내용이 목적지에 남을 수 있고, 재실행은 충돌로 멈춘다. 덮어쓰지 않는 설계의 결과이므로 사람이 정리한다.
- 개발 출발지에는 11/3 증거의 준비 확인용 객체가 DB 밖에 남아 있다. 그 환경에서 돌리려면 `ATTACHMENT_APPROVED_EXTRA_KEYS_FILE`로 개별 승인해야 한다.
- 이 머신의 Docker Hub 토큰이 만료돼 있었다. SeaweedFS와 moto 이미지는 레지스트리 API에서 익명으로 받아 각 층의 해시를 확인한 뒤 `docker load`로 올렸다. Docker 로그인 설정은 건드리지 않았다.
- `t8-attach-` 컨테이너는 모두 지웠다. 시험용 키는 실행마다 무작위로 만들어 컨테이너에만 넘겼고 파일에 남기지 않았다.
