# T22: 실제 출발지·목적지 앱 읽기 전용 점검

2026-11-06 KST에 실제 EKS 출발지와 독립 온프렘 RKE2 목적지의 앱을 각각 조회했다.
양쪽 앱은 1/1 Ready였으며 개인 Kubernetes 접속 경로의 loopback port-forward에서
총 14개 점검을 통과했다. 로컬 Docker 앱이나 합성 HTTP 서버를 사용한 결과가 아니다.

| 점검 | 출발지 | 목적지 |
| --- | --- | --- |
| 기본 화면·health·ready | 각각 200 | 각각 200 |
| 앱의 DB ping | 200 | 200 |
| 환경 조회와 HTTP 환경 헤더 | aws | onprem |
| 인증 없는 관리 상태 조회 | 401 거부 | 401 거부 |
| WebSocket hello와 HTTP 상태 일치, 프로토콜 ping/pong | 통과 | 통과 |

WebSocket에는 최대 signed bigint의 `after` 값을 사용해 과거 메시지를 받지 않았다.
응답은 상태·환경·해시만 보존했고 채팅 본문·비밀값은 수집하지 않았다.
업무 메시지 쓰기, 첨부 업로드, 관리 설정 변경, 강제 연결 종료와 컷오버는 0회다.
부하 생성기가 아니며 측정 시간·성능 자격을 제시하지 않는다.

시험 전후 양쪽 Deployment UID·spec은 같고 generation은 각각 5였다.
출발지는 현재 등록된 앱의 namespace·ServiceAccount·정확한 image와 일치했다.
목적지는 공식 개인 단기 토큰 접속 도구로 실제 대상 클러스터의 앱을 조회했다.
목적지 앱과 등록 원문 전체의 동등성을 이번 점검만으로 주장하지 않는다.

## 이 점검이 증명하지 않는 것

- 고정 공개 URL, 실제 Edge 전환과 휴대폰 브라우저 동작
- 1012 강제 종료 뒤 재접속과 전환 중 신규 메시지·첨부 저장
- 양쪽 앱이 쓰는 DB 신원의 동등성이나 DB 데이터 이전·무결성
- T14의 모든 통제 PASS, T19 운영 판정·승인 또는 무중단 이전 완료

T22의 남은 완료 기준은 실제 컷오버 중 휴대폰 채팅 지속과 환경 전환이다.
따라서 완료 체크를 올리지 않았다. T10/T19 실제 계획의 수신·판정과 T12/T17의
전환 담당 경로를 재사용하며, 별도 승인·실행기를 만들지 않는다.

실제 세부 응답·배치 원문·접속 정보와 점검 스크립트는 비공개로 보존했다.
[summary.json](summary.json)은 공개 가능한 요약·해시이며, 공개본만으로 운영
자원의 실체를 독립 검증할 수는 없다. [source-manifest.json](source-manifest.json)의
revision은 증빙 기준선이고 실행 중인 앱의 소스 revision을 대신하지 않는다.
실행 이미지 digest는 요약의 각 runtime 필드에 별도로 남겼다.
