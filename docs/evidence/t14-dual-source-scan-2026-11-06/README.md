# T14 양쪽 실제 앱의 소스·배포 명세 검사

2026-11-06 18:06–18:08 KST, 기존 EKS 출발지와 온프렘 목적지 앱에서
**SEC-01.2가 각각 PASS**였다. 각 실행의 나머지 19개 시험은 UNKNOWN/NOT_RUN이다.
T10 저장이나 T19 운영 PASS를 뜻하지 않는다.

## 실제 확인

- 기존 등록의 고정 demo-chat 소스 revision에서 추적된 텍스트 파일 93개를 준비했다.
  앱 코드를 import하거나 git hook을 실행하지 않았다.
- 양쪽 실제 앱 프로세스에서 `/app/app` 파일 17개의 해시를 읽었으며 고정 revision의
  앱 파일 전체와 같았다. 임의 로컬 checkout을 실행 이미지의 원본이라고 가정하지 않았다.
- 실제 Deployment/Pod 명세 두 개를 검사했다. 목적지는 앱이 참조하는 텍스트
  ConfigMap 한 개도 읽어 검사하고 UID/resourceVersion/data를 전후 대조했다.
  출발지는 해당 ConfigMap 참조가 없었다.
- 고정 Gitleaks 8.30.1의 공식 아카이브 해시와 실행 파일 바이트를 대조했다.
  제품 `GitleaksProbe`의 고정 기본 규칙을 사용했으며 앱의 allowlist·baseline·allow 주석을
  적용하지 않았다. 각 소스·렌더 명세 검사는 완료됐고 탐지 결과는 없었다.
- 앱 파일·실행 Pod·배포·연결 참조를 전후 대조했다. Secret payload, 프로세스 환경,
  마운트된 비밀, 업무 행은 읽지 않았다. 앱·정책·DB 변경이나 업무 요청 쓰기는 없었다.

목적지 첫 시도는 ConfigMap 참조를 발견해 검사 전에 중단했다. 이를 누락한 채 PASS로
처리하지 않았다. 참조된 텍스트 ConfigMap만 정확히 포함하고 전후 불변성을 검사하는
별도 시도로 재실행했다. 최초 시도와 두 최종 원문을 비공개 보존했다.

## 범위와 인수 조건

출발지는 현재 등록된 image·ReplicaSet·SA와 대조했다. 목적지는 실제 앱 파일이 같은
소스 revision과 일치함을 확인한 범위이며, 목적지의 전체 등록·이미지 공급망이 동등하다는
판정은 아니다. 이미지 레이어·의존 패키지·이전 Git 이력·비밀 마운트는 검사하지 않았다.
파일이 탐지 규칙에 걸리지 않았다는 결과를 전체 비밀정보 부재로 일반화하지 않는다.

새 실행의 run ID·시각·해시를 그대로 보존했다. 이전 TLS 실행의 행을 가져오거나 여러
실행을 합쳐 하나의 결과로 표시하지 않았다. 운영 호스트의 출처 인증·현재 권한·불변
저장·같은 계획 소비는 별도 인수가 필요하다. 개인 접속 권한은 제품 실행 권한이 아니다.

[실측 요약](summary.json)과 [제품 수집기 소스 지문](source-manifest.json)을 공개한다.
원본·비공개 준비 스크립트의 해시는 요약에 남겼다. 이 공개 요약만으로 전체 운영
준비 절차를 독립 재현했다고 주장하지 않는다. T14 완료 체크는 유지한다.
