# T19 계획별 공개키 원장 자격

기존 T10 계획 트랜잭션에서 공개키 등록·폐기를 보존하고 현재 `GateRecordView`에서
읽는 선택적 어댑터다. 명시적 관리 권한·키별 revision·폐기 이력·현재 읽기 권한을
검사하며 운영 신원이나 권한을 자동 생성하지 않는다.

## 검증

- 첫 키 원장 커밋만 체크아웃한 별도 작업 트리에서 **T19 전체 553개 PASS**.
  후속 서명 원장 미커밋 파일은 이 트리와 시험 결과에 포함하지 않았다.
- 새 66개는 실제 SQLite/PostgreSQL 17.11에서 수행했다. 서로 다른 공개키의 동시 등록,
  현재 권한 회수 시 삽입 롤백, 등록/폐기 재시도, 폐기 후 재등록·공개키 이름 바꾸기 거부,
  tenant·용도·revision·이력 불일치, 시계 역행, 다른 정책/종료된 view 거부와 오류 비노출을 확인했다.
- 사본에서 최종 권한 재검사·신뢰 시작 시각 보정·최신 폐기 반영을 각각 제거했다.
  **3개 변이 모두 SQLite/PG 각 회귀에서 검출**했다. 최초 시도는 pytest 경로 설정이
  원본 패키지를 선택해 검출로 세지 않았다. 실제 변이 모듈 경로·해시를 고정한 재시험만
  검출 결과에 포함했다. 원본/CI 정책은 변경하지 않았다.
- 첫 커밋의 wheel을 Linux arm64/Python 3.12.14의 비root·네트워크 없음·읽기 전용 root
  컨테이너에서 실행했다. 실제 SQLite 등록·조회·폐기와 계획 상태 불변을 확인했다.
  컨테이너는 자동 정리했다. 이미지에는 자격증명이나 호스트 홈을 마운트하지 않았다.

## 주장 범위

DB·서명 라이브러리·Linux 런타임은 실제이며 주체/키/관측은 합성 fixture다.
wheel은 키 원장만 포함하며 후속 서명 원장은 포함하지 않는다. 실행한 컨테이너는
자격 시험 기반 이미지이므로 실제 새 운영 이미지 배포 완료와 구분한다.

운영 T10 원문 수신·관리 권한 배정·발급자 인수·관측 원문 서명·T19 실제 판정·콘솔
운영 인수는 남아 있다. 개인 키나 운영 발급자를 이 시험으로 등록하지 않았고 운영 DB 쓰기는 0회다.
