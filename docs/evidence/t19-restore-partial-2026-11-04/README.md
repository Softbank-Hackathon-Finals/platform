# T35 → T14 → T19 부분 검증 — 2026-11-04

실제 로컬 CNPG 백업에서 만든 복원본을 TLS verify-full/SELECT 전용 역할로 새로 읽었다.
등록된 백업·복원 UID와 원래 실행 문맥을 그대로 사용했고, T14 전체 프로필 20행을 생성했다.
출발지 DR-01.1은 PASS, 나머지19개는 UNKNOWN이다. 대상 환경은 연결되지 않았으므로
수집기를 등록하지 않은 T14 실행으로20개 UNKNOWN을 명시했다.

두 실행을 T19의 정본 스키마·프로필·서명 검증 경로에 입력했다.

- DR-01.1은 TARGET_UNKNOWN, 나머지는 SOURCE_UNKNOWN으로 차단.
- 전체 BLOCK이며 실행 전제조건을 발급하지 않음.
- 전체 결과를 PASS로 바꾼 입력, 만료·회수된 서명 주체 거부.
- 서명·권한/저장소는 시험용 로컬 구현. 실제 운영 KMS·SSO·팀 환경 적용이 아님.

이는 한쪽 복원이 성공해도 양쪽 검증을 완료한 것처럼 통과시키지 않는 연결 시험이다.
데이터 준비나 실제 컷오버, T35 양쪽 운영 인수를 완료했다고 주장하지 않는다.
출발지 복원본과 백업은 검사 목적으로 보존했고 새 임시 SQL 역할은 회수했다.

재현(운영자가 보존한 비공개 실제 실행 결과만 입력):

```sh
uv run python testing/verify_live_audit_gate.py --mode restore-partial \
  --source-run <T14-실제-복원-실행.json> \
  --target-run <T14-미검증-목적지.json> \
  --private-output <새-비공개-경로>
```

이 CLI는 시험 전용이며 외부 보고서 업로드·운영 승인 API가 아니다. 실행 결과의 서명은
시험에서 생성되므로 원천 자료의 진위를 제3자에게 보증하는 운영 서명으로 사용하면 안 된다.
