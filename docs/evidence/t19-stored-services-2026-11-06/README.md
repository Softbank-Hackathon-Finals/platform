# T19 저장 원문·서명·현재 권한 연결

T10의 원문 저장과 T19의 운영 판정은 별도 조건이다. 기존 시험에서만 구성하던
연결을 선택적 `StoredGateServices`로 제공했다. T10 정본 저장·계획 잠금,
T19 판정·Ed25519 검증·데이터 준비 판정을 그대로 사용한다. 새 수신 서버,
승인 DB, 발급자, 기본 허용 정책은 추가하지 않았다.

## 검증 범위

- 새 연결 시험 42개, 기존 시험을 포함한 control-gate 전체 382개 통과.
- 실제 SQLite 및 별도 로컬 PostgreSQL 17.11의 T10 원문·현재 context·보고서 저장.
- 실제 Ed25519 연산으로 context, 양쪽 원문, 데이터 준비 등록/관측, 보고서 출처 검증.
- 같은 입력·시계의 반복 판정 일치와 보고서 저장 전후 계획 snapshot 유지.
- 서명 누락·변조·다른 context/purpose, 현재 키 폐기·만료, 현재 권한 회수 거부.
- 공급자에 대한 호출 도중 권한 회수와 비밀을 포함한 예상 밖 오류 거부.
- 서명이 올바르더라도 열린 버킷·스키마 불일치·미실행 결과는 BLOCK.
- 기존 실행 승인 경계 유지. 준비 전제조건의 `authorizes_cutover`는 false.
- Ruff, 공개 문서 검사, 구현 소스의 독립 gitleaks 검사 통과.

DB와 서명 구현은 실제 코드이며, 등록 신원·키·통제 관측·T13 값은 합성 시험
자료다. 팀 환경에서 원문을 수신·평가·표시한 운영 인수로 해석하지 않는다.

## 운영에서 연결할 항목

1. T10 담당이 기존 호스트에 준비한 경로로 실제 원문을 같은 계획에 저장하고
   현재 권한으로 재조회한다. 원문 참조·digest·side·건수·기존 기록 보존을 대조한다.
2. 운영 호스트가 T19 context·현재 평가 권한·자격 확인된 원문의 출처를 제공한다.
   등록용 SSO나 원문 저장 권한을 평가·승인·발급 권한으로 변환하지 않는다.
3. 실제 T13 정책·관측 원문을 제공한다. 없으면 실패를 유지하고 허위 준비 값을
   만들지 않는다. 평가 출력은 실제 호스트의 등록된 issuer가 인증한다.
4. T21 저장 보고서 공급자가 같은 계획·현재 권한·보고서 출처로 읽고 표시한다.
5. T22 실제 앱과 통합한다. 화면 표시 성공을 컷오버·무중단·모든 통제 PASS로
   해석하지 않으며 남은 UNKNOWN을 그대로 보존한다.

어댑터의 생성자에는 기본 허용 콜백이 없다. 저장 행만으로 PASS를 만들거나
실환경 접점을 기다리는 동안 별도 T10 서버를 배포하지 않는다. 운영 키나 권한을
임의로 등록하지 않았으며, 기존 실제 T14 인계 원문도 변경하지 않았다.

소스 결속은 [source-manifest.json](source-manifest.json)에 있다.
