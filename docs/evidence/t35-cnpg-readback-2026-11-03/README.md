# T35 CNPG 완료 상태와 요청 결속 검증

2026-11-03의 **로컬 전용 kind 실제 시험**이다. 팀 AWS/RKE2 적용이나 전체 DR-01.1
통과 기록이 아니다. 기존 CNPG 1.30.1, Barman Cloud plugin 0.15.1, PostgreSQL 18.4,
SeaweedFS 4.52 TLS 저장소를 사용했다.

## 수행

1. 백업 전 인증된 API에서 Cluster/ObjectStore UID·generation·spec 지문을 보존했다.
2. 고유 이름으로 백업 하나를 생성하고 create 응답의 UID와 요청 시각을 보존했다.
3. 컨트롤러 완료 후 새 읽기 검증기로 3개 자원을 각각 두 번 조회했다.
4. 동일 등록의 완료 영수증 생성 및 원본 UID·백업 UID·archive 지문 불일치 거부를 확인했다.
5. 최종 코드에서 같은 백업을 다시 읽어 Backup spec generation까지 재검증했다.

결과는 [results.json](results.json)에 있다. 실제 자원명·UID·endpoint·자격증명·API 원문은
공개하지 않는다. 도구 예외와 초기 로컬 테스트 작성 오류는 개발 기록에 남겼으며,
그 실행을 통과 수치로 포함하지 않았다.

## 판정 한계

- `completed`는 컨트롤러의 완료 상태다. 이번 실행은 새 클러스터 복원이나 DB 행 조회를
  추가 수행하지 않았다. 이전 [실제 복원 검증](../../controls/backup-restore.md)과 구분한다.
- 잘못된 UID·지문 시험은 신뢰된 호출 경계에 잘못된 등록을 넣었을 때의 거부 시험이다.
  실제 공격자가 Kubernetes 관리자 권한을 가진 상황을 차단했다는 증거가 아니다.
- 로컬 운영자 클라이언트로 읽었으며 최소 권한 서비스 계정 배치 시험은 별도다.
- 전후 조회는 동시 변경에 대한 완전한 원자적 스냅샷을 제공하지 않는다.
- 원장 승인·영수증 서명·백업 파일 무결성·보존 정책·WAL 누락·재해 복구 SLA는 후속 검증이다.
