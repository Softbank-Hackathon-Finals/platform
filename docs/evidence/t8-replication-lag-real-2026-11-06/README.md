# T8 실제 경로 복제 지연 — 2026-11-06

**실제 경로에서 정방향 복제 지연은 중앙값 67.7ms, p95 70.9ms다.** 출발지 EKS → Tailscale DERP 중계(도쿄) → 목적지 VM 경로이며, tailnet 왕복 시간(67~107ms, [T30 실측](../t30-tailnet-path-2026-11-06/README.md))과 거의 같다. 목적지 디스크 기록(flush)까지는 중앙값 268ms다. 20번 모두 밀린 WAL은 0바이트였다.

설계 5.3의 데이터 크기 기준(업무 표 합계 10만 행, 200MB 이하)은 [11/4 로컬 측정](../t8-replication-lag-2026-11-04/README.md)대로 유지를 추천한다. 실제 지연이 그때 가정한 범위 안이기 때문이다. 부하가 걸린 상태의 처리량은 재지 않았다.

## 방법

- 시각: 2026-11-06 10:28:28~10:28:57 KST.
- 출발지 `cutover.barrier`에 측정용 행 20개를 1.5초 간격으로 넣었다. 이 표는 컷오버 실행기와 재개 도구가 시험 행을 넣고 지우는 용도의 표이고, 측정 전에는 양쪽 모두 0행이었다.
- 행을 넣을 때마다 출발지에서 정방향 walsender의 `pg_stat_replication`(`write_lag`, `flush_lag`, `replay_lag`, 남은 WAL)을 읽었다. 출발지 시계 하나로 계산된 값이라 두 DB 사이 시계 차이가 들어가지 않는다.
- 끝난 뒤 넣은 행을 출발지에서 지웠다. 목적지에서 20행 도착을 확인했고, 정리 뒤 양쪽 모두 0행이었다.
- 업무 테이블(`messages`, `attachments`) · 앱 · 구독 설정은 건드리지 않았다. 앱 쓰기는 양쪽 모두 차단된 상태였다.
- 당시 설정: 양쪽 `wal_sender_timeout` · `wal_receiver_timeout` 30초(#382, #401), 정방향 `disable_on_error=false`, 목적지 노드 arm64.

## 결과

원값은 [results.json](results.json)에 있다.

| 지표 | 최소 | 중앙값 | p95 | 최대 |
| --- | ---: | ---: | ---: | ---: |
| `write_lag` (목적지가 받음) | 65.3ms | 67.7ms | 70.9ms | 71.4ms |
| `replay_lag` (목적지가 적용) | 65.3ms | 67.7ms | 70.9ms | 71.4ms |
| `flush_lag` (목적지 디스크 기록) | 265.7ms | 268.0ms | 270.0ms | 271.3ms |
| 남은 WAL | 0B | 0B | 0B | 0B |

- `flush_lag`가 약 200ms 더 긴 것은 구독 쪽 커밋이 비동기(`synchronous_commit` 기본 off)라 디스크 기록이 WAL writer 주기(기본 200ms)를 따르기 때문으로 본다(추정).
- 컷오버 실행기는 LSN이 아니라 barrier 행 도착을 50ms 간격으로 확인한다. 실제 도착이 70ms 안팎이므로 barrier 대기는 약 120ms다. 11/4 로컬 표의 평상시 최악값(172ms)보다 짧다.

## 5.3 재검토

11/4 기록은 기준을 유지하려면 세 가지를 확인해야 한다고 적었다. 이번에 그중 2번의 지연 부분을 실제 경로로 쟀다.

| 조건 (11/4) | 지금 |
| --- | --- |
| 1. T13 DB 안 비교(`db-sql-v1`)가 실행기에 연결 | 이 기록의 범위 밖 |
| 2. 실제 경로를 다시 잴 것 | **평상 지연은 실측 완료(중앙값 67.7ms).** 대역폭과 부하 상태 처리량은 재지 않았다 |
| 3. 비교 시간을 실제 경로로 다시 잴 것 | 이 기록의 범위 밖 |

평상 지연이 가정 범위 안이고 경로가 중계를 거쳐도 남은 WAL이 쌓이지 않아서, 기준을 바꿀 근거는 없다. 크기를 늘리는 것도 추천하지 않는다(11/4와 같은 이유).

## 재지 않은 것

- 부하가 걸린 상태의 지연과 처리량. 앱 쓰기가 막혀 있어 업무 행 쓰기로 재지 않았다.
- 역방향(컷오버 뒤) 지연.
- 행 하나가 1.5초 간격으로 들어간 조건이라, 한꺼번에 몰린 쓰기의 따라잡기 시간은 이 값으로 대신할 수 없다.
