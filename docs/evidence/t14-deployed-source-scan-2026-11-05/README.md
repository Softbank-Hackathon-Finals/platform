# T14 실제 출발지 앱 소스·렌더 설정의 비밀 탐지

**배포 이미지의 제한된 소스 진단이며 운영 게이트 자격은 없다.** T5 SEC-01.2는 등록된
앱 저장소와 렌더 설정의 검사를 요구한다. 이번 실행은 이미지 안의 앱 텍스트 14개만 읽었고
저장소의 빌드·CI·기타 파일을 포함한 전체 승인 범위와 Git revision은 확인하지 않았다.
원문 PASS는 이 제한 범위의 탐지 결과로 보존하며 T14/T19 운영 PASS로 등록하지 않는다.
실제 등록 revision의 승인된 저장소 범위를 검사하는 새 실행이 필요하다.

11월 5일 **19:56:41–19:56:54 KST**, 등록된 출발지 앱의 읽기 전용 이미지에서
앱 텍스트 파일 14개(109,962 bytes)와 현재 Deployment spec을 수집해
기존 `GitleaksProbe`로 검사했다. 이 범위의 원문 출력은 PASS이며 발견 건수는 두 입력 모두 0이다.

- [새 실행 원문](control-run.json): `a5fcd61b-9ac4-46fb-99cb-5aa20362956a`
- [스캐너 증거](evidence.json), [범위·결과 요약](summary.json), [실행 패키지 소스](source-manifest.json)
- Gitleaks 8.30.1 배포 archive 체크섬과 바이너리 일치 확인
- 고정 기본 규칙, 빈 ignore, 앱 allow 주석 무시, 보고서 redact 적용
- 소스와 렌더 설정을 각각 검사하고 입력·도구·설정의 지문을 증거에 결속
- 실제 앱·Pod·배포 이미지·접속 등록 정보를 전후 두 번 대조하고 앱 파일도 재조회해 동일성 확인
- 증거를 호스트에 저장·fsync한 뒤 결과 확정. 공개 증거에는 경로·내용·비밀 원문 없음
- DB 연결·Secret 값 조회·앱 코드 실행·설정 변경·모델 전송 없음. 전용 SSM 연결은 종료

## 범위 제한

검사 대상은 이미지의 앱 텍스트 소스와 Secret 참조가 포함된 렌더 Deployment spec이다.
`__pycache__`, 가상환경·설치 의존 패키지, 이미지 전체, Git 이력, 실행 중 환경변수·메모리와
실제 Secret 본문을 검사한 결과가 아니다. 탐지 0건은 비밀값이 전혀 없다는 보증이 아니다.
앱 데이터나 자격증명을 스캐너 프로세스 환경으로 전달하지 않았다.

첫 수집에서는 이미지에 없는 빌드 파일을 기대해 스캔 전에 중단했고
`UNKNOWN/TOOL_ERROR` 실행을 따로 보존했다. 실제 이미지의 앱 소스 범위를 확인한 뒤
새 실행 ID로 재수집했다. 이전 실행의 결과를 수정하거나 실패를 PASS로 덮어쓰지 않았다.
원문·등록 readback·수집 스크립트는 접근 제한된 비공개 경로에 보존했다.

이 실행의 다른 19개 통제는 `UNKNOWN/NOT_RUN`이다. 앞선 TLS·객체 접근 실행과
합쳐 동일 실행의 PASS를 만들지 않았다. 환경은 운영자가 대조한 출발지이며
T10 운영 계획의 생산자 등록이나 실제 목적지 인수를 대신하지 않는다.
T14 전체 완료, 양쪽 동등성, 컷오버 승인 및 규정 준수를 표시하지 않는다.
