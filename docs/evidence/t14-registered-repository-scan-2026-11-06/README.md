2026-11-06 KST에 실제 팀 AWS 출발지에서 SEC-01.2를 새로 실행했다.
등록된 demo-chat 커밋 `66e7419f404f4ec4addc71014aabfcdd44f34688`의
**전체 Git 파일 66개**와 실제 Deployment·Pod 설정 2개를 Gitleaks 8.30.1로 검사했다.
두 입력 모두 발견 0건으로 이 시험은 PASS다.

이전 [배포 앱 파일 일부의 진단](../t14-deployed-source-scan-2026-11-05/README.md)은
저장소 전체와 Git revision을 확인하지 못해 운영 게이트 자격이 없었다. 이번 결과는
그 원문을 수정한 것이 아니라, 등록 workload/source ID로 만든 별도 실행이다.

## 범위와 실제 대조

- 등록 영수증의 저장소·커밋·앱 경로와 IaC 경로를 확인했다. Git 객체에서 모든 추적 파일을
  꺼냈으며 checkout hook·필터·앱 코드·앱의 스캐너 설정을 실행하지 않았다.
- 현재 앱의 Ready 상태, 이미지, 서비스 계정, ReplicaSet 지문을 등록 범위와 대조했다.
  실행 중인 앱 파일 14개의 SHA-256을 등록 커밋의 앱 파일 전체와 대조하고 전후 동일함을 확인했다.
- 전체 66개에는 빌드·CI·문서·테스트·lock 파일이 포함된다. 미지원 파일을 임의로 제외하지 않았다.
- 실제 Deployment·Pod spec을 각각 검사했다. ConfigMap 참조는 없었다. Secret은 참조만
  포함하며 Secret 본문, 실행 중 환경변수, 메모리는 읽지 않았다.
- 스캐너 archive의 고정 체크섬과 바이너리 일치를 확인하고 기본 규칙·빈 ignore를 사용했다.
  앱의 allow 주석은 무시했다. 소스와 렌더 설정의 지문은 수집 증거에 각각 연결했다.
- 실제 배포 등록과 앱 파일을 다시 읽어 변경이 없음을 확인했다. DB 연결·업무 쓰기·설정 변경은
  없었다. 이 시험의 SSM 세션과 로컬 리스너는 종료했다.

## 결과와 인수 경계

[summary.json](summary.json)에 원문 바이트 해시·검사 범위·시각을 기록했다.
원문과 등록 대조 기록은 비공개로 보존했으며, 공개 요약은 원문이나 서명·승인 권한이 아니다.
[source-manifest.json](source-manifest.json)은 제품 소스를,
[collector-manifest.json](collector-manifest.json)은 비공개 운영 수집 스크립트의 지문을 고정한다.

원문은 T14 Catalog와 T19 T5Contract 형식 검사를 통과했다. 실행 ID·등록 앱·환경·시험·증거
해시를 대조했다. **full 프로필의 다른 19개 행은 UNKNOWN/NOT_RUN**이며 이전의 TLS·S3
실행과 합쳐 전체 PASS로 만들지 않았다.

신뢰된 생산자의 T10 저장과 새 계획의 프로필 결속, 증거 유효기간 검증, 실제 목적지 검사 및
T19 최종 판정은 남아 있다. 따라서 이번 수집을 컷오버 승인이나 양쪽 통제 완료로 사용하지 않는다.
탐지 0건은 비밀이 전혀 없다는 보증이 아니며, Git 이력·의존 패키지·이미지 전체 검사는 포함하지 않는다.
