# T33 보안 경계와 운영 인수 조건

이 문서는 탐지 통합 서비스의 `normalizer_version=2` 계약이다. T33은 출처가 보고한 탐지 결과와 수집 상태를 제공한다. **T19의 이전 승인이나 통제 시험 합격을 대신 판정하지 않는다.** 정상 수집(`OK`)은 안전성 합격이 아니다.

## 1. 위협과 보호 목표

| 위협 | 구현한 거부·보존 조건 |
|---|---|
| 미인증 조회, 다른 환경의 기록 조회 | 모든 데이터 API 인증, 요청마다 환경 범위 확인, SQL 페이지 처리 전에 범위 제한 |
| 수집기 자격으로 콘솔 조회·다른 출처 위조 | `read` / `ingest` 분리, 수집 출처·환경의 정확한 일치 |
| 회수·만료된 자격 재사용 | 매 요청 파일 재조회, `not_before <= now < expires_at`, `revoked`, 최대 24시간 |
| 실패 이벤트 누락 후 정상 표시 | 유효 이벤트와 실패 기록을 함께 보존, `INGESTION_GAP`, heartbeat로 해제하지 않음 |
| 과거 PASS 재전송 | 출처 시각이 과거면 현재 상태 유지, 같은 시각의 다른 내용은 격리·보류 |
| 비밀이 포함된 이벤트·오류 | 출처별 허용 필드만 저장, 자유 서술·명령행·excerpt 제외, 값이 포함된 예외 출력 금지 |
| 수집 중단을 문제 해결로 오인 | Falco 침묵 기반 해결 금지, 종전 API는 인증 후 410 |
| 부분 저장·동시 갱신 | 결과·격리·출처 상태·커서·접수 감사의 단일 SQLite 트랜잭션, 출처 시각 비교 |
| 큰 요청·복잡한 JSON | 본문 1 MiB, 전체 수신 10초, 깊이 32, 노드 50,000, 이벤트 최대 1,000개 |

## 2. 신원·권한 계약

### 서비스 인증

브라우저는 T10 플랫폼 API에 로그인한다. T10은 사용자·조직·환경 소유권을 확인하고 **서버에서만** T33을 호출한다. 수집기는 자기 환경·출처의 `ingest` 자격만 가진다. 아래 자격은 사용자 로그인, MFA 또는 직무 분리 구현이 아니다. T10 발급·회수 자동화는 별도 통합 인수 대상이다.

```text
사용자 → T10 로그인·소유권 확인 → 범위 제한 read 자격 → T33 조회
수집기 → 환경·출처 제한 ingest 자격 → T33 수집
                   ↓
     허용된 환경 범위 + 짧은 유효기간 + 감사기록
```

운영 시 `BRAVO_FINDINGS_AUTH_FILE`로 버전 1 자격 레지스트리 경로를 지정한다. 저장하는 것은 높은 엔트로피 토큰의 SHA-256이다. 토큰 원문을 브라우저, 저장소, URL, 로그에 넣지 않는다. 발급자는 CSPRNG로 최소 32바이트 무작위 값을 생성한다. 문자열 길이 검사는 엔트로피의 증명이 아니다.

레지스트리 구조:

```json
{
  "version": 1,
  "credentials": [{
    "credential_id": "collector-onprem-20261103",
    "subject": "collector-onprem",
    "token_sha256": "<64자리 소문자 SHA-256>",
    "environments": ["organization-id:environment-id"],
    "permissions": ["ingest"],
    "sources": ["falco", "kyverno"],
    "not_before": 0,
    "expires_at": 1,
    "revoked": false
  }]
}
```

예시는 배포 가능한 자격이 아니다. 시각은 UTC epoch milliseconds이며 실제 발급 시각으로 채운다. 조회 자격은 `permissions: ["read"]`, `sources: []`로 별도 발급한다.

- `environment_id`는 조직 간 재사용하지 않는 전역 식별자여야 한다. 조직·환경 매핑의 정본은 T10이다. 요청 헤더의 임의 조직 ID를 신뢰하지 않는다.
- wildcard, 알 수 없는 권한·출처, 중복 자격 ID·토큰 해시, 24시간 초과 유효기간을 거부한다.
- 파일은 root 또는 서비스 UID가 소유한 일반 파일이며 그룹·타인 권한이 없어야 한다(0400 또는 0600). 심볼릭 링크를 따라가지 않는다. Kubernetes Secret 볼륨의 링크를 그대로 지정하지 말고, 제한된 init/provisioning 경로에서 일반 파일로 전달해야 한다.
- 레지스트리는 매 요청 다시 읽는다. 원자적 파일 교체로 회전·회수한다. 읽기 실패·손상은 503, 자격 없음·만료·회수는 401, 유효 자격의 범위 초과는 403이다.
- 파일 회수는 이미 완료된 요청을 취소하지 않는다. 수집 반영 시 DB 잠금 획득 후 다시 검사하지만 외부 파일 변경과 DB 커밋 사이의 원자성까지 제공하지 않는다. 금융 운영에서는 T10의 권한 버전·실행권 fencing 통합 시험이 필요하다.
- 기존 `BRAVO_INGEST_TOKENS`는 시작 오류로 처리한다. 암묵적 호환으로 광범위 자격을 유지하지 않는다.
- TLS/mTLS, 네트워크 접근 제한, 연결 수·요청률 제한은 배치 환경에서 강제한다. Tailscale 연결만으로 사용자 권한이 생기지 않는다.

## 3. 실패·재전송·동시성 계약

1. 형식이 잘못됐거나 환경이 다르거나 시각이 유효하지 않은 이벤트는 실패 이유 코드만 격리 기록으로 남긴다. 오류 메시지·원본은 저장하지 않는다.
2. 같은 묶음의 정상 이벤트는 저장할 수 있지만 전체 출처는 `FAILED/INGESTION_GAP`, 화면은 `UNKNOWN`이다. 정상 결과가 일부 보인다고 전체 검증이 끝난 것이 아니다.
3. 빈 heartbeat 또는 다음 정상 이벤트는 격리 이력을 지우지 않는다. Pull 커서는 전진하지 않는다.
4. 출처 갱신 시각이 과거인 이벤트는 `stale`, 같은 시각·같은 의미는 `duplicate`다. 같은 시각에 다른 판정·대상·심각도가 들어오면 격리한다. 단순 수신 순서로 PASS를 택하지 않는다.
5. 미래 시각은 수집기 시각 대비 5분까지만 허용한다. timezone 없는 문자열, bool, 음수·비유한 숫자를 거부한다. 실제 운영에서는 NTP와 시계 오차 감시가 필요하다.
6. 정상 처리·저장 장애·프로세스 재시작에 대해 커서와 성공 상태가 데이터보다 앞서지 않아야 한다. 접수 감사 저장 실패도 503이며 해당 트랜잭션 전체를 롤백한다.
7. 첫 Pull 조회는 이전의 7일 제한 대신 전체 보존 범위를 조회한다. 증분은 5분을 겹쳐 읽는다. 묶음 10,000개 초과는 실패로 처리한다. 5분보다 늦게 나타나는 이벤트의 보장은 정기 전체 재대조와 출처별 전달 계약을 추가 검증해야 한다.

**격리 보류 해제는 아직 일반 API로 제공하지 않는다.** 현재 T10/T19와 검증된 복구 승인 계약이 없으므로, 임의 버튼이나 heartbeat로 오류 이력을 없애지 않는다. 운영 인수 전 다음 절차를 자동화해야 한다.

- 원본 제공자의 보존된 기록과 격리 발생 구간을 조사한다. T33은 민감 원문을 보관하지 않으므로 재처리 입력의 정본은 출처다.
- 누락·충돌 원인을 수정하고 승인된 전체 재수집 범위·데이터 및 기존 미해결 탐지 보존 계획을 확정한다.
- 격리 이력의 revision과 승인·증거를 결속해 완전성을 검증한다. 다른 이벤트가 추가되면 승인·검증을 다시 수행한다.
- T10/T19가 검증한 복구 결과로만 보류를 해제하고 전후 이력을 남긴다. `DELETE quarantine`, 시간 경과, 데이터베이스 초기화로 대신하지 않는다.

이 운영 복구 경로가 연결되기 전까지 격리 발생 환경은 자동 이전 승인 근거로 사용할 수 없다.

## 4. 데이터 최소화와 감사

`source_projection()`은 정규화에 필요한 출처별 필드만 남긴다. Falco `output`, `proc.cmdline`, Kyverno `message`, T5 evidence `excerpt`, 임의 확장 필드는 보관하지 않는다. 인증 헤더·토큰·비밀번호·개인 키 등 알려진 패턴은 추가 마스킹한다.

- `raw` 테이블은 이름을 유지하지만 **최소화·마스킹된 출처 투영본**만 저장한다. `raw_sha256`도 그 투영본의 정규 JSON 해시이며 원문 보존·서명·출처 진위를 증명하지 않는다.
- 탐지 UID는 마스킹 전 출처·환경·원본 ID를 해시한다. 서로 다른 계정의 표시값이 같아져도 탐지가 합쳐지지 않는다.
- 허용된 제목·자원 식별자에 임의로 들어간 모든 비밀을 패턴으로 찾아낼 수는 없다. 수집기 필드 정책, 실데이터 DLP 검증과 UI 출력 이스케이프가 추가로 필요하다.
- 요청 감사에는 생성한 request ID, 주체, 작업, 결과 코드, 승인된 환경·출처만 남긴다. 요청 본문·헤더·임의 URL·검증 오류의 input은 기록하지 않는다.
- SQLite 감사는 로컬 운영 기록이다. DB 관리자에 대한 변조 방지나 독립 감사 저장소를 의미하지 않는다. T24의 별도 권한·불변 보관·보존 기간·위변조 경보가 운영 인수 조건이다.

## 5. Falco 종료와 화면 계약

Falco는 탐지 발생 이벤트이며 정상화 증거를 보내는 서비스가 아니다. 24시간 새 이벤트가 없다는 이유로 `Resolved`로 바꾸지 않는다. `resolve-silent`는 미인증 401, 인증된 조회 주체에 410을 반환하며 내부 메서드도 변경 없이 실패한다.

실제 해결 처리는 향후 사고 관리에서 조치·재검증·승인·대상 결속을 확인한 뒤 별도 상태로 제공한다. 그 전까지 탐지는 미해결로 남는다. 다른 출처의 최신 명시적 PASS/Resolved는 출처 주장으로 표시하며 T19의 독립 합격 결과로 사용하지 않는다.

## 6. 배포·업그레이드

- 서버 기본 메모리 DB를 금지한다. `BRAVO_FINDINGS_DB`에 영속 경로를 지정해야 한다. 신규 DB는 0600으로 만들며 그룹·타인 접근 권한, 비정규 파일, 심볼릭 링크를 거부한다. 부모 디렉터리도 서비스 관리 경계 안에서 보호해야 한다.
- 과거 스키마의 데이터가 있으면 시작을 거부한다. 자동 삭제·묵시적 변환을 하지 않는다. 기존 데이터에는 이미 저장된 비밀과 잘못 해결된 탐지가 있을 수 있다.
- 변경 전 DB를 제한된 접근 권한으로 보존하고, 출처 정본에서 미해결 결과를 재대조한다. 검사한 새 저장소와 원래 이력을 모두 보존한 상태에서 승인된 교체를 수행해야 한다. 이전 DB를 그대로 새 파일명으로 복사하거나 버전 표식만 추가해서 우회하면 안 된다.
- `normalizer_version=2`와 새 UID 계약은 소비자 T21에서 수용해야 한다. 이전 UID와 새 UID를 같은 항목으로 임의 병합하지 않는다.
- SQLite는 단일 인스턴스 로컬 저장 어댑터다. 다중 노드 HA·RLS·백업/PITR·스토리지 암호화 완료를 의미하지 않는다.

## 7. 실제 운영 활성화 전 필수 시험

| 검증 | 인수 증거 |
|---|---|
| T10 신원·조직·소유권·발급·회수 | 조직 A 자격으로 B의 목록·요약·수집 거부, 권한 회수 후 모든 인스턴스 거부 |
| TLS/mTLS·망 접근 | 평문·미신뢰 인증서·허용되지 않은 네트워크 차단 |
| 실출처 수집 | AWS/Kyverno/Falco 실데이터, SCC API 필터·등급·완전성 확인 |
| 장애와 누락 복구 | 부분 페이지, 저장 공간 고갈, 재시작, 지연 도착, 격리 재처리·승인 검증 |
| 감사·원문 보호 | 별도 불변 감사 저장소, 실제 민감정보 입력 시험, 접근·보존·폐기 검증 |
| 가용성·용량 | 요청률 제한, 10,000개 이상 backlog 복구, 보관량 경보, HA DB/재해 복구 |
| 의미 판정 통합 | T33 수집 OK를 T5/T19의 PASS로 오인하지 않음, UNKNOWN·보류 전파 |

이 문서는 위 경계를 정의하고 로컬 회귀 시험을 제공한다. 금융 규정 준수 완료, 운영 인증, 실제 클라우드 검증 완료를 주장하지 않는다. 규제 조항의 공식 매핑은 T23에서 수행한다.
