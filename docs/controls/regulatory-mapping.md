# 6개 통제의 일본·한국 원문 대응표 (T23)

확인일: 2026-11-03. 목적은 [T5 시험 계약](README.md)의 근거와 한계를 조항 단위로 설명하는 것이다. **원문 확인 완료는 규제 준수 완료가 아니다.** 아래 연결은 팀의 기술적 대응 해석이며, 감독기관의 인증·승인이나 기관별 법률 적용 판단을 대신하지 않는다. 규제 문구를 런타임 게이트 입력으로 받아 PASS로 바꾸지 않는다.

금융청 문서는 `기본적 대응사항`과 `대응이 바람직한 사항`을 구별한다. 특히 **출구전략과 대체 수단 정기 시험은 2.6 d의 바람직한 사항**이다. 이를 법률상 일률적 의무로 표현하지 않는다. 2025년 개정 공표는 NISC 조직 개편에 따른 기술적 수정을 설명한다. T5에서 참고한 2024년 원문과 이번 현재 링크를 구별한다.

한국 별표7은 일반 서버 보안 기준 전체가 아니라 **망분리 예외에 적용하는 대체 통제**다. 현행 시행세칙 제2조의3 제3항의 자체 위험성 평가·통제 적용·정보보호위원회 승인이 전제다. 제4항의 반기 평가는 같은 조 제1항 제3호의 내부 업무망 SaaS 경우에 관한 것이며 모든 이전에 일반화하지 않는다. 과거 자료의 `제2조의2(망분리 적용 예외)`는 현재 **제2조의3**이다.

감독규정 별표2의3·2의4도 중요업무와 비중요업무에 따라 필수·추가 사항 적용이 다르다. 목적지가 온프렘이라는 이유만으로 클라우드 이용 조항의 적용·비적용을 자동 판정하지 않는다.

## 3. 별표7 적용 범위를 잃지 않는 방법

- **내부 업무망 SaaS**: 현재 조문은 고유식별정보·개인신용정보를 처리하지 않는 경우의 예외를 다룬다. 실제 금융 상담 데이터가 있다는 이유로 이 예외가 당연히 적용된다고 설명하지 않는다. 모의 채팅 앱의 합성 데이터와 고객 운영 데이터는 다르다.
- **연구·개발**: 독립망, 중요정보 처리 모니터링, 외부 반출 관리까지 포함한다. 리허설 namespace의 기본 거부 정책은 그 일부 시험 자료다.
- **원격접속**: 단말기 보호·인증·회선·유휴시간·접속자 관리까지 포함한다. DB TLS 성공을 원격접속 대책 전체로 표시하지 않는다.
- **업무용 단말기**: 사용자의 관리자 권한 제거·프로그램 통제·저장 암호화는 사람의 단말기 통제다. 컨테이너 비루트 실행과 동일 조치로 취급하지 않는다.
- **공통·메일 시스템**: 악성코드 및 정보유출 대응도 있다. 현재 여섯 통제의 시험만으로 이 항목들을 모두 시험했다고 하지 않는다.

## 4. 게이트·감사에서의 사용

1. 고객 기관이 관할·업무 종류·데이터·적용 예외를 정하고 책임자가 적용성을 검토한다. 이 문서는 자동 법률 판단기가 아니다.
2. 시험 대상과 프로필·방법 버전을 고정하고, 원본/목적지 결과를 T14가 수집한다.
3. T19는 기존 T5 규칙으로 시험 증거와 승인 유효성을 검사한다. 규제 링크가 있다고 미수집·만료 증거를 통과시키지 않는다.
4. 보고서에는 **조항 원문 확인 / 시험 수행 / 특정 통제 결과 / 운영·규제 적합성 검토**를 분리한다. 기술 시험 예외 승인은 법적 의무의 면제나 금융기관 정보보호위원회 승인이 아니다.
5. 원문이 개정되면 출처 버전과 적용성 해석을 재검토한다. 이 표를 고쳤다는 이유로 시험 계약·운영 허용 범위를 자동 변경하지 않는다.

CIS는 별도 벤치마크 버전과 환경별 적용성이 필요하다. 이번 T23은 일본·한국 원문 확인이며, 기존 설계표의 포괄적인 CIS 범주를 번호가 검증된 CIS 통제로 격상하지 않는다.
