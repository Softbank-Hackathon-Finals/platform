# 개발 리전과 향후 일본 배치의 경계

상태: **T1 인프라 검토 제안**. 현재 개발 환경의 관측과 향후 결정할 항목을 분리한다. 이 문서만으로 일본 배치, 법률 적용, 팀의 새 아키텍처 합의 또는 지역 통제 구현을 확정하지 않는다. 정본 설계·태스크·통제 시험의 의미를 바꾸는 채택은 담당자 검토와 별도 변경으로 다룬다.

## 현재 서울 개발 환경

2026-11-04 KST 운영자 확인 기준이다. 사용자는 현재 개발 환경의 **서울 단일 리전 SSO**와 운영자 로그인 후 요청한 팀원의 개인 접속 준비를 승인했다. 일본의 거버넌스·제약까지 고려한 지역적 일체성은 향후 일본 이전을 가정한 질문이며, 지금의 리소스를 일본으로 이전하라는 결정으로 해석하지 않는다.

| 대상 | 현재 확인한 사실 | 확인 범위와 남은 일 |
|---|---|---|
| 출발지 EKS·플랫폼 EC2/RKE2 | 기존 AWS 실측은 서울 `ap-northeast-2`. 두 IaC의 `region` 기본값도 서울 | IaC 기본값은 모든 실행의 리전을 강제하지 않는다. 온프렘 VM의 물리적 국가나 일본 설치를 증명하지 않는다 |
| Organizations | 사용자 승인 후 생성, 기존 관리 계정 하나만 포함 | 새 멤버 계정 생성·워크로드 이전 없음. 이것만으로 지역 통제 정책이 적용되지는 않는다 |
| Identity Center | 서울 organization instance 하나가 `ACTIVE`, Identity Store 존재 | 활성화 시 단일 서울·AWS 소유 키·AWS 계정 액세스 기능 활성·추가 리전 없음으로 선택. 운영자 개인 신원·사람 전용 개발 관리자 권한 세트·계정 할당 readback 완료. 개인 로그인과 EKS/RKE2 개인 권한은 별도 검증 |
| 사람의 인증 | 기존 개인 IAM 인증으로 기반과 SSO 준비를 수행 | IAM 세션·임시 콘솔 federation·인스턴스 `ACTIVE`는 개인 SSO 성공을 대신하지 않는다. [운영자 검증 절차](operator-sso-verification.md) 적용 |
| 과금 전제 | 변경 전 계정 계획은 `PAID` / `ACTIVE`, 남은 Free Tier 크레딧 없음 | 다른 크레딧·향후 비용 전체를 조사한 결과는 아니다 |

이번 Identity Center 활성화 화면의 최초 표시에는 서울과 미국 오리건을 포함한 다중 리전 구성이 있었다. 운영자는 승인된 **단일 서울**을 명시적으로 선택한 뒤 생성했다. 이는 이번 UI와 선택의 관측이며 모든 계정의 기본값을 뜻하지 않는다. 또한 단일 리전 선택으로 외부 IdP·AI·감사·지원 시스템의 저장·처리 위치까지 검증됐다고 하지 않는다.

운영자 readback 원본은 접근 제한 경로에 보존한다. 공개 문서는 관측 시각·방법·결과와 한계를 제공하며, 계정·인스턴스·디렉터리 식별자, 개인 이메일, 토큰, 콘솔 접속 URL은 싣지 않는다. 생성 성공 이후에도 실제 사용자별 로그인, 허용·거부 동작과 세션 만료 증거가 필요하다.

일본 서사와 규제 대응의 반영을 일본 내 데이터 저장·처리의 검증으로 확대하지 않는다. 반대로 레지던시 문제가 전혀 제기되지 않았다고도 하지 않는다. **문제와 차단 원칙은 논의됐고, 구체적인 지역 값과 서비스 전체 범위·예외·실측 계약은 남아 있다.**

## 일본 프로필 채택 전에 정할 계약 — 제안

여기서 프로필은 배치 조건을 묶어 검토하는 문서상의 이름이다. 실행 코드나 현재 게이트에 이미 존재하는 기능이 아니다. 각 행의 값·책임자·승인 버전·증거가 채워지고 관련 담당자가 검토하기 전에는 일본 지역 요건을 충족했다고 표시하지 않는다. 국가와 리전만 같다고 모든 데이터 처리 조건이 같아지는 것으로 간주하지 않는다.

| 경계 | 채택 전에 정할 값 | 필요한 실측·검토 근거 |
|---|---|---|
| 적용 범위·데이터 분류 | 개발/시연/운영, 적용 기관·관할 검토 주체, 합성/개인/신용/운영 데이터, 허용 국가·리전 | 데이터 목록과 분류 승인, 대상 환경·계획 버전 결속. 법률 적용 판단은 해당 책임자가 별도 검토 |
| 출발지·목적지·플랫폼 | 각 AWS 리전, 온프렘 물리적 위치, 제어·데이터 경로, 허용 대체 위치 | 실제 리소스 리전·호스트 위치의 신뢰 가능한 근거, 계획과 readback 대조. VM 이름이나 클라우드 기본값으로 위치를 추정하지 않음 |
| DB·첨부·복제 | 주 데이터·임시 사본·복제·재전송·복귀 경로의 저장/처리 위치와 종료 후 삭제 | 실제 endpoint·복제 대상·버킷·볼륨 설정, 경로별 허용/거부 시험, 복제·failback 중 범위 재검증 |
| 백업·재해 복구 | 백업·스냅샷·소산·복원 위치, 보존 기간, 삭제 권한, 장애 시 예외 | 실제 백업 목적지·복제 설정, 지정 위치에서 복원, 금지 위치·삭제 권한 거부. 기존 복원 시험 결과와 지역 검증을 구별 |
| 로그·감사·지표 | 환경 내부 로그, 중앙 감사, 플랫폼 지표, 추적·증거의 보관/처리 위치와 민감정보 범위 | 수집기와 저장소 설정, 전송 대상, 보존·삭제, 민감정보 제외와 차단 대조군. 환경 안의 저장과 일본 안의 저장을 구별 |
| KMS·비밀·인증서 | 키·비밀 저장 위치, 복제 여부, 소유/운영 권한, 회전·폐기, 복구 키 | 실제 키 종류·리전·복제·정책과 암복호화/거부 시험. AWS 소유 키 선택 하나로 다른 저장소 키까지 검증하지 않음 |
| Identity Center·IdP | 주리전·추가 리전, 디렉터리·외부 IdP, 개인 정보·인증/감사 데이터 범위, 장애·변경 절차 | 인스턴스 유형·리전·복제 설정, IdP의 처리 조건, 개인별 로그인·만료·회수와 EKS/RKE2 허용/거부 증거 |
| AI·외부 서비스 | 모델/구독·호출 경로, 프롬프트·첨부·응답·로그의 저장/처리/보존 조건, CI·이미지 저장소·네트워크/Edge·지원 도구 | 선택한 서비스·계약·설정의 근거와 실제 전송 대상, 허용/차단 대조군. 관측한 endpoint만으로 사업자 내부 처리 위치를 단정하지 않음 |
| 예외·변경 | 허용할 예외, 승인자, 이유, 범위, 만료, 리전/공급자 변경 시 재검토와 비상 복구 | 예외와 계획/정책 버전의 결속, 만료·범위 밖·승인 후 변경 거부 시험. 미결정 예외를 자동 허용하지 않음 |
| 증거·완료 판정 | 관측 시각, 대상·설정·정책 버전, 책임자, 재검증 조건, 공개 가림 기준 | 원본 readback과 공개본의 연결, 긍정/부정 시험, 미관측·만료·오류 구분. 문서 작성/PR 병합을 실제 지역 준수 완료로 올리지 않음 |

현재 서울 개발을 계속하는 것과 일본 프로필을 채택하는 것은 별도 변경이다. 일본 이전을 선택한다면 기존 계정·SSO·키·데이터·백업을 즉시 이동하거나 복제한다고 가정하지 않고, 위 계약과 서비스별 변경 가능성·영향을 먼저 검토한다. 채택된 아키텍처 의미는 T29 절차에 따라 설계/ADR에 반영하고, 필요한 구현·완료 기준은 관련 태스크 담당과 조율한다.

## 조회 범위와 한계

정본 조회는 설계·태스크, 템플릿을 제외한 ADR 13개, T23 대응표, SSO 절차, 출발지·플랫폼 리전 변수 파일 19개다. Slack은 채널 생성일 10/30부터 11/4 01:24 KST까지 top-level 134개와 SSO·설계·11/3 회의의 전체 스레드를 읽었다. Notion은 11/1·11/2 회의록, 보안 제안의 개요·아키텍처·정책·이전·감사 절, 별도 설계 추가 제안을 읽었다.

모든 Slack 답글·허들·Notion 문서를 전수 조회한 것은 아니다. 검색은 실제 존재하는 SSO 원문도 0건으로 반환해 합의 부재의 근거에서 제외했다. 위 범위에서 구체적인 일본 배치 계약을 찾지 못했다는 결과이며, 팀의 모든 대화에 그런 결정이 없었다는 단정이 아니다. 이 문서는 새로운 규제 해석이나 전체 운영 적합성 감사가 아니다.
