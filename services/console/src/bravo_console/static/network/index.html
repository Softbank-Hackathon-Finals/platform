주소가 바뀌는 지점까지.

미확인을 숨기지 않습니다.

Target 호스트의 NAT 규칙·카운터와 프록시별 전송 경로를 별도로 표시합니다. 규칙은 변환 설정이며, 카운터는 해당 규칙의 누적 일치 수입니다. 조회 실패는 UNKNOWN으로 남습니다. 가정용 라우터의 NAT 설정과 ISP CGNAT는 아직 직접 조회하지 않았습니다. 100.64.0.0/10의 Tailscale 주소만으로 ISP CGNAT를 판정하지 않습니다. EndpointSlice Ready는 애플리케이션 트랜잭션 성공을 뜻하지 않습니다.

WireGuard & 경로 선택

직접 UDP, 구성된 Peer Relay, DERP relay를 사용할 수 있습니다. 모두 WireGuard로 종단 간 암호화됩니다. 현재 상태에서는 운영자 기기와 워크로드 프록시의 제한된 탐침으로 Direct·DERP를 확인합니다. 데이터 경로 확인과 애플리케이션 요청 성공은 별개입니다.

TLS & Kubernetes identity

워크로드 API는 TLS server name 검증을 유지하고 원래 ServiceAccount Bearer 토큰을 전달합니다. API proxy의 noauth 모드는 Kubernetes 인증·인가를 생략하지 않습니다.

Kubernetes ServiceAccount ↗

DNS & Service discovery

기존 공유망의 MagicDNS 이름, 워크로드의 cluster-local Service, 원본 인증서의 server name을 구분해야 합니다. Service 이름을 바꾸는 것만으로 인증서 신원이나 RBAC가 바뀌지 않습니다.
