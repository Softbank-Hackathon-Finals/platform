# T21 워크로드 대응 지도: 구현과 검증 기록

날짜: 2026-11-07 KST. 상태: 로컬 구현·검증, 팀 플랫폼 배포·운영 인수 미완료.

## 변경과 이유

기존 Sova 워크스페이스의 UI를 유지하면서 자원별 관계, 부분 격리, 대체·검증·경로 전환을
표시한다. 기존 세 자원 경로는 접을 수 있는 등록 정보로 보존했다. 표시 데이터가 실제
승인·격리 권한으로 사용되지 않도록 읽기 전용 경계와 명시적인 합성 시나리오를 분리했다.

## 표시 안전 조건

- 요청 기록은 실제 격리·전환 완료가 아니다.
- 근거가 없는 상태, 연결 실패, 유효기간 만료는 현재 성공으로 표시하지 않는다.
- 하나의 자원 근거로 여러 자원의 격리를 완료 처리하지 않는다.
- 계획 변경·권한 철회 뒤 도착한 응답으로 이전 자원을 복원하지 않는다.
- 충돌한 stream/revision 또는 역행한 관측 시각은 이후 정상 응답만으로 해소하지 않는다.
  사용자가 다시 연결하거나 계획이 바뀌어야 읽기 상태를 초기화한다.
- 구성 위반·T10 보류·T19 PASS·실제 격리 검증을 별개로 표시한다.
- 파란 선의 움직임은 관측 상태의 시각화이며 패킷·대역폭 실측이 아니다.
- 로컬 시나리오는 메모리에서 재생하며 운영 변경 요청을 보내지 않는다.

중단했고 `STOPPED_FOR_CODE_CHANGE`로 보존했다. 중단 실행을 60분 PASS에 합산하지 않았다.

두 저장소의 교차 시험은 미인증·다른 테넌트·열람 권한 거부 때 생산자를 읽지 않으며,
생산자 철회·본문 해시 변경·다른 환경·읽는 도중 계획/생산자 권한 변경을 거부했다.
만료 문서는 과거 기록으로 수용하되 현재 상태 주장은 제거했다. 두 환경의 자원 20개,
관계 18개, 구성 경고 2개를 표시했으며 런타임 성공 주장은 0개였다.
기존 T10이 다른 테넌트 요청에 반환하는 상태는 403이다. 초기 개인 시험의 404 기대를

48개 선택에 걸린 로컬 시간은 Chromium 810ms, WebKit 1,881ms였다. 이 값은 한 Mac의
합성 화면 시험이며 운영 응답시간 목표나 클러스터 부하 측정이 아니다.

로컬 기본 Gitleaks 8.30.1은 기존 설정의 구버전 allowlist 형식을 수용하지 않았다.
공식 배포 체크섬을 확인한 CI 고정 8.24.3으로 실행했다. 검사 설정·예외·범위를 완화하지 않았다.

초기 전체 브라우저 시험에서 두 엔진이 하나의 변경 가능한 fixture DB를 동시에 사용해
일부 실패했다. 각 엔진의 서버를 초기화해 독립 실행한 최종 결과가 위 표다. 기존 지도
시험은 보존된 접이식 영역을 여는 동작만 반영했고, 권한·판정 조건을 약화하지 않았다.

## 로컬 미리보기와 운영의 차이

미리보기는 loopback에만 바인딩하고 일회용 접속 주소로 개인 쿠키를 발급한다.
인증 없는 접근은 403, 재사용한 시작 주소는 404다. 시험용 세션을 공개 주소에 노출하지 않는다.
모든 자원·계획·효과가 합성이라는 안내를 화면 위에 유지한다.

[5분 확인 순서](workload-response-demo.md)로 정상·부분 격리·대체 실패·만료를 확인할 수 있다.
이 결과는 실제 플랫폼의 공격 대응이나 무중단 이전 완료를 뜻하지 않는다.

## 실제 플랫폼에서 확인한 병목

워크플로 호스트는 0/1 및 CrashLoopBackOff였다. 실제 이미지와 세 설정 객체는 앞선
05:25 관측과 같았다. 이미지 원본은 `445848d`이며 새 보안 서비스 생산자 `546f6e0`과
별개다. 호스트 수정 PR의 병합을 실제 배포 완료로 해석하지 않는다. 조회가 끝난 뒤 이번
SSM 세션만 종료했고, AWS Active 없음·History Terminated까지 확인했다.

후속 06:37~06:39 KST 조회에서는 Reader·등록 API·관측 수신기·호스트 모두 1/1 Ready였다.
Reader·등록 API·호스트의 실제 imageID와 source 주석은 새 GitOps 원본 `87ec6147`에 일치했다.
Reader 설정 v2의 정규 내용 해시는 Deployment·Pod 주석에 같았고 공개 JWKS 형식을 확인했다.
설정 이름은 이전 직렬화 방식의 해시이므로 이름 차이만으로 변조로 판정하지 않았다.
인증 요청과 실제 효과 시험은 수행하지 않았다. 이번 조회의 SSM 세션 종료도 확인했다.

새 배포 원본 `87ec6147`의 T10 소스를 사용한 별도 로컬 HTTP 소비 10개가 통과했다.
security의 사전 계약 진단 34개도 통과했으나 제품 허용 SHA나 CI 자격을 확장하지 않았다.

따라서 현재 화면을 실제 대응 결과로 채우려면 다음 인수가 필요하다.

1. 위 Ready 관측을 바탕으로 실제 시험 창의 이미지·설정·자격 기준을 고정하고 재확인.
2. 현재 계획·사용자 권한에 결속된 보안 생산자의 읽기 경로 등록.
3. 실제 양쪽 환경의 자원 UID와 탐지·격리·대체·전환 영수증 연결.
4. 실제 권한 거부·철회·감사·복구 결과의 별도 인수.

구체적인 호스트 계약과 시험은 [표시 계약 문서](workload-response-view.md)에 있다.
T21 완료 체크나 운영 PASS, 실제 격리·복구 상태는 이번 로컬 작업으로 변경하지 않았다.
