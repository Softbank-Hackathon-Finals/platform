# T21 실제 관측 → 워크로드 지도 개발·인수 기록

작업 기간: 2026-11-07~08 KST. T21 자체 코드 범위이며 운영 배포 완료 보고가 아니다.

## 변경 이유와 기준

기존 Sova 화면의 고정 그래프를 실제 등록 대상의 GET 결과로 채운다. 기존 T10 계획·권한·실행 코드는 재사용하고,
관측만 가능한 상황을 표현하기 위해 승인이나 계획을 가짜로 만들지 않는다.

- 코드 생산자: `b3e43b3e764ce1ec1e733ee83064d505a2087606`.
- 이 생산자는 `develop`의 `9d9e4508`을 통합했다. 이 문서의 커밋은 별도 문서 커밋이다.
- 실제 브라우저 인수도 위 생산자의 추적 소스 70개 바이트를 대조한 프로세스에서 수행했다.
- 기존 배포 연결 PR [#727](https://github.com/Softbank-Hackathon-Finals/platform/pull/727)의 T43 변경은 이 작업에 포함하지 않았다.

## 구현

1. 고정된 클러스터 UID·namespace·Service 등록에 한정해 Service·Pod·컨테이너·일부 설정 관계를 읽는다.
2. Pod Ready 조건, 컨테이너 준비 상태, 관리 HTTP `/healthz`를 서로 구분한다.
3. 클러스터 UID와 Service UID·설정을 수집 전후로 확인한다. 등록 digest·코드 출처가 다르면 수용하지 않는다.
4. 90초가 지난 자료나 수집 실패의 현재 준비·HTTP 근거를 철회한다. 브라우저 조회가 수집 시각을 갱신하지 않는다.
5. 기존 Sova UI와 공통 그래프 검증·렌더러를 재사용한다. 독립 모드는 계획·승인·격리·컷오버 API를 제공하지 않는다.
6. native T10에 붙일 때는 실제 계획의 앱·환경 방향과 현재 읽기 권한을 검증한다. 별도 판정·권한 발급기를 만들지 않는다.

최신 develop 통합 직후 한 번은 설치된 `bravo-iac`가 이전 소스로 남아 native 연동 시험 1개가 실패했다.
판정·시험 기대값을 바꾸지 않고 같은 locked 의존성을 캐시 없이 재설치한 뒤 전체 467개가 통과했다.
앞선 실패와 수정 후 결과는 비공개 원본에 별도로 보존했다.

자원 수와 관계 수는 이 관측 회차의 값이다. 다른 세션의 실제 롤아웃에 따라 다음 회차에서 달라질 수 있으며,
Pod UID·컨테이너 실행 식별자가 바뀌면 새 자원으로 취급한다. 단순 개수 일치만을 인수 근거로 삼지 않는다.

## 미검증·다음 인계

1. **AWS 출발지 조회:** 기존 승인 접속 설정의 loopback 연결은 거부됐고 현재 tailnet에서 출발지 API가 보이지 않았다.
   이는 클러스터 장애 판정이 아니다. 출발지 담당에게 현재 승인된 읽기 도구/설정 참조를 받아 등록 UID를 대조해야 한다.
2. **운영 T10 합성:** [T43 범위 합의](https://github.com/Softbank-Hackathon-Finals/platform/issues/355#issuecomment-6707434943) 후
   공식 이미지·보호된 등록·전용 읽기 자격·현재 SSO grant·네트워크를 연결하고 실제 호스트에서 다시 인수한다.
3. **공격 대응:** 실제 탐지 공급자, 승인된 대응 실행과 격리 후 독립 검증을 원래 경로로 인수해야 한다.
   Pod Ready나 NetworkPolicy 설정 개수를 공격 차단·격리·보안 PASS로 바꾸지 않는다.
4. **전체 이전:** 실제 계획의 양쪽 T14·T19·T28 연결, DB·세션·컷오버·복구는 별도다. 이 작업으로 T21 Done을 체크하지 않는다.

개발용 독립 호스트는 기존 Sova-test 개인 운영자 인증을 재사용하며 loopback만 연다.
기업 SSO/호스팅 인증이 아니다. 기본 콘솔과 공용 워크로드·RBAC·네트워크·데이터는 변경하지 않았다.
