# Sova UI 통합과 실제 관측 연결 준비

2026-11-07. 기존 Sova UI를 유지하며 최신 팀 코드와 합친 로컬 통합 기록이다.
공용 플랫폼에 배포하거나 실제 격리·복구를 실행한 기록이 아니다.

사이드바·워크스페이스·색상·Sova 브랜딩을 유지한다. 네트워크 지도와 워크로드 대응 지도를
같은 화면에 배치하며 기존 T10 승인·복귀, T19 보고서, T33 탐지, T37 관측 소비 경로를 보존한다.
콘솔의 고정 lockfile은 수정 없이 설치됐다.

검증: Python 350개, JavaScript 245개, Chromium 49개, WebKit 49개 통과.
Python 시험은 별도의 로컬 PostgreSQL을 포함한다. 브라우저별 서버를 새로 시작해
시험용 승인 기록을 공유하지 않았다. 최초 합동 실행에서는 공유 fixture 간섭과
시험 포트의 하드코딩 때문에 실패했으며 해당 실행을 통과로 집계하지 않았다.
Ruff, JS 문법·자산 검사, 공개 문서 개인정보 검사도 통과했다.

## 실제 플랫폼 재조회

10:24 KST에 기존 개인 SSO·플랫폼 SSM 경로로 계정·클러스터 신원을 대조한 뒤 조회했다.

- T10 Reader·등록 API·워크플로 호스트·창 수신기는 각 1/1 Ready였다.
- T15 리허설 호스트는 0/1, `CrashLoopBackOff`, 마지막 종료 코드 1이었다.
  원인 진단·재시작·수정은 수행하지 않았다. 이는 조회 시점의 관측이다.
- Reader·등록 API·리허설 호스트의 imageID가 고정 GitOps 선언과 일치했다.
- Reader 설정 v2의 정규 내용 해시가 Deployment·Pod 주석과 일치했다.
  설정 이름은 예전 공백 포함 JSON 해시 방식이므로 현재 내용 해시와 별도로 대조했다.
- SA UID·RBAC·NetworkPolicy·EndpointSlice를 읽었다. 설정 존재를 실제 거부 시험으로
  판정하지 않았다. 읽기 점검용 SSM 세션은 AWS에서 종료 상태까지 확인했다.

## UI에 연결할 원본과 남은 접점

| 화면 / 기존 구현 | 연결할 원본 | 현재 확인과 남은 일 |
|---|---|---|
| 계획·승인·이력 / 기존 T10 API·SSE | 실제 계획 ID/digest/version, 운영자 신원·열람 권한 | 클러스터 조회 권한은 앱 조회 권한을 대신하지 않음. 운영자 세션과 실제 계획을 기존 T10 경로로 연결해야 함 |
| 통제 비교 / `T10ControlReports` | 동일 계획에 저장된 양쪽 T14 원문, T19 현재 발급자·서명 | 실제 full 프로필 원문과 현재 권한을 인수해야 함. 과거 일부 PASS를 합치지 않음 |
| 워크로드 / `PlanWorkload` | 등록된 보안 생산자의 SHA·신원·원문 hash·자원 UID/revision | 로컬 계약 연결 완료. 운영 생산자 등록·읽기 저장소·현재 권한 callback 미연결 |
| 탐지 / `PlanSecurity` | 기존 T33 인증된 환경별 조회 | 수집 정상과 공격 부재를 구분. 실제 endpoint·읽기 권한 인수 필요 |
| 관측 / `PlanObservations`, `T37Details` | 기존 T37의 고정 TLS 주소·환경 매핑·읽기 자격 | 누락·수집 단절은 미확인. 실제 양쪽 수집 경로 연결 필요 |
| 감사 / 기존 T24 reader | 같은 실행의 검증된 체인·보존 영수증 | 실제 영속 원본과 조회 권한 인수 필요 |

현재 조회한 `platform-state`의 Deployment와 고정 호스트 코드에서는 이 콘솔의
`compose_console`·`PlanWorkload` 운영 등록을 확인하지 못했다. 따라서 화면의 합성 계획에
운영 Pod UID를 붙여 실제 앱 계획처럼 보이게 하지 않는다. 등록된 출발/목적지·앱이 없으면
연결을 보류하며, 데이터가 없다는 이유로 정상·격리 완료를 생성하지 않는다.

## 적용 전 필요한 변경

1. 기존 T7/T9 신원·비밀 관리로 읽기 전용 생산자와 TLS 신뢰 참조를 준비한다.
2. 기존 T10 호스트의 현재 신원·계획 열람 권한에 `compose_console`을 조립한다.
   브라우저가 producer URL·토큰·환경 매핑을 등록하게 하지 않는다.
3. 보안 저장소의 `project_security_snapshots` 결과를 기존 `RegisteredWorkload`로
   전달하고 원문 인증·철회·SHA·hash·계획·자원 범위를 읽기 전후 확인한다.
4. 실제 격리·대체·복구 표시는 T10 승인/잠금·T31/T12 효과·독립 확인 영수증을 연결한 후
   별도 변경 시험 창에서 인수한다. 요청·정책 선언만으로 완료 표시를 만들지 않는다.

이번 변경 범위는 로컬 통합·읽기 전용 관측·인수 준비다. 배포, exec, 토큰 발급,
권한 변경, 격리·전환·복구는 보류했다. 팀 콘솔 브랜치는 로컬에서 검토 가능하게 보존한다.
