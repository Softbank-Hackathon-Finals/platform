- 플랫폼은 개인 SSO 및 기존 SSM API 경로에서 등록 신원을 확인한 뒤 조회했다. 해당 시점의 Reader·등록 API·호스트는 Ready, Argo는 Synced/Healthy였다. 자신의 SSM 세션은 종료했다.
- 플랫폼 Tailscale 직접 경로는 EOF였으므로 성공으로 바꾸거나 기존 SSM 경로를 제거하지 않았다. 온프렘 전용 접속 도구를 플랫폼에 사용하지 않았다.
- 목적지는 기존 개인 직접 API 도구의 등록 UID와 native `customer_status.py`로 GET 수집했다. 실제 결과는 **NOT_INSTALLED / APPLICATION_CRD_MISSING**다. 비교 SHA는 후보이며 고객 적용 승인으로 간주하지 않는다.
- 실제 고객 Argo 설치·Application 소유권 인수·활성화는 수행하지 않았다. 기존 자원을 자동 인수하지 않는다.

- 호스트의 실제 개인 SSO 등록·계획별 최소 grant, 전용 읽기 수집 SA/단기 자격과 네트워크, 공식 이미지 발행·출처 검증·배포 시점 확인이 필요하다.

## 실제 로컬 TLS 보강

`test_operator_bridge_tls.py`에서 실제 loopback HTTPS 서버와 생성한 시험 인증서로 세 경우를 확인했다.
정상 CA·등록 서버 이름은 성공했고, 미신뢰 CA와 다른 서버 이름은 TLS 단계에서 거부됐다.
거부된 두 경우 upstream이 받은 HTTP 요청·Authorization은 0개다. 중계 주소가 loopback이어도
등록된 서버 이름(SNI)을 검사하며, `verify=False`나 HTTP 대체 경로를 사용하지 않는다.
시험 키는 fixture의 비공개 임시 파일만 사용하고 종료 시 제거했다. 실제 AWS proof는 사용하지 않았다.

기존 전체 446개 통과에 더해 이 TLS 시험 3개를 별도로 통과했다. 운영 호스트 TLS나 실제 SSO 등록을
인수한 것으로 확대하지 않는다. #727 원래 head의 Node/Python 콘솔 CI도 통과했으며, infra와 다른
필수 묶음은 확인 당시 아직 진행 중이었다. 추가 커밋의 CI 결과는 별도로 확인한다.
