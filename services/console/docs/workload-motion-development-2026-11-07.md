## 기준과 범위

사용자 요청은 기존 Sova UI의 워크로드 대응·격리·대체·연결 전환을 눈에 보이게 만드는 것이다.
앞서 만든 데모 전용 워크플로우의 조작 패널과 별개로 진행했다.

- UI 인계 기준: `1489a52ef1e4a6e9530a64fee0bcde824e1b6d61`.
- 작업 브랜치: `feature/T21-workload-response-motion`.
- 표시 배치·SVG 보간: `0554bd47`.
- 부분 대응 시나리오·화면 연결·브라우저 회귀: `f0c3734d5f3d030350b2ac57d405e05a6b36575a`.
- 추적 작업: [T21 #27](https://github.com/Softbank-Hackathon-Finals/platform/issues/27).

기존 UI 인계 브랜치와 워크플로우 데모 브랜치는 변경하지 않았다. T10/T19 판정,
권한·승인·실행 API·생산자 형식은 유지했다. 공용 AWS·온프렘 자원 변경은 수행하지 않았다.

## 달라진 표시

| 장면 | 표시 |
|---|---|
| 정상 | 13개 합성 자원과 등록 관계. 유효한 연결 관측에만 흐름 점 표시 |
| 보안 이상 | 대상 노드 강조와 바로 다음 의존 자원의 옅은 영향 가능성 표시 |
| 격리 요청 | 원래 위치 유지. 요청된 연결과 확인된 차단을 구분 |
| 격리 확인 | 해당 노드가 별도 격리 영역으로 이동. 기존 위치 윤곽과 끊어진 연결 표시 |
| 대체 준비·검증 | 별도 환경의 대체 앱·작업자 등장. 검증 실패는 경로 활성화로 이어지지 않음 |
| 경로 전환·복구 | 대체 경로에만 흐름 표시. 원본 격리·사고 보류 유지 |
| 근거 만료 | 현재 성공·격리 수 철회. 과거 배치를 회색으로 유지하고 원본 재개를 추정하지 않음 |

API·작업자 전체, API만, 작업자만의 세 범위를 제공한다. API만 격리하면 기존 작업자의 DB
경로가 남고, 작업자만 격리하면 진입점→API 경로가 남는다. DB·저장소가 의존 자원이라는
이유만으로 격리됐다고 표시하지 않는다. 제어 관계도 업무 통신 차단과 별도로 표시한다.

SVG는 ID·자원 UID로 노드 요소를 유지한다. 좌표와 연결 곡선을 함께 보간하고, 확인된
차단은 중간 간격을 둔 두 곡선으로 표현한다. UID 교체 시 이전 노드·과거 격리 위치를
재사용하지 않는다. 노드 이동은 논리적 표시이며 물리적 호스트 이동의 증거가 아니다.

`지도 확대`·Escape와 동작 줄이기 설정을 지원한다. 키보드 선택·권한 회수 시 식별자 삭제,
같은 revision 충돌 시 미확인 처리 등 기존 조회 경계를 유지했다.

## 검증

- JavaScript 전체 253개 통과. 부분 범위·각 단계의 동일 계약, 격리 요청과 확인,
  연결 간격·보간 좌표, 실패 시 전환 금지, 과거 배치와 현재 주장 분리를 확인했다.
- Python 59개 통과. 콘솔 자산·워크로드 조회·호스트 조립의 관련 회귀 범위다.
- Chromium·WebKit 각각 전체 52개 시험을 실행했다. 그 후 직접 화면 캡처에서 상세 패널의
  연결 상태 이름 참조 누락을 발견해 수정했다. 페이지 오류 감지를 추가하고 **최종 코드의
  워크로드 시험 12개씩 재실행해 모두 통과**했다. 최초 전체 통과를 오류 부재의 근거로 삼지 않는다.
- 최종 미리보기 직접 확인: 노드 13개, 격리 표시 2개, 대체 경로 관측 표시, 기존 사이드바 1개,
  페이지 오류 0건, GET 이외 요청 0건.
- JS 문법·로컬 자산 검사와 공개 텍스트 개인정보 패턴 검사 통과. 자격 비노출 검사는 별도 수행한다.

화면 캡처와 검증 요약은 로컬 비공개 증빙 폴더에 보존한다. 개인 접속 URL·쿠키는 게시하지 않는다.

## 적용 범위와 남은 연결

새 렌더러는 기존 `PlanWorkload`의 검증된 표시 자료를 받는다. 서버 생산자 연결과 실제
격리·대체·경로 전환의 독립 확인 영수증이 준비되면 같은 표시 경로를 사용할 수 있다.
기본 플랫폼 모드는 자료가 없으면 미연결이며, 합성 성공으로 대체하지 않는다.

이번에 조작해 확인한 것은 **브라우저 로컬 합성 시나리오**다. 실제 공격 탐지, AWS/온프렘
격리 실행, DB 이전·무중단·운영 복구를 완료한 기록이 아니다. 보안 규칙을 우회하거나
실제 T10 계획의 상태를 이 시나리오로 변경하지 않는다. T21/T28 운영 완료 체크도 변경하지 않는다.

[시연 순서](workload-response-demo.md)와 [표시·생산자 경계](workload-response-view.md)를 함께 인계한다.
