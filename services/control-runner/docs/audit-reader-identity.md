# T14 CloudWatch 감사 조회 신원 결속

`QualifiedCloudWatchAuditProbe`는 기존 `AuditSearchProbe` 판정 앞에 AWS 임시 조회 신원
확인을 연결한다. 기존 테스트 ID·기대값·관찰 규칙은 바꾸지 않는다. 역할 생성이나
감사 이벤트 발생, 운영 자격 발급은 수행하지 않는다.

## 호스트 계약

호스트는 인증된 등록에서 앱·환경, 조회 역할 ARN과 불변 RoleId, 같은 계정·partition의
정확한 log group ARN·전체 stream 집합을 제공한다. 출발지나 목적지의 원천을 업로드 JSON이
선택하지 못하게 한다. 실제 완료된 효과에 대한 `CanaryReceipt`와 임시 자격 공급자,
영속 evidence sink도 신뢰된 내부 함수여야 한다. 다른 계획/앱의 영수증이나 fixture를
실제 환경 영수증으로 등록하지 않는다.

1. 요청 앱·환경·시험과 실제 카나리 영수증을 확인한 후 자격을 받는다.
2. 동일한 임시 자격 snapshot으로 STS `GetCallerIdentity`를 호출한다.
3. ARN·계정·RoleId·세션 이름을 확인하고 동일 snapshot으로 CloudWatch를 조회한다.
4. 기존 검색기가 실제 행의 시각·주체·행동·원천·완전한 페이지를 검사한다.
5. 조회 신원 지문·자격 만료·원문 관찰 지문을 하나의 증거로 저장한 뒤 Observation을 반환한다.

환경변수의 임의 endpoint·프록시·CA 설정을 사용하지 않는다. TLS 검증과 고정 SDK endpoint,
연결/읽기 timeout·재시도 상한을 유지한다. 자격 원문과 원본 감사 메시지는 증거에 넣지 않는다.
AWS wire debug가 켜져 있으면 자격을 사용하는 요청을 시작하지 않는다.

전체 호출은 전후 단조 시계로 60초 예산을 검사한다. 호스트는 credential/receipt/sink와
네트워크 호출을 포함한 worker의 강제 종료 한도를 별도로 설정한다. Python 콜백이 멈춘
상태를 이 함수가 강제로 끊지는 못한다.

## 실패와 책임

- 다른 역할·재생성된 역할·만료된 임시 자격·시계 역행·예산 초과는 통과하지 않는다.
- 빈 검색은 기존 NOT_RUN/absent 규칙을 따른다. 권한 거부는 정상 거부 대조군이나 PASS가 아니다.
- 검색 증거가 없거나 hash가 다르면 거부한다. 영속 저장 실패도 PASS로 반환하지 않는다.
- STS 신원 확인은 최소 권한이나 취소 불가능성을 증명하지 않는다. 실제 조회 API의 허용과
  별도 거부 주체 시험이 필요하다. 자격은 호출 중에도 회수될 수 있다.
- 효과를 만든 주체와 감사 로그를 읽는 주체는 다를 수 있다. 각각 영수증과 조회 증거에 결속한다.
- 조회자의 identity hash는 인증 증빙의 일부이며 서명·계획 권한을 대신하지 않는다.
  T10/T19의 실제 계획·프로필·원문 저장·인가 연결은 호스트의 별도 책임이다.

[실제 출발지 시험](../../../docs/evidence/t14-audit-reader-identity-2026-11-06/README.md)은
본인 SSO 임시 세션으로 수행했다. 별도 시험 namespace의 AUD-01.3 부분 검증이며,
앱 namespace·최소권한 전용 조회 역할·목적지 전체 인수로 사용하지 않는다.
