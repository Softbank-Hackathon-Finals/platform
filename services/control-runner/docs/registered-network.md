# 실제 listener 등록을 사용하는 네트워크 시험 후보(v2)

실제 출발지 PgBouncer의 Service·EndpointSlice·listener가 5432여서 기존 v1의
고정 6432 정상 대조가 실패했다. `RegisteredNetworkAccessProbe`는 DB와 풀러를
포트 번호 대신 **서로 다른 등록 서비스 역할**로 선택한다. 두 역할 모두 필수다.
같은 포트 번호를 쓰더라도 하나의 서비스만 두 번 검사할 수 없다.

## 기존 계약과의 관계

- 기존 `NetworkAccessProbe`, T5 기본 카탈로그, T19 패키지 계약은 그대로다.
- 새 관찰의 `method_version`은 `2`다. v1 관찰의 시각·방법을 바꾸어 재사용하지 않는다.
- [후보 프로필](candidates/network-method-2-profile.json)은 `full:2`의 20개 시험을
  유지하며 NET-01.2/NET-01.3만 방법 2로 정의한다. 기본 경로나 자동 선택에 연결하지 않는다.
- **T19 운영 게이트에서 사용할 수 있는 상태가 아니다.** v2의 두 역할 증거를 실제
  등록·계획에 결속하는 검증기, 고정 카탈로그 및 T10 새 계획 등록을 함께 인수해야 한다.
  기존 v1 카탈로그/계획은 full:2를 받아들이지 않는다. 직접 `PASS` JSON을 보내지 않는다.

## 호스트가 등록·검증해야 할 것

| 항목 | 필수 조건 |
|---|---|
| 두 역할 | `database`, `pooler` 각각 정확히 1개 |
| 서비스 | 서로 다른 UID와 서로 다른 IP·포트 쌍. 같은 포트는 허용 |
| 실행 범위 | 같은 앱·환경·허용/거부 주체·건강 확인 endpoint·DNS 기준 |
| 자원 신원 | 인증된 API에서 Service UID·port/targetPort, EndpointSlice UID·Ready backend, Pod UID·실행 이미지·컨테이너·소유 관계 확인 |
| 등록 근거 | 등록된 두 경로의 설정·소유 신원 해시를 각 `RegisteredListener.registration_sha256`에 고정 |
| 새로 읽기 | 시험 전·첫 역할 후·두 번째 역할 후 실제 등록을 읽고 `ListenerSnapshot`을 반환 |
| 정책 | 각 역할의 시험 전후 SG·NetworkPolicy/필요한 설정 원문 해시 대조 |

호스트는 사용자가 보낸 주소나 JSON을 그대로 등록하지 않는다. digest는 서명이 아니고,
문자열 agent 이름은 인증이 아니다. 네트워크 권한과 접속 설정은 환경 담당이 제공한
등록 경로를 사용하며, 수집기는 이를 바꾸지 않는다. DNS 이름을 바꿔 같은 대상이라고
추정하거나 사라진 Service UID를 새 자원으로 자동 교체하지 않는다.

## 시험과 실패 처리

각 역할에서 허용 주체의 정상 연결, 거부 주체의 건강 확인, NET-01.3의 DNS 확인을
먼저 수행한다. 실제 부정 연결 후 같은 대조를 다시 수행한다. TCP timeout 3초,
콜백 응답 5초, 두 역할과 등록 조회를 합친 전체 창 60초를 유지한다. 두 번째 역할에
새 60초 예산을 주지 않는다. 원격 호스트가 콜백의 프로세스 수명도 제한해야 한다.

v2의 증거 시각은 수집기의 실제 요청·응답 구간을 기준으로 한다. 인증된 채널에서
이번 nonce·agent·endpoint가 일치하고 5초 안에 돌아온 응답만 수용한다.
`observed_at`은 수집기 수신 시각, `coordinator_started_at`은 요청 시각이고,
원격 원문 시각은 `agent_observed_at`에 그대로 보존한다. 에이전트 시각은 이 구간에서
최대 1초만 벗어날 수 있다. 이 후보 한도는 실제 약 0.4초의 시계 차이를 계측한 뒤
정했으며, 재전송 허용 기한이나 증거 TTL 연장이 아니다. 초과 차이·잘못된 nonce·다른
주체·수집기 시계 역행은 거부한다. 운영 자격에는 시간 동기화 및 이 방법의 명시적
인수가 필요하다. v1의 원격 시각 조건과 기존 증거는 바꾸지 않는다.

- 대조군 성공 후 어느 역할이든 연결되면 `allow`다.
- 양쪽 대조군이 성공하고 두 역할 모두 거부돼야 `deny`다.
- 정상 대조가 하나라도 실패하면 `UNKNOWN/POSITIVE_CONTROL_FAILED`다.
- 등록·환경·방법·정책 불일치, 시각 변경, 저장 실패 시 완료 관찰을 반환하지 않는다.
- 부분 증거는 원인 분석용이다. 최종 증거와 `ControlRun`이 없으면 전체 통과로 쓰지 않는다.

각 역할과 합산 증거에 방법 버전·등록 해시·포트·개별 결과·정책 및 출력 해시를 남긴다.
증거 공개본에는 IP·자격증명·DB payload가 없다. TCP 성공은 SQL 로그인, 데이터 접근,
TLS 성공을 뜻하지 않는다. 목적지의 접근 차단 결과와 운영 계획 인수는 별도다.

## 검증

`tests/test_registered_network.py`는 같은 포트의 서로 다른 서비스, 역할 누락·중복,
같은 UID/endpoint 재사용, 경로 혼합, stale/다른 context/다른 등록, 대조군 실패,
공통 예산 초과, 저장 실패, 기본 카탈로그와 후보 카탈로그 분리를 검사한다.
기존 v1 네트워크 회귀도 함께 실행한다. 모의 거부 결과를 실제 정책 PASS로 사용하지 않는다.
